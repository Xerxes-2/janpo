## 0. 结论摘要

| # | 改动 | 结论 | 一句话 |
|---|---|---|---|
| 1 | 面子也受「4 组」上限约束 | **正确** | 纯形态问题，与规则集无关；它修的是引擎自己的 DFS bug（会把「4 面子 + 1 搭子」判成和了），任何实现都必须这么做。 |
| 2 | 孤张全是「四张全在手里」的牌种、且无雀头时 +1 | **正确，且天凤取的正是这一边** | 天凤官方手册**明文**写「純手牌で４枚使用していなければ成立」——即暗牌握满四张时不成立；129 179 局真实牌谱里 2 例直接印证（天凤按不听收罚符）。但它同时把一条**因规则集而异**的判据焊死在了天凤这一侧（EMA 竞技规则判不听）。 |
| 3 | 字牌死张是向听下界 | **正确，但它根本不碰听牌边界** | 40 万手对照实验中它**一次**都没有翻转过听牌/和了判定（只改 ≥1 向听的数值）；有结构性论证支持。所以它不需要「人确认」，它影响的只有 Ukeire / Assisted 档的建议质量。 |

**核心问题的答案：**

> **天凤规则下，待ち牌が 0 枚（纯空听 / 純カラ）的形式听牌，荒牌流局时算听牌、收听牌料，也能立直。**

出处：天凤官方手册 `tenhou.net/man/`「形式聴牌あり」，且除「純手牌で４枚使用」外没有任何其他排除项。
实测：12 188 局天凤鳳凰卓牌谱、129 179 个 kyoku 里，**342 个纯空听座位**在荒牌流局时被判听牌，
其中 307 个收到正的听牌料、35 个在全员听牌局（0 授受），**0 个被判不听**；
93 838 次立直宣言里有 **13 次**在宣言当下待牌已经 0 枚，天凤照样受理。

**因此 04 票的听牌料与 12 票的流局判定都不是错的**，引擎与天凤一致——因为
`Shanten.calculate : TileKindSet -> HandShape -> Shanten` 的签名里压根没有「牌河 / 副露 / 宝牌指示牌」，
它看不见场上的可见枚数，天凤也不看。

**唯一真正的「剩余枚数」味道来自哪里**：改动 2 与 3 读的是 `HandShape.counts`，
也就是**这家自己的暗牌张数**。暗牌张数是手牌形态的一部分，不是可见性。它们编码的是另一件事：
**目标集合（和了型）里每种牌最多 4 张**，所以「等第 5 张」的形不是听牌。见 §2。

## 1. 三条改动的精确判据

先把术语对齐。`searchStandard` 的状态是
`(index, melds, partials, hasHead, anyFloater, allFloatersAreQuads)`，
`melds` 从 `nakiCount` 起算（副露与杠各算一个已成面子），叶节点的候选值是

```
8 - 2*melds - partials - (hasHead ? 1 : 0) + (unpairable ? 1 : 0)
```

`original` 是 `HandShape.counts hand`，即**暗牌**的 34 长计数（**不含副露牌面**——`HandShape` 只存 `nakiCount`）。

### 1.1 改动 1：面子也受「4 组」上限约束

**判据**：刻子分支与顺子分支都加了守卫 `blocks < 4`，其中 `blocks = melds + partials`。
雀头不占这 4 组（`hasHead` 另算）。原来只有搭子分支有这个守卫。

```fsharp
let blocks = melds + partials
if count >= 3 && blocks < 4 then   // 刻子
if ... && blocks < 4 && ... then    // 顺子
```

**它在什么输入下改变结果**：任何能凑出「4 面子 + 至少 1 搭子」的分解。
没有上限时 `8 - 2*4 - 1 = -1`，被当成和了型。

**例（全部不含四张同种，排除改动 2/3 的干扰；均经 oracle 与 `xiangting` 复核）**

| 手牌 | 副露 | 正确 | 撤掉上限 |
|---|---|---|---|
| `2m2m2m 7m8m9m 4p 6p 1s1s1s 6s6s6s` | 0 | **0** | −1（假和了：4 面子 + `4p6p` 嵌张，无雀头） |
| `6m7m8m 1p2p3p 5p6p6p7p8p 1s2s3s` | 0 | **0** | −1 |
| `3m4m5m 3p4p 7s8s9s 1z1z1z` | 1 | **0** | −1 |
| `3m4m 4s6s7s8s9s 7z` | 2 | **1** | 0（假听牌） |
| `1p1p1p1p 2p2p2p2p 7s8s9s` | 1 | **0** | −1 |

**性质**：这是**唯一**能翻转「和了型」判定的一条（40 万手实验里另两条各 0 次和了翻转）。
它同时能翻转听牌判定。它与规则集无关，纯粹是「一手牌是 4 面子 1 雀头」这个定义。

### 1.2 改动 2：孤张全是「四张全在手里」的牌种、且无雀头 → +1

**判据**（两处，同一族，报告里只把第二处写在括号里）：

```fsharp
// (a) 叶节点
let unpairable = not hasHead && anyFloater && allFloatersAreQuads
// allFloatersAreQuads 沿着「孤张」分支累乘 isQuad original index，即 original.[index] = 4

// (b) 对子搭子分支
if count >= 2 && blocks < 4 && not (isQuad original index) then
```

用话说：

- **(a)** 某个分解里没有雀头、且剩下的每一张孤张都是「暗牌里已经握满 4 张」的牌种时，
  这个分解永远补不成——雀头只能靠孤张凑对，而第 5 张不存在——所以要多一次替换。
- **(b)** 「对子搭子」（双碰的一半）不能从握满 4 张的牌种里拆：拆出 `XX` 之后它要的第 3 张
  你手里还有 2 张，真正想成刻子直接拆刻子就行；把它算成搭子等于假设能摸到第 5 张。

`isQuad` 读的是 `original`，也就是**暗牌**的原始张数。**副露牌面不参与**——`HandShape` 里根本没有。

**它在什么输入下改变结果**：手牌里有牌种握满 4 张，且这 4 张的第 4 张只能当单骑 / 双碰的一半。

| 手牌 | 副露 | 正确 | 撤掉改动 2 |
|---|---|---|---|
| `3m4m5m 6m7m8m 1p2p3p 6s6s6s6s` | 0 | **1** | 0（假听牌：6s 单骑，第 5 张 6s 不存在） |
| `6m6m6m6m 2p2p2p` | 2 | **1** | 0 |
| `2p3p4p 3s3s3s3s 5s6s7s` | 1 | **1** | 0 |
| `4m5m6m 1p1p1p1p 6p7p8p` | 1 | **1** | 0 |
| `4p5p6p 3s3s3s3s` | 2 | **1** | 0 |

**反过来，它不该开火的三类地方**（引擎也确实不开火，天凤同样判听牌）：

| 手牌 | 副露 | 结论 |
|---|---|---|
| `4m5m6m 8p`（另有 888p 的碰） | 3 | **听牌**（8p 单骑）。暗牌里只有 1 张 8p，天凤的「純手牌で４枚使用していない」成立 |
| `7m9m 6z6z`（另有 8888m 的杠） | 3 | **听牌**（8m 嵌张）。杠出去的牌不算暗牌 |
| `1m2m3m 4m4m4m4m 6m7m8m 6s7s8s` | 0 | **听牌**。存在另一种分解 `234m + 444m + 678m + 678s` 使孤张变成 `1m`（非四张牌种），判据要求**每一张**孤张都是四张牌种才 +1 |

前两行是**真实牌谱里的局面**，天凤都付了听牌料（见 §4.4 / §4.6）；
第三行也是真实牌谱（`2026010323gm…b19764ce`），它提醒了一件事：
**`allFloatersAreQuads` 是对整个搜索取最小值时的逐分解判据**，
只要存在**一个**孤张不是四张牌种的分解，就还是听牌。

**性质**：改动 2 只翻转听牌判定，**从不翻转和了判定**（40 万手 0 次）。原因显然：
和了型必有雀头，`unpairable` 要求 `not hasHead`。

### 1.3 改动 3：字牌死张是向听下界

**判据**：

```fsharp
let spare = if HandShape.isAwaitingDraw hand then 0 else 1
Shanten(max searched (max 0 (deadQuadKinds legal original - spare)))
// 且 searched <= -1（和了型）时直接短路返回 agari，不套这个下界
```

`deadQuadKinds` = 满足「暗牌握满 4 张」且「在这个规则集下进不了任何合法顺子」（`canJoinRun`）的牌种数。
四麻里就是字牌；三麻里还包括 1m / 9m（缺 2m-8m 就没有含它们的三连号）。
`spare` 是「3n+2 的手牌本来就要打一张，白送一次」。

| 手牌 | 副露 | 正确 | 撤掉改动 3 |
|---|---|---|---|
| `1z1z1z1z 2z2z2z2z 2m3m4m 5s5s` | 0 | **2** | 1 |
| `1s2s3s3s3s 2z2z2z2z 5z5z5z5z` | 0 | **2** | 1 |
| `4p4p 2s3s4s 2z2z2z2z 6z6z6z6z` | 0 | **2** | 1 |

**关键性质：它一次都没有翻转过听牌或和了判定。** 见 §4.1 的 40 万手实验（0 次），
以及下面的结构性论证：

> 13 张手牌要让朴素搜索给出 0，只有两种分解：`4 面子 + 孤张（无雀头）` 或 `3 面子 + 1 搭子 + 雀头`。
> 前者若含一个死张牌种，第 4 张只能当那个孤张，于是改动 2 已经把它顶到 1；
> 要两个死张牌种就得 8 张字牌 + 2 组面子 = 14 张 > 13，凑不出。
> 后者要把 4 张同种全用掉，只能是「雀头 `XX` + 对子搭子 `XX`」，而改动 2(b) 已经禁掉了。
> 所以 `deadQuadKinds - spare ≥ 1` 与「朴素值 = 0」在 13 张上互斥。
> 14 张（3n+2）时 `spare = 1`，下界更松，且 14 张的和了判定走的是 `searched <= -1` 短路，
> 根本不经过这个 `max`。

**结论：改动 3 不属于「听牌边界」问题**，它只影响 ≥1 向听的数值，
也就是 Ukeire 的排序、Assisted 档的「进退向」标注、以及将来 ToolSearch 档的搜索质量。
它**不需要人在规则层面拍板**。

## 2. 为什么这不是「把剩余枚数混进向听判定」

这是本次调研最要紧的一条澄清。

向听数的严谨定义（tomohxx《麻雀アルゴリズム》[Z3]）是：

> ここでは向聴数を「聴牌するために必要な牌の枚数の最小値」と定義する。……
> 「和了するために必要な牌の枚数の最小値」として置換数を導入する。S(h) = T(h) − 1

也就是「手牌 h 到**和了型集合**的最小距离 − 1」。而**和了型集合里的每一手都是合法手牌，每种牌最多 4 张**。
于是「握满 4 张 X 的单骑听 X」这种形，到和了型集合的距离本来就是 2 而不是 1 ——
**这是定义直接推出来的，不是往里塞了可见性**。

EMA 规则书 §3.3.8 把同一件事写成了自然语言 [E1]：

> **A complete hand cannot contain five of the same tile, so a hand containing four copies of
> the same tile cannot wait on the fifth copy, and a hand with no waiting tile is noten.**

对照三个坐标轴：

| 判据读什么 | 改动 2 / 3 | 「纯空听」 |
|---|---|---|
| 自家暗牌的张数 | ✅ 读 | 不读 |
| 牌河 / 他家副露 / 宝牌指示牌 | ❌ 不读 | 要读 |
| 牌山剩余 | ❌ 不读 | 不读（不可见） |

引擎的 `Shanten` 只吃 `TileKindSet * HandShape`，**结构上不可能**读到牌河或宝牌指示牌。
`Ukeire.calculate` 才有 `visible` 参数，而它的产物 `Ukeire.Tiles` 明确保留 0 枚牌种、
另给 `Ukeire.live` 过滤（03 的决策），且引擎里**没有任何地方**拿 `Ukeire.live` 去做听牌判定
（`grep` 过：`Ukeire.*` 在 `src/` 里只被 `Janpo.Cli/Program.fs` 用了 3 次）。

所以：**「纯空听算不算听牌」这个问题在我们的实现里根本无法回答成「不算」**，
它必然算听牌。而这恰好就是天凤的答案。

## 3. 出处与引文

### 3.1 天凤官方（一手，有约束力）

**`https://tenhou.net/man/` · ■ルール / 段位戦4人打ち**（2026-08-16 取）：

> \- 形式聴牌あり。5枚目を待つ聴牌あり(手牌＝純手牌＋副露手牌として純手牌で４枚使用していなければ成立)
> \- リーチ宣言は得点が1000点以上でツモ巡がある場合に可能
> \- 振聴リーチあり
> \- ノーテン親流れ、聴牌連荘
> \- 流し満貫あり。聴牌清算を満貫清算に代替。親の聴牌で連荘。

逐条读：

1. **「形式聴牌あり」** —— 无役的听牌算听牌。规则清单里**没有**任何「待ちが場に全部見えている場合は除く」
   之类的排除项。⇒ **纯空听算听牌。**
2. **「5枚目を待つ聴牌あり(……純手牌で４枚使用していなければ成立)」** —— 要第 5 张的听牌**允许**，
   条件是「純手牌（暗牌）没有用满 4 张」。⇒ 暗牌握满 4 张的单骑**不算听牌**（= 改动 2），
   而「碰了 3 张 + 手里 1 张单骑」**算听牌**（= 我们的 `original` 只数暗牌，正确）。
3. **「リーチ宣言は得点が1000点以上でツモ巡がある場合に可能」** —— 立直的附加条件只有点数与牌山，
   没有「待ちが残っていること」。配合「振聴リーチあり」（连必定和不了的振听立直都允许），
   ⇒ **纯空听可以立直。**
4. **「ノーテン親流れ、聴牌連荘」「親の聴牌で連荘」** —— 12 票的连庄与流し満貫读的是同一个「聴牌」定义。

二手复述（可交叉验证同一句话）：
- `https://riichi.wiki/Tenhou_rules` —— 原样引了同一行。
- `https://riichi.wiki/Tenhou_Meijinsen` —— 名人战版写成「5枚目を待つ聴牌あり（**打牌選択可能な手牌で**4枚使用している牌を除く）」，措辞不同、意思相同（「打牌選択可能な手牌」= 暗牌）。
- `https://wikiwiki.jp/tenhou-chat/…` —— 「形式聴牌あり。5牌目を待つ聴牌あり。」

### 3.4 EMA 竞技规则（一手规则书，**与天凤相反的那一边**）

**EMA Riichi Rules 2025 (EN) §3.3.8 Tenpai and noten**
（`mahjong-europe.org/portal/images/docs/Riichi-rules-2025-EN.pdf`，第 13 页）：

> Tenpai (waiting) means that the hand is almost complete; there exists at least one tile that,
> if added to the hand, would complete it. …… **A complete hand cannot contain five of the same tile,
> so a hand containing four copies of the same tile cannot wait on the fifth copy, and a hand with
> no waiting tile is noten. A player is still considered tenpai if all their waiting tiles are
> visible among the discards and called sets.** During a player's turn, their hand is considered
> tenpai if it is possible for it to be tenpai after discarding.

两条都在同一段里：
1. **「四张同种不能等第 5 张」⇒ 不听**（= 改动 2 的方向，但 EMA 数的是**整手牌**，含副露）；
2. **「待ち牌が捨牌と副露に全部見えていても仍算听牌」⇒ 纯空听算听牌**（与天凤一致）。

规则书自带的两个例子（PDF 用自制麻将字体，映射已经用同文件的三个振听例子校验过：
`asdfghjkl` = 1-9 筒、`zxcvbnm,.` = 1-9 索、`qwertyuio` = 1-9 万、大写 = 被鸣的横置牌）：

- **例 1（判不听）**：`z x c` + `o` ‖ 吃 `123m` ‖ 碰 `999m` ‖ 吃 `234p`
  = 暗牌 `1s2s3s 9m` + 3 副露，**9m 单骑，而 999m 是自己碰的**。
- **例 2（判听牌）**：同一手把暗牌的 `9m` 换成 `9p`，规则书注明
  「**tenpai regardless of how many 9 circles are visible in the discards and opponents' called sets**」。

**例 1 就是天凤明说「テンパイになります」的那个形。这是两套规则的真实分歧点。**
EMA §6.6.2 与 6.6「Declaring riichi while noten」把不听立直定为 chombo ——
也就是说 EMA 的立直合法性同样接在这个 tenpai 定义上，和我们（与天凤）的接法一致。

### 3.5 算法侧的一手技术资料（三条改动的理论出处）

**tomohxx「ブロック分解方式向聴数計算アルゴリズムの精度の検証」**
（`zenn.dev/tomohxx/articles/aecace4e3a3bc1`）：

> 先に結論を述べておきます。ブロック分解型向聴数計算アルゴリズムは**孤立牌不足**の手牌で
> 向聴数計算を間違えます。例えば正しくは一向聴の手牌を誤って聴牌と判断することがあります。
> 孤立牌不足の手牌とは**5ブロック取ることができない手牌**のことを指します。
> ……**生き孤立牌**: 雀頭に変化できる孤立牌／**死に孤立牌**: 雀頭に変化できない孤立牌

它转引的「麻雀C言語プログラム集」原注，正是我们改动 3 的出处：

> 【問題点】例えば「東東東東南南南南西西西北北北」のシャンテン数は１ですが、このソースでは
> ０（テンパイ）になってしまいます。これは**４枚目の字牌はターツになる事ができない
> 「死に孤立字牌」**なのが理由です。これを回避するには「どれか一つでも「４枚目の字牌」を
> 持っていたらシャンテン数＋１」とすれば良いかもしれませんが未検証です。

它还穷举出了**全部**会算错的手牌型（13 张 4 型 / 14 张 3 型，型名里 `4` = 四枚使い、`3` = 面子、
`2` = 搭子、`1` = 生き孤立牌），并证明「孤立牌不足 ⇔ 算错」且「错的一定正好差 1」，
外加出现频率：**13 张手牌里约 6500 万分之一，14 张里约 160 亿分之一**。

**tomohxx「正確なブロック分解方式の向聴数計算アルゴリズムの提案」**
（`zenn.dev/tomohxx/articles/16c0d807218d2a`）提出的三条修正，与我们的改动一一对应：

| tomohxx | janpo |
|---|---|
| 4枚使いを双碰待ち(シャンポン待ち)とみなさない | 改动 2(b)：对子搭子要求 `not (isQuad original index)` |
| 孤立牌不足になり得る手牌では孤立牌を数える | 改动 2(a)：`anyFloater && allFloatersAreQuads` → +1；改动 3：`deadQuadKinds` 下界 |
| 枝刈りを導入して高速化する | 未做（03 走朴素 DFS，13.7 µs/手，够用） |

同一篇还点名否掉了一个**看起来更直观、其实错的**修正方案（正是本次调研要防的那个坑）：

> 「聴牌と判定された場合に**待ちの枚数が残り何枚あるか**をカウントして0枚の場合は向聴数1を返す」
> ……この案では上記の4333型と4433型の手牌に対する間違いは修正できますが
> **その他の分類型に対する間違いは修正できないことに注意が必要です。**

**我们的实现没有走这条路**——它没有去数「剩余枚数」，走的是形态侧的正解。

**Mortal / libriichi** 的向聴数实现（`libriichi/src/algo/shanten.rs` 首行）：

> //! Rust port of tomohxx's C++ implementation of Shanten Number Calculator.
> //! Source: <https://github.com/tomohxx/shanten-number-calculator/>

即：跑在天凤上的最强 AI，用的就是 tomohxx 这一套（含上述修正）的向聴数。

而且引擎目前**结构上无法表达另一侧**：

> **「5 枚目を待つ聴牌」的口径**：天凤只看暗牌（碰了 `999m` 再单骑 `9m` = 听牌），
> EMA 竞技规则看整手牌含副露（同一手 = 不听，规则书 §3.3.8 例 1）。
> 引擎取天凤口径；因为 `HandShape` 只有 `nakiCount`、没有副露牌面，**当前无法配置成 EMA 口径**。
> 实测影响 4 / 72 204 座位（0.006%）。若将来要加竞技预设，需要给 `HandShape` 带上副露牌面
> 或给 `Ruleset` 加一个 `TenpaiRule` 开关。雀魂取哪一边**未找到一手资料**。

**建议 C（推荐做，最有价值）—— 给 13 票加一条独立锚点断言。**

03 报告自己承认「期望值是照我们自己的实现写的」。真正独立的锚点只有真实牌谱。
13 票（真实牌谱对拍）已经要跑天凤 JSON 的 oracle，建议在它的验收里加一条：

> 荒牌流局局（排除流し満貫局与途中流局）上，逐座位对拍
> `PlayerState.isTenpai` 与天凤清算结果（`deltas` 的正负 / 天凤 JSON 的 `全員聴牌` `全員不聴`）。
> 仓库固件的 18 局里有 15 局可判定（60 个座位判定），本次调研已用全量 12 188 局
> （72 204 个座位判定）验过 0 处不符——固件那 60 个座位可以直接固化成回归断言。

**建议 D（可选）—— 03 的三条待审项里，第 3 条（死张下界）可以直接放行。**

它不需要人在规则层面拍板：40 万手实验里它一次都没有改变过听牌 / 和了判定（§4.1），
且有结构性论证（§1.3）。把它从「需人确认」降级为「已确认，纯算法正确性问题」即可。

### 5.3 为什么现有测试「没抓到」

严格说：**没有东西可抓——三条都是对的**。但把这个问句认真回答一遍，能看出测试网上的两个真洞：

1. **`ShantenTests.fs` 的两条具名用例（`四张全在手里的单骑不算听牌`、`四张全在手里的字牌是死张`）
   的期望值是照实现写的**，oracle 固件也是拿 `mahjong` 库生成的——
   而 `mahjong` 库与我们「碰巧」都实现了同一套修正。这一层是**互相印证**而不是**独立验证**。
   本次调研补上了两个真正独立的锚点：`xiangting`（证明型算法）与**真实牌谱的天凤清算**。
2. **规则集分歧这一类问题，现有测试原理上抓不到**：`HandShape` 里没有副露牌面，
   于是「碰了 `999m` 再单骑 `9m`」在引擎里**只有一种可能的答案**。
   不是测试写漏了，是类型把另一半规则空间切掉了。这类问题只能靠 ADR / CONTEXT 记住，
   或者等真的要加雀魂 / 竞技预设时再拓宽 `HandShape`。
3. 另外提醒一句：`Ukeire.Tiles` 保留 0 枚牌种是有意的（03 的决策），
   但它意味着 **`Ukeire.live` 为空 ≠ 不听牌**。若哪天有人图省事写
   `not (List.isEmpty (Ukeire.live u))` 当听牌判据，就会悄悄把纯空听判成不听，
   04 与 09 一起错，而且现有测试确实抓不到（固件与用例里没有纯空听样本）。
   **建议在 `Ukeire.live` 的 XML 注释里加一句「不得用于听牌判定」**，
   或者在 `UkeireTests.fs` 里补一条纯空听的具名用例把这条钉住。

## 6. 未解决的疑点

1. **天凤是否对「立直宣言时的听牌」与「流局时的听牌」用同一份定义**——手册只有一份规则清单，
   没有分开写。旁证很强（同一张清单里同时写着「形式聴牌あり」「振聴リーチあり」，
   且 13 次待牌 0 枚的立直被受理），但**没有明文**。若哪天要死磕，
   可以在牌谱里找「立直宣言时暗牌握满 4 张某牌种、只等第 5 张」的局——
   本次 129 179 个 kyoku 里**一例都没有**（真人不会立这种直），所以这条只能停在「未证实但高度可信」。

2. **雀魂（MahjongSoul）取哪一边**——官方规则原文里没找到「5 枚目を待つ聴牌」的条款。
   **未找到一手资料。** 若 12 票或将来的雀魂预设要用，需要单独调研（或实机验证）。

3. **EMA 例 1 的字体解码**——PDF 用自制麻将字体，我用同一份 PDF 里三个振听例子
   （文字描述给了答案：「3, 6 and 9 circles」「1 and 4 circles」「4 and 7 circles, and red dragon」）
   反推出了键位映射并全部对上，因此对例 1 的解读（碰 `999m` + `9m` 单骑 = 不听）**有把握但非零风险**。
   例 2 的文字描述（「tenpai regardless of how many 9 circles are visible」）是独立佐证。

4. **三麻**：`canJoinRun` 对 `TileKindSet` 的推广已经和 `xiangting` 的 `PlayerCount.THREE` 对上了
   （§4.2），但三麻还有拔北等规则会让「手牌」的含义变化，**本次没有查**。

5. **`AgariShape` 与「等第 5 张」**：`HandShape.create` 拒绝第 5 张，
   所以「荣和第 5 张」结构上不可能发生（`PlayerState.isAgariWith` 的注释已经写明）。
   这一点没有独立验证过——牌谱里也不会出现。风险极低，记一笔。
