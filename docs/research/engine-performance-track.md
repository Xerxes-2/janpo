# 引擎性能：长期课题的登记册

**这不是一份研究报告，是这条线的登记册。** 每一轮研究或改动落地后往这里加一行，
让下一轮不必重新翻三千行 `DECISIONS.md` 才知道「上一轮量到哪、哪些前提是悬空的」。

## 这条线的规矩

1. **先量再改。** 每一轮先给数字，再谈改法。调度器已经在这条线上错过两次
   （见 `docs/agents/judgments.md` 判据 13 及其补强）。
2. **先问「一趟做几次」，再问「一趟多贵」。** 外层动作（起进程、装依赖）只发生个位数次；
   内层循环（每决策、每张牌、每次调用）是三四位数次。两次判断失误都源于先看了外层。
3. **每一轮必须回答上一轮留下的悬空前提。** 悬空的东西记在本册「未答」一节，不许攒着。
4. **产品路径上不做没量过的优化。** 页面本来够用（一次决策毫秒级，夹在 1–30 秒的模型调用之间）；
   做优化的正当理由通常是**别的**——例如 CI 的 CPU 总量、或扩大语料的可行性。
5. **语义不许动。** 每一轮的验收都包含：黄金用例逐字段、真牌谱对拍零差异、双目标对拍逐字相同、
   改前改后 soak 事件流逐条相同。**数值变了就不是优化，是行为变更。**
