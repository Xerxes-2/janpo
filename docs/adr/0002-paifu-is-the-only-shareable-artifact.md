# Paifu 是唯一的可分享物，不存在局面快照格式

一场对局对外只有一种序列化形式：Paifu（mjai 事件流 + 可选的 DecisionRecord 列表）。URL 分享携带压缩后的事件流（省略 thinking），JSON 导入导出携带全量，两条路径共用同一个解码器与同一条回放路径——Replay 就是对事件前缀做 fold。之所以不做「短局面快照」，是因为快照会引入第二套必须与引擎状态长期同步的序列化格式，同时丢掉时间轴步进与思考记录，而那正是分享的卖点；事件流本身很小，体积大头是 thinking，省掉它就足够短。

## Consequences

- URL 长度随对局推进增长，长半庄的 URL 会偏长。可接受：真要更短，压缩与编码是渲染侧的优化，不需要新格式。
- 引擎新增状态字段不需要同步改分享格式——状态是 fold 出来的，不是存下来的。
- 「回放」不需要独立测试路径：黄金用例已经在测事件流 fold，分享功能只需测编解码往返。

## 两条修订（调度器补记）

**一｜URL 分享省掉的不止 thinking**（2026-08-24，票 110 指出，源头是票 77）。
正文那句「URL 分享携带压缩后的事件流（**省略 thinking**）」已经**拆旧**：
票 77 之后 URL 那条路走的是 `Paifu.stripAudit`——**整条 `DecisionRecord` 列表都不带**
（`Decisions = []`、`Prompting = empty`），不只是省掉 thinking。
只省 thinking 那一档（`Paifu.forShare`）今天**没有生产调用方**，留在引擎里当同族的另一档。
判据 15（拆旧的记录要么订正、要么删掉）：这里订正，不删——**决定本身没变，变的是「短」是怎么做到的**。

**二｜那笔账不是牌谱的一部分**（2026-08-24，票 110 的判断）。
`Table.Voided`（问话花了钱但没落子：过期剪枝 / 拨座位撤票 / 开下一局作废）**判给会话，不进牌谱**。
理由：三种起因里两种是坐在这台浏览器前的人按的那一下、第三种是 HTTP 与牌桌时钟的竞态，
**同一份事件流换个人打开一笔都复现不出来**（`Table.replay` 里 `Voided = []` 就是它的形状）；
牌谱里其余每一样都对得上事件流，唯独它没有任何对照物。
- 这**不与本 ADR 冲突**：ADR 管的是「不许有第二套序列化格式」，账单口径管的是牌桌上那一行。
- **缺口两头都要说出来**（票 110 落成闸门）：Live 侧说「导出的牌谱不带这几笔」，
  牌谱进来那一侧说「当时花掉的只多不少」；URL 分享那一屏因为 0 tok 而不长这一行——
  **没有数就没有要声明的缺失**。
- **推翻的触发条件**：`Table` 上再长出第三本不进牌谱的账、或「花掉的总额」这个口径再分叉。
