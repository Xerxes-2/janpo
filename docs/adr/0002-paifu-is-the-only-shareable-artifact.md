# Paifu 是唯一的可分享物，不存在局面快照格式

一场对局对外只有一种序列化形式：Paifu（mjai 事件流 + 可选的 DecisionRecord 列表）。URL 分享携带压缩后的事件流（省略 thinking），JSON 导入导出携带全量，两条路径共用同一个解码器与同一条回放路径——Replay 就是对事件前缀做 fold。之所以不做「短局面快照」，是因为快照会引入第二套必须与引擎状态长期同步的序列化格式，同时丢掉时间轴步进与思考记录，而那正是分享的卖点；事件流本身很小，体积大头是 thinking，省掉它就足够短。

## Consequences

- URL 长度随对局推进增长，长半庄的 URL 会偏长。可接受：真要更短，压缩与编码是渲染侧的优化，不需要新格式。
- 引擎新增状态字段不需要同步改分享格式——状态是 fold 出来的，不是存下来的。
- 「回放」不需要独立测试路径：黄金用例已经在测事件流 fold，分享功能只需测编解码往返。
