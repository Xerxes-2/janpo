# 不做 live 观战：Host 的浏览器是唯一的对局推进者

v1 里一场对局只在 Host 的浏览器里前进——key 存在他本地、请求由他直发 provider——所以别人打开链接时看到的必然是 Paifu 回放，不是实时牌桌。「打开 URL 就看到一桌牌在走」的第一印象由随应用分发的 Demo Paifu 自动播放来兑现。原 SPEC 的 Story 1 写的是「正在进行的对局」，那在无后端加自带 key 的前提下物理上不成立：访客的浏览器里没有任何东西能推进牌局。

## Consequences

- Live 观战需要一个广播事件流的后端与服务器侧对局状态，正是本期 Out of Scope 明确排除的东西。要做就是二期，且届时应作为与 Mortal 容器同级的**可选**依赖，不得成为单点。
- 「围观者」不是权限级别，只是视角；Host 与 Visitor 都能处于它。因此 UI 的可见性规则（上帝视角、思考气泡解锁）应挂在对局配置与终局状态上，不是挂在「用户是谁」上。
- Demo Paifu 是产品资产而非测试固件：它决定陌生人对这个平台的第一印象，值得挑一局好看的牌。
