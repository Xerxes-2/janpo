# 调度器裁决与备注

与 `DECISIONS.md` 分开的理由很实际：agent 与调度器都往 `DECISIONS.md` 尾部追加，
每次都在同一处冲突。本文件**只有调度器写**，agent 不碰。

## 裁决 D-1：标识符用术语表拼法，wire 用 mjai 原拼

04 票把事件 case 命名为 `Event.Ryuukyoku`，而 wire 是 `"ryukyoku"`（mjai 的实际拼法，
少一个 u），并把这个出入标为待审——因为我在派工时写的是「case 名 = mjai 事件名转 PascalCase」。

**我派工的措辞不对，04 的做法对。** ADR-0001 已经定了：标识符遵循术语表的罗马字拼法。
`Ryuukyoku` 是 `CONTEXT.md` 里的词，wire 是外部协议的既有事实，两者本就该分离——
这正是 ADR-0001「人类可读形式隔离在渲染层」的同一条原则，只是这次隔离的是**协议层**。

规则定死，05-14 票不必再议：**F# 标识符用 `CONTEXT.md` 的拼法；JSON wire 用 mjai 原拼；
两者不一致时在编解码处一行映射，不改标识符去迁就 wire。**

## 裁决 D-2：把 06 与 07 并行，偏离睡前的波次表

睡前定的是 `{04,07}` 并行、`06` 串行。实际情况：04 先落地，07 仍在跑，而 06 只阻塞于 04。

让 06 干等 07 是白等一整波。06 改的是 step 机制（和了成立、振听、头跳），07 是纯役种函数，
**两者的重叠面与刚刚成功集成的 `{04,07}` 同构**（只在 fsproj 与 Program.fs 的列表上撞）。
且 06 票明确不算点数与役——它不消费 07 的任何东西。

所以 06 派进 ws-a（04 腾出来的），与 ws-b 的 07 并行。串行纪律仍然守在真正互相踩的那批上：
`09/10/11/12` 全部改同一块响应阶段与动作集，那里不并行。

## 备注 N-1：04 交出的动作集扩展契约（05-12 票都要照它）

加一个动作固定改三处：① `Action` 的 case；② 产出动作集的函数——摸牌后的填
`awaitingDahaiActions`（06 自摸和 / 09 立直 / 11 暗杠），他家打牌后的填 `responsesTo`
（06 Ron / 10 Pon·Chi / 11 大明杠，现恒返 `[]`）；③ `step` 的执行 match。漏哪处编译器都报。

**04 留下的关键警告**：06 与 10 谁先填 `responsesTo`，就必须同时加一条「过」（mjai `none`），
否则响应阶段会停在那里没人推得走——这是个能让 soak 死锁的坑，写在这里免得两票互相以为对方会加。

## 备注 N-2：05 与 06 的票范围重叠（我切票时的失误）

07 落地后，理论上的 frontier 是 `05`（只阻塞于 04）与 `10`（只阻塞于 04）。两者我都**没有**派：

- `10` 要往 `responsesTo` 里填 Pon/Chi，而 06 此刻正在往同一处填 Ron 与「过」——这正是裁决 D-2
  说好不并行的那批。
- `05` 的问题更微妙，是**我切票时的失误**：05 票写了「无人和了时按规则决定进局或连庄」，
  而 06 票也写了「和了产出 Hora 事件并正确进局或连庄」。**进局/连庄 这块逻辑被两张票同时声明了。**
  并行会让两个 agent 各写一份，且 05 只能看到 Ryuukyoku 一种终局，写出的转移逻辑接不住 Hora。

所以 07 之后没有可派的票，等 06。这不是 DAG 画错（05 确实只依赖 04 的 `GameState`），
而是**票的边界没切干净**——DAG 只能表达「依赖」，表达不了「两票会写同一段逻辑」。

早上若要复盘切票质量，这是最值得看的一条：`to-tickets` 产出的阻塞边是必要条件，不是充分条件。
