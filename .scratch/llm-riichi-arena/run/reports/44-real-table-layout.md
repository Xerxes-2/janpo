## 1. 布局怎么摆的

### 1.1 一个三×三的格子，四家围着中央

```
grid-template-areas:
  "toimen  toimen  toimen"     ← 对家占满上面一整行
  "kamicha center  shimocha"   ← 上家 / 牌桌中央 / 下家
  "self    self    self";      ← 自家占满下面一整行
```

上下两家占满整行是因为**手牌 14 张要地方**（一行约 420px），左右两家各 1fr 就够放一块
六列的河 + 两行牌背。**中央那一格摆场况**：局数与本场、供托与立直棒、剩余摸牌、宝牌指示牌
（上帝视角还多一行里宝牌）——真牌桌上它们本来就在中间，四家围着它坐。

`.board-head` 那条横条因此没有了（它的四个字段原样搬进 `.table-center`，**testId 一个没改**：
`table-kyoku` / `table-kyotaku` / `table-wall` / `table-dora` / `table-uradora` / `table-bou`
照旧，`verify-export.mjs` 与 `verify-llm-seat.mjs` 读它们的地方一行没动）。

### 1.2 三排牌从外往内摆

一家的三排是 **副露 → 手牌 → 河**（DOM 顺序就是这个），真牌桌上就是这么放的：
副露在身侧最外、手牌在自己面前、河推到桌心。四个方位各自把这三排**朝中心那一边翻**：

| 方位 | 怎么翻 | 结果 |
|---|---|---|
| 对家（上） | `flex-direction: column` | 上→下 = 副露、手牌、河 —— 河贴着桌心 |
| 自家（下） | `column-reverse` | 上→下 = 河、手牌、副露 —— 河贴着桌心 |
| 上家（左） | 列向照旧，**横向对齐说话**：`.kawa { align-self: flex-end }`、`.naki-row { flex-start }` | 河贴右（中心）、副露贴左（外侧） |
| 下家（右） | 同上镜像 | 河贴左（中心）、副露贴右（外侧） |

**左右两家没有把牌转 90°**：那要给每张牌定死宽高、再给三排各写一套竖排规则，
是「CSS 上过夜」的开头，而票面的合格线是「看得懂一局」。这一版用**横向对齐**表达朝向，
效果见图；真要转，M2 的思考气泡那一票之后再单开。

**河摆成每行 6 张的方阵**（`grid-template-columns: repeat(6, auto)`，标题独占头一行）——
牌谱与真牌桌都是这个摆法，一眼看得出打到第几巡，而且每家的河宽度固定，四个格子不会互相挤。

### 1.3 方位跟着视角转：判据只有一处

```fsharp
// src/Janpo.Web/Board.fs
let anchor (board: BoardView) : Seat = board.Viewer |> Option.defaultValue Seat.first

let position (ruleset: Ruleset) (anchor: Seat) (seat: Seat) : Position =
    match Seat.distanceFrom ruleset anchor seat with
    | 0 -> Position.Self
    | 1 -> Position.Shimocha
    | _ when Seat.toimen ruleset anchor = Some seat -> Position.Toimen
    | _ -> Position.Kamicha
```

三件事值得写下来：

1. **座位算术全交给引擎**（`Seat.distanceFrom` / `Seat.toimen`）。三麻没有对家，
   `Seat.toimen` 自己返回 `None`，于是第二家落回上家——这一层不重写一份 `(seat + 2) % 4`。
2. **上帝视角的参照系是起家（座位 0）**，并且**页面上把这句话写出来**
   （中央那行小字：`上帝视角：以起家（座位 0）为下方`；坐着看时写的是
   `坐在座位 N：自家在下、下家在右、对家在上、上家在左`）。M1 传下来的第六条规矩是
   「相对方位必须显式声明参照系」，这行字就是那条规矩的落地，`data-anchor` 是它给机器看的一半。
   被否决的两种：不声明（读者只能猜「下家」是谁的下家）、拿「上一次坐过的座位」当参照系
   （要多存一份状态，而起家是牌谱与 CLI 一直在用的锚点）。
3. **DOM 顺序仍按座位升序**，画到哪个格子由 `data-seat-position` 决定，
   CSS 按这个属性选格子（`.seats-board [data-seat-position="toimen"] { grid-area: toimen }`）。
   于是 `seat-N` 那些钩子与既有闸门全不受影响，而**位置**跟着视角走。
   代价与收益写在 §3.3（属性与坐标同源，因此闸门两头都核）。

`Board.position` 与 `Position` 是新加的**渲染层出口**（ADR-0001）：`toWire` 给 `data-`，
`toDisplay` 给页面上那枚「下家」小标签（**只在坐着看时写**——上帝视角没有观测者，
写「自家」会指向一个不存在的人）。

## 3. 「渲染给人」那一侧的闸门

### 3.2 八项：人看见的那一半、机器读的那一半，以及把两头对上的那条断言

**判据的形状是刻意的**：`data-` 只是同一件事给机器看的一半。只核 `data-` 的话，
牌一张不画、只留属性照样全绿（票 32 那次缺陷正是这个形状）；只核文字的话，属性写错没人知道。
所以每一项都**两头对上**，凡是「看得见/看不见」的记号还去读**计算样式**。

| 项 | 人看见的 | `data-` | 断言（除了两头一致以外的那条） |
|---|---|---|---|
| ① 手牌 | 自家的牌面 / 他家的斜纹牌背，标题「手牌 N」 | `data-hand-count`、`data-hand-hidden` | 亮着的恰好一家、且它就是画在「自家」那个格子里的；**牌背的边框色不许是透明的、必须有斜纹底**（票 32） |
| ② 河 | 牌 + 摸切的虚线淡色，标题「河 N」 | `data-kawa-count`、每张 `data-tsumogiri` | 每张都标了手切/摸切；**摸切的计算边框必须是 dashed、手切必须是 solid** |
| ③ 副露 | 组、横放那张、「来自上家」标签 | `data-naki-count`、`data-naki`、`data-naki-from(-seat)`、`data-naki-taken`、`data-naki-added` | 票 38 那四条（非暗杠恰一张横放 + 有来源；暗杠两样都没有；中文说法与绝对座位对得上、吃恒来自上家；只有加杠有「＋」）**外加**「来源那枚标签的文字必须真写出来」 |
| ④ 点数 | 座位卡上那个数 | `data-score` | **四家点数 + 供托×1000 恒等于开局那一刻的总点**（起手总点不写死在闸门里，从页面读） |
| ⑤ 供托与本场 | 「N 根」+ N 根立直棒；「东1局 M 本场」 | `data-kyotaku`、`data-bakaze/-kyoku/-honba` | 立直棒的根数 = 供托数（0 时整个字段不画，票 32）；**首局里供托 = 立直成立的家数**（把 ⑤ 与 ⑧ 互相当对照） |
| ⑥ 宝牌指示牌 | 牌面 | `data-tile-count` | 至少一张，且写着几张就画出几张、那一格不是空的 |
| ⑦ 巡目 | 「第 N 巡」 | `data-junme` | **再走 6 手，四家巡目之和必须变大、且没有一家倒退**（写死一个数骗不过去）；快照后一手也没走成就报「在空转」 |
| ⑧ 立直状态 | 头上那枚「立直」标记 | `data-riichi`（none/declared/accepted） | 三档之一；立直了必须有那枚标记，没立直不许有 |
| 顺带 | 赤牌的红字、刚摸那张的间距 | —（读计算样式） | 赤牌与普通牌不许同色；`.tile.drawn` 的 `margin-left` 必须 > 0 |

顺带那两条不在票面的八项里，但它们是票 38 列的**七种记号**里剩下的两种——
既然这一票的任务是「一个都不许弄坏」，就把它们也钉住（§5）。

### 3.3 方位：属性与坐标两头都核

五个视角（座位 0-3 + 上帝视角）各点一遍，每次：

1. `data-anchor` 必须等于该视角的参照系（上帝视角必须是起家 0）；
2. 每一家的 `data-seat-position` 必须等于 `(座位 − 参照系 + 4) mod 4` 那一档；
3. **元素中心的坐标**：自家在最下、对家在最上、上家在左、下家在右；
4. 四个座位视角下**画在下方的必须是四个不同的人**——这条专抓「切了视角但布局没转」。

第 2 条与第 3 条不是重复：样式表按 `data-seat-position` 选格子，所以属性错了坐标跟着错；
但坐标还抓得住另一件事——**格子本身摆错了**（`grid-template-areas` 写反、媒体查询把三列拍平）。
§4 的第 12、13 条就是这两种坏法各红一次。

新闸门第一版把 `process.exit(1)` 写在 `try` 里，而邻居（`verify-export.mjs` /
