## 1. 分界线划在哪

判据一句话：**改这一桌「怎么开」的归 `setup`，改这一桌「怎么走 / 怎么看」的归 `ops`。**

| 归 `setup`（「配这一桌」，收在页面上半） | 归 `ops`（「操作这一桌」，贴着牌桌上沿） |
|---|---|
| 对局长度 · 赤宝牌 · 食断（票 72） | 播放 / 暂停 · 单步 · 下一局 · 倍速 |
| **种子 + 重开**（从视角那一排收过来） | 从头再放 · 时间轴 · 上一步 / 下一步 · 跳到局号 |
| 四席绑定（座位 → 选手 → 档位 → 人格/模板） | 导出牌谱 · 复制分享链接 + 那句分工说明 · 导入牌谱 JSON |
| 模型档案库（provider·模型·key·baseUrl·超时·思考） | 视角 · 上帝视角 · 危险度 |
| 渲染版本那一行、那一大段说明（`panelNote`） | —— |

三处判断值得写下来：

1. **种子与「重开」跟着配桌走**（票 72 报告里记的第一条 nitpick，这一票兑现）：拨完那三项要按
   「重开」才生效，而「重开」原本在视角那一排上——两个动作分在两处，人得来回找。现在**四样并成一排**，
   拨完手不用离开那一行。
2. **视角与危险度跟着牌桌走**：它们改的是**这一桌的呈现**，拨一下当场就要看见牌桌变样。
   调度器裁的就是这一条，落地没有异议。
3. **那行 token 账单（票 79）本来就在牌桌里**（`TableBoard.tableBody` → `AgentLine.usageLine`，
   在 `table-board` 这个盒子内部），因此「算这一桌的信息、跟着牌桌走」这一条**不用改代码就已经成立**。
   我核过 DOM：`table-usage` 是 `table-board` 的子节点。

**两屏一套装配**（票面第 3 条）：`TablePage` 从前有 `homePage` / `hostPage` 两个布局各自摆块，
现在只有一个 `layout model live dispatch intro`，`live` 是 `LiveTable option`——
**配桌那一块是 `Option.toList` 出来的**，回放那一侧结构上就没有它。
两页的差别只剩下抬头下面那几句话（首页两段、主持人一段）。

## 2. 收起来的那两块用了什么形态

都是**原生 `<details>`**，不进 MVU、不加消息、不占 localStorage、无动效（票面「不做动效补间」）。
选它的理由：折叠状态是**这台浏览器此刻的读法**，不是这一桌的状态；
做成 `TableMsg` 就得给每一席存一格 `bool`，而票面明写「不动消息」。
React 侧不给 `open` 属性，因此 React **不会**在重渲染时把人敲开的那一格合回去（实测：
播放中每 300 ms 一帧，敲开的那一格一直开着）。

### 2.1 一席的「人格·模板」

```
座位 0 [均匀随机][有主见][档案 1] 脚手架[裸奔▾]            ▸ 人格·模板〇默认
座位 1 [均匀随机][有主见][档案 1] 脚手架[裸奔▾]            ▸ 人格·模板●人格
```

- **收起时看得出有没有内容**：摘要上写的不是一枚圆点而是**哪一格填了**
  （`〇默认` / `●人格` / `●模板` / `●人格·模板`），机器读 `data-seat-custom`
  （`""` / `persona` / `template` / `persona,template`）。
  只画一枚点的话，人看得出「有东西」却看不出「哪一格有」——那正是这一票要治的毛病。
- **展开一席不把另外三席顶出屏外**：收起时它贴在行尾（`margin-left: auto`），
  **敲开之后独占本行的下一行**（`.seat-detail[open] { flex: 1 1 100% }`），
  只长一排文本框的高度。实测（视口 1280×720）：四行收起时跨 `318→476`，
  展开一席后跨 `318→583`——**四行仍然全在一屏里**，闸门量的就是这一条（§4.2）。

### 2.2 那一大段说明（`panelNote`）

```
▸ 这几格都是什么意思？key 存在哪儿？模型不说话怎么办？（点开看）
```

**一个字没删**（连票 30 那段自定义端点的坑也在里面，仍旧只在库里真有那么一份档案时出现），
只是收成一行 19 px 的小字。摘要写成三个问句而不是「说明」两个字——人要知道点开有什么才会点。

### 2.3 档案库与座位绑定分成两块

`llm-panel` 里现在是两个 `.panel-block`，各带一句小标题，中间一条淡线：

- **谁坐哪一席：选手·档位·（人格·模板）** —— 四行，答「谁坐哪、给多少信息」；
- **模型档案库：怎么问这个模型（key 只在这里填）** —— 页签 + 六格 + 渲染版本行。

理由写在代码注释里：**一份档案坐三席时下面那块只填一遍、上面那块要拨三次**，
它们是两种东西，混在一片读不出这件事。

### Spec — 票面逐条

六条行为、两条闸门边界、五条边界逐条对上（票文件里的框已勾）。三处值得写下来：

- **「四席一眼看全」落成了几何断言而不是眼力活**：闸门读的是四行的真坐标与视口高，
  因此下一个人往座位行里加东西时会当场红，而不是等主人再试玩一次。
- **`TablePanel.controls` / `viewpoints` 从 `internal` 降成 `private`**，对外只剩 `setup` / `ops`
  ——「一页只有两块」这件事因此是**类型层面的**，不是纪律。dotnet 侧用例读的是 `TablePage`
  的那十六个出口，一个没动（202 条全绿）。
- **`?table=1` 那段抬头说明里「下面四行是四个座位各自的绑定」仍然成立**（配桌在上、四行还在下面），
  因此那段话没改——**这是运气好，不是设计**：文案里写方位的句子会被重排咬到，下次重排要先扫一遍。

### 记录但没改的 nitpick

1. **`.seat-detail` 用 `margin-left: auto` 顶到行尾**，因此「脚手架」与那枚记号之间是一片空白。
   四枚记号排成一列好扫，但窄视口下它会先换行。想更紧凑得把座位行改成 grid，
   而 grid 的列宽由所有行的 max-content 决定——敲开一席会让另外三行的列宽跟着跳，反而更糟。
2. **主持人那一页抬头那 82 px 的说明**没动（见 §3.4）：它是产品文案，改它该由主人拍板。
3. **`table-rules` 那句「这一桌就是按这三项开的」**现在与种子同排，而种子不在「这三项」里。
   措辞仍然准确（它说的是规则），但读起来容易被当成四项。改文案同样是主人的事。
4. `verify-home` 里那两条新函数（`opsShape` / `opsProblems`）与票 81 在同一个文件里，
   **块与块之间没有重叠**，但集成时若两票都改了这个文件，按块合而不是按行合。
