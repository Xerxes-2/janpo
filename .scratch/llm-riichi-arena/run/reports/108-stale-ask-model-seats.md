## ① 先复现：票面那个机制走不到，走得到的是另一个

### 1.1 「响应阶段当场散掉」在这个引擎里散不掉

`src/Janpo.Engine/GameState.fs` 的 `applyResponse`：

```fsharp
let remaining = waiting.Responses |> List.filter (fun each -> each.Seat <> actor)
…
if List.isEmpty remaining then …裁决… else …接着等…
```

**一席只会被它自己的答复摘掉**，别人碰了也不会让还没答的那一席的待答消失
（`Responses = remaining`，那几项一个字节都不动）。因此「A 席在飞、B 席碰了、A 的待答整条消失」
这件事**不成立**——响应阶段要收齐才翻篇，而收齐意味着 A 也已经答过了。

**这不是读代码读出来的印象，是扫出来的**（临时探针，跑完即删）：
四席全模型、40 颗种子 × 两种到达顺序（正序 / 倒序＝并发最坏的错位），
每一手都挑**最能把局面搅乱的那一条**（荣和 > 杠 > 碰 > 吃 > 立直 > 第 0 条）：

```
正常对局：80 场、336 局、28916 手、28916 次问话（其中 124 次是多席同问的那一轮）→ 过期问话 0 例、剪枝 0 次
```

**票 92 报告里那句机制描述因此是错的**（判据 15：前提被后续核对拆掉时要回头重问）。
它当时同一节的第 1 条修的是**同一席被问两次**——那才是包会过期的原因：
两份包指向同一个决策点，第一份落定之后第二份就是旧的。`flying` 补上 `Consulting` 之后那条没了，
而 `Consulting` 那道剪枝**当时一条闸门都没有**（本票给它补上了，与模型席共用同一段 `swept`）。

### 1.2 走得到的那一条：人把在飞的那一席拨给自己

牌桌只有三处会绕过 `drain` 的顺序往前走：`HumanPlayed`、`HumanTicked`（两者都走 `handOf`）
与重开 / 开下一局（那两处把 `Awaiting` 整表清空）。于是**唯一的活路**是：

```
① 座位 0（模型）被问出去，回执在飞
② 人在面板上点「我自己」（SeatBound）——那一席从此是他的，而那份问话还在飞
③ 他自己打了一手 → 牌桌翻篇 → 包里的 id 不再是这一手的号
④ 几秒后鬼回执回来
```

**每一步都是页面上真点得到的**：模型答得慢（真跑里中位 1.7 s、p95 2.4 s、最长 27 s，票 79 量的）时
「不等了，我自己上」是人会做的第一件事。

## ③ 修法：一条判据、一本账

### 3.1 剪枝

`TableState.drain` 顶上原本只剪 `Consulting`（票 92），现在两侧走同一段 `swept`：

```fsharp
let current (package: DecisionPackage) = stillCurrent table package
let asking, expiredAsks = live.Awaiting |> List.partition (fun each -> current each.Package)
let consulting, expiredConsults = live.Consulting |> List.partition (fun each -> current each.Package)
```

**判据与票 92 逐字同一个 `stillCurrent`**（「引擎此刻给这一席的合法动作集与包里那一列逐条相同」），
没有另写一个。剪枝发生在 `drain` 顶上，因此 `Answered` / `HumanPlayed` / `HumanTicked` / `step`
四条路进来都过这一道。

### 3.2 账：花了钱、没落子

**新增 `VoidedAsk`（`src/Janpo.Web/Table.fs`）与 `Table.Voided`**，形状与账单口径按票 79 / 83 那一份：

| 谁 | 干什么 |
| --- | --- |
| `Table.Voided: VoidedAsk list` | 作废的那几次问话（票号 / 作废时的手序 / 座位 / 中文原因 / 账单），按作废顺序，**跨局累计** |
| `Table.usage` | **决策记录 + 作废的问话**（票 79 的口径：账单行那几个数是**花掉的总额**，不是落了子的那几手的总额） |
| `Table.voidAsk` | 记一笔（**不走 `played`**：手序不动、事件流不动、一条决策记录都不留） |
| `Table.creditVoid` | 作废那一票的回执**晚回来了**，把 token 补上（座位与票号都要对上；重复补是幂等的） |
| `Table.paidVoids` | 账单里那几笔「没落子」的（强 AI 基线在本机跑，它那几条没有账单） |

**为什么不留一条 `DecisionRecord`**（票面那条要害）：`Turn` 是手序的锚，
一条 `Turn = N` 的记录会被回放按手序摆到**别人那一手**上（`Table.replay` 的 `recordAt`），
气泡会替它编一句理由，`Table.fallbacks` 会把它算成一次兜底。**那一手没有发生**，
说得出这件事的记录只能是另一种记录——这就是 `VoidedAsk` 存在的全部理由。

**回执晚回来时那条路**（`Answered` 里原来只有一句「丢掉」）：

```fsharp
// **但钱不能从账上消失**（票 108）：这一票如果是 `drain` 剔下来的那一种（过期作废），
// 它真的调过 provider、真的计过费，只是那一手没发生——把 token 补到那一条作废记录上。
```
对不上的其余几种（重开过一桌、开过下一局、座位与票号错位）在这张牌桌上压根没有那一条记录，
于是这一句对它们恰好是个空操作。

### 3.3 那一席就此重新可问

`step` 认的是 `Awaiting` / `Consulting`（`flying`），剪掉之后轮到它就再问一次，拿的是此刻那份新包。
用例钉的不是「有一份新包」（那与剪枝判据同源，会写成恒真式），而是**落得下去**：
新那一票换得回一个此刻合法的动作、引擎收下、手序 +1、留下这一席的决策记录。

**可缓存前缀那条属性没破**（票 95 的 `prefix.test.ts`）：本票**一个字节都没碰 `web/src/agent/**`**，
重问走的是同一条渲染路径——历史是事件流的派生物，作废一次问话不删事件流里的任何一条。
