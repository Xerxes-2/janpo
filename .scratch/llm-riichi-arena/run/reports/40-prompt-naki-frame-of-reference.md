### 2.1 为什么是「**他的**上家」而不是光写「上家」

**光换参照系不够，还得就地声明**——否则只是把错从一头搬到另一头。理由很硬：
固定 preamble（可缓存前缀，`template.ts`）里写着

```
别家按相对位置称呼：下家（你的下一家）、对家、上家（打给你的那家）。
```

**它宣告了整份 prompt 的默认参照系是观测者**。在这条规矩下写「上家：副露：吃（来自上家）」，
模型按宣告的读法解出来的是「座位 0 吃了座位 0 打的牌」——一句新的不可能的话。
「他的」两个字把这一处的参照系当场翻出来，代价是尾部每组他家副露多两个字（前缀一字未动，§6）。

三种写法各自都回答得了「这个上家是相对谁说的」：

| 场合 | 写法 | 参照系 |
|---|---|---|
| 鸣的是**观测者**打的那张 | `来自你` | 无所谓——**「你」是身份不是方位** |
| **自家**那几组 | `来自上家` | 观测者（＝副露方，两者重合），与 preamble 那句一致 |
| **他家**那几组 | `来自他的上家` | 副露方，「他的」就是声明 |

`来自你` 这一档是有意留的：它比「他的下家」直接得多，而振听与安全度都要「那张是我打的」
这一条。它也不引入歧义——身份不需要参照系。

**被否决的三种**：
1. **只换参照系、不写「他的」**——与 preamble 那句读法冲突（上面刚说的）。
2. **改写 preamble 去声明副露那句的参照系**——preamble 在**可缓存前缀**里，改它等于
   废掉全部旧缓存 + 换一个 `render_version`（票 31 的运维含义），而这一处**就地两个字**能解决。
3. **改写成绝对座位（`来自座位 3`）**——最无歧义，但 29b 定的是「来源写相对位置而不是座位号」，
   牌桌（票 38）也用相对位置；两处说法要一致，且票面明写「别顺手重写 prompt 文风」。

## 4. 参照系是怎么传的

```
presentSection(decision)                       观测者 = observation.self.seat
  ├─ self(seat, words)        → naki(…, { owner: seat.seat, viewer: seat.seat })   两者重合
  └─ other(seat, words, viewer) → naki(…, { owner: seat.seat, viewer })            两者不同
                                        └─ nakiFrom(words, frame, target)
                                             target = viewer            → 「你」
                                             owner  = viewer            → words.whoFrom(owner, target)
                                             否则                        → 「他的」+ words.whoFrom(owner, target)
```

判据照 DECISIONS「票 38 在票外挖出」那一节：**一个函数同时被「渲染自家」与「渲染他家」调用、
而方位是相对的，就必须把参照系当参数传进来**。`NakiFrame` 是那个参数，两个字段各带一句
「按它算什么」的注释；`naki()` 因此**不可能**再从调用点隐含地拿参照系。

`Words.whoFrom(origin, seat)`（`wording.ts`）算「`seat` 相对 `origin` 是第几家」。
包里没有这个数——`MaskedSeat.relative` 每一项都是**相对观测者**的，而本票的硬约束是
**决策包不变**（黄金用例逐字段钉着它）。因此它**沿着座位环走**：包给的那几个 `relative`
升序排出来就是「自己、下家、对家、上家」那个圈（引擎的 `Seat.orderFrom`），
把圈转到 `origin` 那一格起头，往后数到目标是第几步。

**这不是仓库里的第二处座位取模**（`CONTEXT.md`：唯一那处在 `Seat` 的私有 `shift` 里）：
数的是**包自己给的那个圈**，圈多长、有没有对家都由引擎说了算——三麻少一格，数出来自然少一档。
数不出来（不在圈里、或者数出 0 家，那是它自己）就退回「座位 N」，形状照 `Threat.who`
与牌桌的 `TablePage.nakiFrom`。**被否决**：让 TS 去调引擎的 `Seat.distanceFrom`——
ADR-0005 写死跨界只有 `F# 调 TS` 一个方向是廉价的。

### 5.1 为什么历史那一行是对的（而且不能顺手改成副露方参照系）

`上家 第2巡 吃 对家打的 2p` 读着像「吃了对家的牌」，但它**不是**第 1 处那个错：
这一行是**观测者的旁白**，一句话里的**两家都按观测者称呼**——座位 3 相对观测者是对家，
而它同时正是座位 0 的上家，因此这句话**在日麻里成立且能落到绝对座位**。
（对照第 1 处：那句话里只出现一个相对方位词，而它挂在一段以别人为主语的小节下，
默认参照系因此漂了。）

把历史也改成副露方参照系是**不行**的，两条理由：**历史行在可缓存前缀里**（改措辞＝废掉
全部旧缓存，票 31 的运维含义），且它会把同一句里的两家劈成两个参照系（`上家 … 吃 他的上家打的`），
比现在难读。**两处说法不同但都真**：尾部说「相对副露方是上家」，历史说「那张是对家打的」，
两句指的是同一个座位 3。

### 5.2 新加的两条「确认对的」闸门

- `prompt.test.ts`：「危险度那一节的参照系是**观测者**」——逐条核 `threats[].display`
  必须以 `words.who(threat.seat)` 开头（引擎渲的中文 vs 这一层按包算的称呼对拍）。
- `history.test.ts`：「历史那一行的参照系是**观测者**」——扫 12 手真历史里的每一条 `chi`，
  先核**包里的绝对座位**（`target` 恒是 actor 的上家，否则固件坏了），再核**渲出来的那一行**
  把副露方与打牌那家都按观测者称呼。防空转：核不到 3 行吃就直接报错。

## 6. 前缀稳定性与缓存影响

**结论：可缓存前缀逐字节未变，旧缓存不作废。** 证据是拿 fixed point 那一版渲染器与现在这版
逐份对拍（`jj file show -r 4713ab42 web/src/agent/*.ts` 拷到 `/tmp` 当「修前」那一侧）：

```
共 15 份决策包 × 2 档：前缀逐字节相同 30/30，尾部原样 8/30
preamble 相同：true
---- 尾部变了的行 ----（去重后共 3 种）
decision-danger  尾部第 18 行： 修前 副露：碰 1z（来自上家…） 修后 副露：碰 1z（来自他的下家…）
decision-sequence[2..11] 尾部第 21 行： 修前 副露：吃 2p（来自对家…） 修后 副露：吃 2p（来自他的上家…）
decision-sequence[10,11] 尾部第 18 行： 修前 …吃 3m（来自下家…） 修后 …吃 3m（来自他的上家…）
```

为什么必然如此：`naki()` 只被 `self()` 与 `other()` 调用，两者都在 `presentSection`（**尾部**）里；
`historySection` 与 `preambleOf` 一行都没碰。因此：

- **`prefix.test.ts` 那条属性照样绿**（本票没让它换过一次形态，全套 111 条 web 用例绿）；
- **provider 那边攒下的前缀缓存全部仍然命中**——「改渲染 = 废缓存」这条运维含义**这次不触发**，
  因为改的那几行本来就每手付全价；
- `render_version` 也没变（它是**模板内容**的哈希，模板一字未改）。**这是一处要人知道的口子**：
  版本号认得出「换了模板」，认不出「换了渲染器代码」。见 §8 第 1 条。

**牌谱与录制固件：一个都不用重录。** `ask-*.json` 存的是模型的回答，`decision-*.json` 存的是
决策包（**本票没动决策包**），黄金用例（40 条、2069 个字段）逐字段照旧绿。牌谱里存的
`prompt_tail` 是**当时那次真的发出去的字节**，`rebuildMessages` 原样接回去——因此**旧牌谱
回放出来仍然是当时那句错话**，这正是审计要的（票 31：「渲染器当时出了什么怪，尾部原样留着证」）。

   修法有两种（把渲染器源码哈希进版本号 / 版本号里加一段人手维护的 `renderer` 号），都超出本票，
   没做。
2. **相对位置的中文映射现在有四份**：引擎 `Threat.who`、牌桌 `TablePage.nakiFrom`、
   TS 的 `wording.relative` 表（`who`）、以及本票的 `whoFrom`。第四份**没有引入新表**
   （`whoFrom` 查的就是 `wording.relative` 那张表），多出来的只是「怎么数第几家」。
   收成一处要么改 wire（决策包多带一项 owner-relative），要么让 TS 调引擎（ADR-0005 禁），
   都不在本票范围。
3. **「他的」这两个字是写死的**，不像抬头与五张措辞表那样可由模板替换。与 `来自` / `亮出`
   同一级别（票 31：槽位切在段落这一级），换措辞的人换不掉它。真要 M2 做措辞对照实验时，
   它应当与 `来自` 一起进模板。
4. **三麻**：`whoFrom` 沿包给的圈走，圈是三格时数出来只有 1 / 2 两档，而
   `DEFAULT_WORDING.relative` 把 2 认成「对家」——**这与引擎 `Threat.who` 现在的行为一致**
   （同一个坑，同一个形状），本票没有把它修好也没有把它弄坏。真上三麻时，这两处要一起改。
5. **旧牌谱回放仍显示修前那句话**（§6 末）。这是审计的正确行为，但看回放的人可能困惑；
   M2 的回放界面若要提示「这一手的渲染器版本比现在旧」，得先解决第 1 条。
