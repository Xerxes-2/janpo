## 1. 病灶：引擎的一步里夹着一次「牌谱交代不了的摸牌」

`Replay` 把事件流里的动作原样交回 `GameState.step`。而 `step` **在同一步里**做两件事：
落定这个动作，以及——没人能鸣时——**替下家摸一张**（`applyDahai` → `afterDahai` → `drawNext`，
杠之后的岭上牌同理）。摸牌不是 `Action`，事件流里那条 `tsumo` 是引擎自己吐出来的。

于是：事件流截在 `dahai` 之后、它引出的那条 `tsumo` 之前时，引擎照样摸——**摸的那一张取自
`buildWall` 推断出来的牌山**（余牌里凑数的一张），牌谱里根本没有它。

同一族的还有三种切点，都是同一个机制（首页那份真资产 756 条事件逐条扫出来的账）：

| 截断点的末事件 | 切点数 | 其中末帧带假牌 |
|---|---|---|
| `dahai`（没人能响应那种） | 363 | **268** |
| `start_kyoku`（连 Oya 的第一次自摸都不在） | 5 | **5** |
| `reach_accepted` | 2 | **2** |
| `ankan` / `dora` | 各 1 | **各 1** |
| `tsumo` / `chi` / `pon` / `hora` / `ryukyoku` / `end_kyoku` | 375 | 0 |

**合计 278 / 756 个切点**的末帧摆着一张牌谱里不存在的牌。

### 1.1 一条要给人的更正：**今天页面上的「导出」按钮碰不到它**

票面写着「页面上任何时刻都能导出 → 导入 → 拖到末帧就看得见」。我按判据 14 先量了再信：
写了一个探针，**真跑 12 场全 bot 对局，在每一个能导出的时刻**（每走一步就导一次
`Table.paifu`，共 **4166 个导出时刻**）导出、回放、比末帧——**0 个带假牌**。

原因就是上面那句「同一步」：引擎的每一步都把 `dahai` 与它引出的 `tsumo` **一起**吐出来，
因此 `Table.events` 取得到的事件流永远停在整步的边界上，落不进那种相位。

**所以这一条的真实触发面是**：手工截断的牌谱、别的工具产出的 mjai 日志、
以及**任何将来会从半步边界取事件流的路**（导入入口收的是任意 JSON，票 78）。
——**缺陷是真的，票面那条路径不是**。修还是照修：`Replay` 不该造牌，这与谁在调它无关。

## 2. 形态：选了 ①（末帧停在牌谱交代得出的最后一刻）

**理由三条：**

1. **② 做不干净。** 那一张摸出来的牌**已经在 `GameState` 里**：手牌、`Wall.remaining`、
   各座位的掩蔽流（引擎把 `tsumo` 事件吐给了 `SeatStream`）、`Observation`、
   牌数守恒律……要「UI 上不摆它」得在四处以上各滤一次，漏一处就是判据 2 那句
   「记录声称了一件事，而那件事的执行体不存在」。① 只有一处：**那一步压根不走**。
2. **① 的不变量说得出口，也守得住**：「回放交出来的局面**恒是喂进去那份事件流某个前缀**
   的 fold」。手里的每一张要么来自 `start_kyoku` 的起手，要么来自某条 `tsumo`，没有第三个出处。
   这句话可以直接当断言写（见 §3），而 ② 的不变量是「渲染层每一处都记得滤」。
3. **①「少一帧」是有代价的，我认这个代价**：`dahai` 与它引出的 `tsumo` 在引擎里是同一步，
   拆不开，所以退掉那一步等于连**那次打牌**也不显示（末帧回到打牌之前）。
   票面写的是「末帧停在最后一条事件落定那一刻」——严格说落定的是**倒数第二条**。
   两害相权：少显示一手真事 ≪ 显示一张假牌。

**② 与「标记号」都没选**；「标记号」是票面明令禁止的。

### 2.1 实现：一本账，两行判断

`Replay.Driving` 多一个字段 `Backing`：**这一局的事件流还能给引擎背书几条事件**。

- 开局那一刻 = `1 + moves 的条数 − 引擎开局产出的条数`（引擎开局吐 `start_kyoku` + Oya 的 `tsumo` 两条）；
- 每走一步减掉 `GameState.step` 这一步产出的条数（`step` 的第二个返回值，从前直接丢掉）；
- **减到负数 = 这一步越过了牌谱** → `continuing` 把整步退掉，回到步前那一刻收摊；
- 开局那一刻就已经透支（`moves` 是空的，只有一条 `start_kyoku`）→ 这一局一帧都不交，
  是最后一局就当牌谱到此为止，中间那一局就是 `Stranded`（事件流自己不自洽）。

一份完整的牌谱里引擎产出的每一条都对得上事件流里的一条（`verify-export` 那道往返闸门
钉的就是这件事），因此这本账**只会减到 0**——完整牌谱一步都不会被退掉。

**没碰的**：`buildWall`（牌山推断）、`Paifu` 格式与版本、`Table.fs`、任何 Web 部件、
`verify-export` 的断言。

## 3. 新闸门：三条，凭什么造不出假牌

三条闸门的参照物都**只有喂进去的那份事件流本身**——不碰牌山、不读规则、不拿第二份实现
当期望值，因此**它们造不出一张牌，也造不出一条事件**（判据 18：票 79 的教训是第三个锚点
自己也会造数据，要选一个「造不出数据」的）。

| 闸门 | 在哪 | 形状 |
|---|---|---|
| A | `ReplayTests.从任何一处截断，回放吐出来的事件都是喂进去那份的前缀` | 整场 770 条事件**逐个切点**（769 个）：`Replayed.events` 必须是截断流的前缀（条数 ≤、逐条相同）。附阳性对照：语料里截在「下一条就是自摸」的位置有 334 个（判据 3） |
| B | `ReplayTableTests.末尾截断的牌谱：末帧四家手里的每一张都在事件流里找得到出处` | 一整局 148 条**逐个切点**：`Table.replay` 的末帧手牌必须等于 `handsAlong` 里的某一项——**事件流某个前缀的加减法结果**（起手 + 摸 − 打 − 副露吃掉的）。附阳性对照两条：截在自摸前的切点 > 20 个；**不截断时末帧走到局终、手牌正是走到底那一份**（防「回放少走几步」变成万能出口） |
| C | `ReplayTests.只有一条 start_kyoku…` / `中间某局只有一条 start_kyoku…` | 两条把新的取舍钉成用例：只有 `start_kyoku` 时**一局都不给**（`NoKyoku`），中间那一局如此则是 `Stranded(1, …)` |

**A 与 B 为什么不共用一个断言**：A 比的是事件流（引擎有没有多吐一条），B 比的是**牌**
（人在页面上看得见的那一样）。A 便宜（`Replay.game` 5.5 ms/次），所以扫整场；
B 贵（`Table.replay` 整场 25.7 ms/次 × 941 个切点 ≈ 20 s），所以扫一局（150 ms）。

**B 的 `handsAlong` 与 `ReplayTimelineTests` 的 `handsFromEvents` 故意各存一份**：
两条被测的路共用同一个参照物时，参照物一错就两边一起错。

### 3.1 顺带改硬的一条（票 75 的用例，**没有放宽**）

`ReplayTimelineTests.拖到中间那几个游标…` 里那条二选一的手牌断言
（「要么停在截断点，要么多摸了真的那一张」）在这一票之后**在规则下不成立**了：
任何满足票 85 的实现都会停在截断点**之前**。判据 5 的那种正当理由，因此改了它——**改成更硬的**：

```
旧：got = 截断点那一刻  ||  got = 截断点 + 真的那一张      （二选一，一处松）
新：walked = 帧自报走到了第几条（Table.events）
    ① walked ≤ 截断点                                     （票 85 的上界）
    ② got = handsFromEvents(同一份事件流截到 walked)       （精确，没有「或」）
```

「走到哪里」由帧自己报，「手里是什么」由加减法算——两个来源，**帧自己造一张牌就当场对不上**
（旧实现正是造牌的同时在自己的事件流里补一条 `tsumo`，所以 ① 也照红）。

## 7. 留给人的待审项

1. **「少一帧」这件事要不要在 UI 上说一句。** 现在导入一份半步截断的牌谱时，末帧比牌谱
   最后一条事件**早一步**，页面上没有任何提示。我判断不加（票面禁止「给人看一张不存在的牌」，
   而「少走一步」不会误导）；要加就是新的一票（末帧那一条上写「牌谱到此为止」之类）。
2. **`ReplayError.NoKyoku` 的语义扩了一点**：从「没有一条 `start_kyoku`」扩成「或仅有的那一条
   后面连 Oya 的第一次自摸都不在」。两种都是「摆不出一局」，共用同一句中文提示
   （「这份事件流里一局都没有」）。要更精确的诊断得新立一个 case，我没立——
   现在这句对人已经够用，且真走到这里的只有 2 条事件的牌谱。
3. **`Driving.Backing` 是一本「条数」的账，不是逐条比对。** 它够用（引擎的日志与牌谱
   在完整牌谱上逐条相同，这件事由 `verify-export` 那道往返闸门守着），但如果哪天
   引擎开始在某一步产出**牌谱里换了位置**的事件，条数对得上而内容不对，这本账看不出来。
   要更硬就得逐条比 `GameState.events`——实测那是 O(n²) 的表结构比较，会把首页那 470 帧的
   fold 从 25 ms 拖到 100 ms 以上，我没换。
