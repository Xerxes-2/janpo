  **本轮把它拆掉了**：观测的增量维护

### 3.1 顺带抓到的一件事：一条永远红不了的闸门

`MaskedStreamProperties.incrementalAgrees`（被 `:159` 与 `:212` 两条属性共用）比的是

```fsharp
(SeatStream.start …, events) ||> List.fold (fun s e -> SeatStream.advance e s) |> SeatStream.observation
=  Observation.ofEvents ruleset seat events        // = start |> advanceAll events |> observation
                                                   // 而 advanceAll = List.fold advance
```

**两侧是同一个 fold。** 判据 3：「一条永远执行不到的断言，与一条从不失败的断言，危害相同」。
它顶着「增量维护与一次性全流 fold 给出同一份观测」这个名字，而**真在守这件事的是 Web 侧
`TableTests` 那一条**（一颗种子、一局）。

**两次反向自证**（树副本，红的输出在研究文档 §8.2）：

1. 弄坏 `SeatStream.absorb`（`WallRemaining - 1` → `- 2`）：`ObservationProperties` 两条**当场红**；
   `MaskedStreamProperties` 那两条与 `TableTests` **一条没红**。
2. 弄坏「牌桌忘了推进流」（`Views = table.Views`）：`TableTests` 两条**当场红**（「第 1 手：增量维护的
   观测与重头 fold 不一致」）；引擎侧 13 条**一条没红**。

**不许删它、不许放宽它**（`AGENTS.md` 硬约束 3）。实现票该做的是往硬里改（G2）并补一条真的（G1）。

## 4. 建议的实现票草案

**完整票面在研究文档 §15**，这里只摘要点（**票号由调度器分配，本票没建票文件**）：

**标题**：决策路径接上已有的增量掩蔽流（`DecisionPackage.forSeatWith`）

- 新入口 `DecisionPackage.forSeatWith : SeatStream -> Seat -> GameState -> DecisionPackage option`；
  `forSeat` 原样保留，内部退化成「自己起一条流吃完全部事件再走 `forSeatWith`」（票 55 的先例）
- 只改三个调用点：`Table.decide`、`TablePage.dangerPanels`、CLI `decideSequence`
- **三道闸门，每条都要反向自证**：
  - **G1**（必须）：引擎侧属性——逐手推进维护流，`forSeatWith` 与 `forSeat` 建出的包逐字段相同。
    **它不是恒真式**（左侧吃 `step` 吐出的 `produced`，右侧吃 `GameState.events state`）
  - **G2**：把 `incrementalAgrees` 从恒真式改硬（被比的一侧换成 `ofMasked (MaskedEvent.stream …)`）
  - **G3**：`TableTests` 那条从一颗种子扩成一批种子 × 两种选手
- **验收**：`janpo decide --steps/--sequence` 改前改后逐字节相同、黄金 40 条 2069 字段、真牌谱对拍零差异、
  soak 事件流逐条相同；浏览器整局净决策包成本 **≥1.8×**；**`dotnet test` CPU 变化在 ±2% 内（预期无收益）**
- **边界**：不碰 `Shanten`/`Ukeire`/`Scaffold`（那是 C 级另一张票）、不碰 `web/` 的 TS 侧、不新增可变状态
