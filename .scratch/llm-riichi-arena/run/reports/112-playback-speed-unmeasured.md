## ① 量法：挂哪个钩子、量点在哪

**量点是「牌桌上那一步真的画出来的那一刻」**（判据 20）。页面里挂一个 `MutationObserver`
（`document.body`，`subtree + childList + characterData + attributes`），每次「这一屏变了」
记一个 `performance.now()`，同时记下**手数计数器**当时的值；一段量完只回一次 node
（票 56 那一课：每手一次 playwright 往返是三千次跨进程调用）。

**手数计数器分两种，各有各的理由**：

| 页 | 计数器 | 为什么 |
| --- | --- | --- |
| 回放（首页那份 Demo，`replayTick`） | 时间轴的 `data-cursor`（帧号） | 一记被认下的定时器 = 一帧，**精确**；一帧 ≈ 一手（那份资产 256 帧 / 252 手，差的是四个开局帧） |
| Live（`?table=1`，四家 bot、零网络，`step`） | 「这一屏变了」的次数 | **牌桌上没有手序可读**：时间轴只有回放才有（`TableState.timeline` 在 Live 那一侧返回 None）。一记被认下的定时器 = 引擎真走一手 = 一次重绘 |

**没有一处绕过世代锁去直接喂 `Ticked`**（票 111 记的那个陷阱）：这一趟从头到尾只点页面上的按钮
（播放 / 暂停 / 倍速 / 座位），手数是**牌桌自己走出来的**。探针自己喂一记 `Ticked` 时那个数
修前修后一模一样——那正是票 111 §⑥ 记下的「空转的收据」。

**为什么不是 `data-turns`**：回放那一页的 `table-timeline-at` 上确有手序，但定时器推的是**帧**，
两者差着开局帧那几下；钉住定时器真正推的那个数才是这一趟要的。

## ③ 断言的形状：为什么是「手/秒」，为什么带子是 [0.70, 1.15]

**票面给的三个候选里，「比例」最稳但有一个致命盲区**：2× 是 1× 的两倍这类比例，
**对「所有档一起翻倍」是瞎的**——而那正是票 78 那个 bug 的形状（世代锁破了，四档一起双倍速，
比例仍旧漂亮）。「N 手的总耗时落在 [a,b]」与「间隔中位数」则各有各的脆：前者对负载敏感，
后者对**两条链错开跑**看不见（见结论 2）。

于是这一趟量的是**手/秒 =（手数差 ÷ 秒数）**，判据是它与设计手秒（1000 ÷ 设计间隔）的比值：

| 边 | 取值 | 它抓什么 | 对负载敏不敏感 |
| --- | --- | --- | --- |
| 上界 | **1.15** | 两条定时器链一起跑（**2.0**）、`Speed.interval` 被改小（减半 = **1.99**） | **不敏感**：负载只会让手数变少，绝不会变多 |
| 下界 | **0.70** | 档位没接上（8× 走成 1× 的间隔 = **0.10**）、间隔被改大（加倍 = **0.50**）、后台节流（**0.06–0.6**） | 敏感——因此它离最坏的实测（20× 降速的 0.824）还留 15%，离最近的坏（0.50）也还有 40% |

**上界那一半是这一票的主角**：它就是抓票 78 那个坑的那一条，而它恰好是对机器负载完全不敏感的那一半
（判据 16：假红比真红危险）。下界虽然敏感，但四种坏至少差三倍，带子摆在中间不会两头不着。

**期望值（600/300/150/60）在闸门里另写一份，故意不从 `Playback.fs` import**：
从编译产物里读回来当然更「单一真源」，可那样一来**把 600 改成 300 时闸门会跟着改口**——
判据清单开头那条说得清楚：断言「两边一样」之前先问「两边是不是同一个实现」。
这份期望是**第三个锚点**；`Playback.fs` 的 `interval` 上补了一句注释指着它（改一处要改两处）。
**档位数量本身有阳性对照**：页面上有几枚 `table-speed-*` 按钮就得与那张表一样长，
加了一档而闸门没跟上时它当场说出来。

## ⑥ 后台节流那件（票面要害 2）：写清 + 做成断言

`setTimeout` 在**后台标签页**里会被 Chrome 压到一秒一记；那会让这条闸门变成噪声源。
这条跑道上不会发生，**两道保险，都实测过**：

1. **playwright 起 chromium 时带着三个关节流的 flag**：`--disable-background-timer-throttling`、
   `--disable-backgrounding-occluded-windows`、`--disable-renderer-backgrounding`
   （权威源是包自己的代码：`playwright-core@1.62.1` 的 `chromiumSwitches`，判据 13）。
2. **无头 chromium 里每个 page 各是各的 target**，互相不会把对方按成后台。

**实测**（临时探针：`ignoreDefaultArgs` 把那三个 flag 摘掉，再在同一个浏览器里开第二页 `bringToFront()`）：

```
① 摘掉三个 flag、只有一页　      setTimeout(60) → 60 60 60 60 60 60 60 60 60 60 60　visibilityState=visible　hasFocus=true
② 摘掉三个 flag、另一页在前台　  setTimeout(60) → 60 60 60 60 60 62 60 60 60 60 60　visibilityState=visible　hasFocus=true
③ playwright 默认、另一页在前台　setTimeout(60) → 60 60 60 60 60 60 60 60 60 60 60　visibilityState=visible　hasFocus=true
```

**光写在注释里不算数**（判据 2），因此闸门自己把它断言了：每量一档顺手读一次
`document.visibilityState`，不是 `visible` 就红并说明「这一档量到的数是噪声」。
将来谁把跑道改成多页并发、或者换一种浏览器，这条闸门会**当场说出来**，而不是默默飘出一堆噪声。

**页面上一个新的数都没印**（票 107）：所有的数只进闸门的 stdout。

## ⑦ 票 111 交回来那 600 ms：量了，维持它的取舍（**没改**）

票 111 留给人的第 2 条：「拨座位那一下会把当前那一记步进间隔重置（换世代的代价）」，
它判「不值得为此加一格状态」，并写着这是可以被推翻的取舍。**先量再说**（判据 14）：

`?table=1` 拨到 1×（代价最大的一档）真播着，在随机相位点一下座位 0 **已经绑着的那一项**
（同一项 = 不换人、不撤票，只走 `roused`），记「点下去 → 下一手落地」：

```
605 / 605 / 605 / 606 / 607 / 608 / 608 / 610 ms（n=8，中位 607）
```

**八次都是整整一记间隔**：拨那一下把在飞的那记扔掉、重新起一记满的。于是那一手比不拨时晚
**0–600 ms（均值 ~300 ms）**，8× 档上同一件事是 0–60 ms。

**维持票 111 的取舍，本票一个字没改**：真要免掉这一截，得在 model 上记住「上一记还剩多久」
（第二份定时器状态），而它换来的是 1× 档偶尔少等 0.3 秒——**代价是形态债，收益是人眼几乎看不见的东西**。
现在这个数有出处了，将来谁要推翻它，推翻的是一个数而不是一句印象。

## ⑧ CI 覆盖不到什么（判据 4，逐条写出来）

| CI 里跑得到 | CI 里**跑不到** |
