## 五、`Houjuu` 那条词条

收在 `CONTEXT.md` 的「规则判定」一节、`Hora（和了）` 紧后面：

- **定义**：自己打出的那张牌被别家荣和。
- **边界一（票面点名的）**：**自摸不算**。mjai 的约定是自摸时 `Target` 等于 `Actor`
  （`Hora.Target` 那条注释），照字面数会给每次自摸的和了者**自己**记一笔放铳。
- **边界二（我核代码时看出来的，顺手写进去了）**：**双响时放铳那家记两笔**——
  两条和了事件各指着它一次，`horaOf` 是一次 fold，两条都进账。
- **执行者**（判据 2，逐条去核过、不是抄写）：

  ```
  src/Janpo.Engine/Scorecard.fs  Scorecard.horaOf   →  SeatTally.HoraTargeted
      | Hora fields when fields.Actor = seat  -> hora + 1, targeted
      | Hora fields when fields.Target = seat -> hora, targeted + 1
  ```

  **「自摸不算」不是一句注释，是匹配次序**：`Actor = seat` 那一支排在前面，
  自摸（`Actor = Target = seat`）因此**走不到**下面那一支。这一句我特意写进了词条——
  报告 133 里的说法是「那一支要显式减掉」，而代码里**没有任何一道减法**；
  照那句话去找执行体的人会找不到，而找不到执行体的不变量正是这个项目最常犯的那类错。

- **守着它的**（我逐条打开核过今天还在、还跑得到）：
  `ScorecardTests.自摸只记和了，不给自己记一笔放铳`、
  `ScorecardTests.双响时两家各记各的和了，点炮那家记两笔放铳`、
  `verify-scorecard.mjs` 的第三锚点（`tallyFromPaifu` 在 node 里照同一条规则重数一遍，
  这一趟真跑了 28 格 / 4 行 × 7 列，牌谱里 4 条 hora 事件、464 条决策记录）。

**授权只到这一个词条，我严格守住了**：别的该收的词没有自己收
（`HoraTargeted` 该不该跟着改名写进了 DECISIONS 145-2 等下一次授权）。

  读它读不出谁是起家。
- ∴ 结论是**看不出来**。票面说「看不出也别在这一票补」，我照做了。

**我的判断**（供裁）：记分卡去掉风之后这件事**没有变得更糟**——原来那一列写的是末局自风，

不该补进记分卡：记分卡的四行是四个选手，不是四个方位。
