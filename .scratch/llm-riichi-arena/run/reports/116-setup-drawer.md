## 2. 票面里有一条自相矛盾，我改了做法并说明

票面写「收成一枚**弹出层**」，且边界里要「**弹出层不许盖住牌桌**（原型里抽屉宽度取成正好等于
牌桌左右那条边距）」。

**那条边距是票 117 的固定舞台才有的。** 116 这一步页面还是竖排长卷、牌桌满宽，于是：

- 浮层式抽屉 ⇒ **必然**盖住牌桌（牌桌占满宽，没有边距可躲）；
- 内联折叠 ⇒ **永远不可能**盖住 ⇒ 那条断言变成同义反复（判据 60 那个坑）。

∴ 这一票用**内联折叠**（`Html.details`，正是票 83 自己给 `panelNote` 立的那副写法），
浮层抽屉留到 117 有了边距再做。**「不盖牌桌」那条断言我没写**——它在这一步只能是假绿。
换成真正要的那件事：**落地那一眼牌桌顶边 ≤ 420 px**（§4 ①）。

顺带：折叠用 `<details>` 而不是往 `TableModel` 里加一个 flag，因此
**不进 model、不添消息、不碰 localStorage**。代价是折叠状态不持久（刷新回到收起），
同票 83 §9 待审 ② 那笔账，仍不还。

## 3. 摘要行写值，不写「配桌」两个字

票面点名的那条判据（同票 83 §2.1 的形状：只画一枚点会让人看得出「有东西」却看不出「是什么」）。
摘要行摆的是**拨到的那一份**，与里面那三排按钮一致；因此得把 `rulesPending` 也带出来——
拨好了还没按「重开」时，摘要上那几个值并不是这一桌真在按的（同 `table-rules` 那一格的判据），
此时摘要染朱并加「（拨好了，未重开）」。

## 7. 三个坑，都是我自己先踩的

### 7.1 `content-visibility: hidden` —— 一条永远不会触发的守卫

我先给 `seatShape`（`verify-seats`）加了一条守卫，防的是这件真事：
**四席在配桌里，收着时「四席同屏」那条会空过**（`top < 0` 与 `bottom > viewport` 两边都不成立）。

头一版守卫量的是「矩形高度是不是 0」。**它永远不会触发**：
Chrome 新版 `<details>` 收起用的是 `content-visibility: hidden` 而不是 `display: none`，
子元素**点不到、却仍有布局**——实测收起时那四行照旧 `h=37`、`top` 不变。

改用 `row.checkVisibility()`（同时覆盖 `display:none` / `visibility:hidden` / `content-visibility:hidden`），
再验：量密度前偷偷收起配桌 ⇒
`Error: 座位那几行没渲染出来：座位 0、1、2、3——配桌大概还收着（票 116）。这一屏量不出密度，不许当成「都在同一屏里」。`

### 7.2 还原了源码却没重建 —— 差点误读一个数

破坏实验 C 改的是 CSS。我还原了 `styles.css`，**没重新构建**，于是 `dist/` 里还留着
那句 `content-visibility: visible !important`。接着 `verify-home` 报牌桌顶边 **847 px**——
我差一步就把它当成「收起没生效」去追。

**`previewUrl` 服的是构建产物、`devUrl` 是热的**（`verify-board`/`home`/`setup` 走前者，
`verify-seats`/`export` 走后者）。`ci-web.sh` 第 89 行本来就会 `vite build`；
本地单跑必须自己补这一步，破坏实验的还原也必须**连带重建**。

### 7.3 一行会说谎的日志

`drawerProblems` 头一版的 `console.log` 里硬写着「默认收着」，
于是拿写死 `open` 的版本去试时它照旧印「默认收着」。**印的得是量到的，不是期望的**：
改成 `一进页面 open=${shut.open}`。
