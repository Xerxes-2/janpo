# 票 98：抢杠那一轮从来没被抽到过 —— 判决、牌山与那十条红

**结论先说五句。**

1. **判决：摊得出牌山，但今天挂不进取值域表 —— 走锚点那条路。**
   两条摊好牌山的抢杠轨迹都跑通了（加杠抢杠 9 步、国士抢暗杠 4 步，都在固件里），
   但把它挂进 `GameStateArbitraries.Traces` 会**当场把七条现成的属性按红**（两条轨迹合起来十条）。
   那些红是真发现，不是我的锅，也不许顺手改（判据 5 / 派工单第五条）。因此这一票只做零代价的那一半：
   **具名 `[<Fact>]` 锚点 + 模块头写明「随机属性到不了这里」**（判据 4）。
2. **那条属性的随机部分今天在守什么：什么也没守。**
   `KanProperties.抢杠那一轮只有荣和与「过」，宣言杠的那家不在被问之列` 的三个分支里，
   `ResponseCause.Dahai` 与 `AwaitingDahai` / `Ended` 都直接 `true`，唯一做事的那一支采样命中 0 次
   ——**它等价于 `fun _ -> true`**。实证：把那一支的断言改成必然为假（`choice.Seat = phase.Target`），
   `dotnet test` 里那条属性**照样绿**（§1.2 有原文）。判据 3 的第四个案例，也是最干净的一个。
3. **就算挂上去也买不到「每趟」**：抢杠局面在那条九步轨迹里的密度是 **11.1%**（9 步里 1 步），
   给到权重 2 只有一趟 **47.1%** 的开口率；要一趟 99% 得让它**独占权重表的 40.5%**
   （权重 22 / 合计 55）。而锚点是每趟 **100%**，代价是 0。
4. **新的红是真发现，单独报**（§4）：十条红分四类，最值钱的是第四类——
   **加杠一宣言，掩蔽流 fold 出来的观测就把碰升成了杠，而引擎要等杠成立**；
   被抢之后那个杠永远不成立，**观测那份却一直显示它成立**。这一条会一路影响到浏览器里的回放。
5. **本票一条断言没放宽、一条属性的语义没动**：改动只有「新增固件 + 新增一条 `[<Fact>]` 锚点 +
   新增一份探针」。引擎全量 20 趟 × 751 条全绿（改前 750 + 本票这条锚点），`./scripts/ci.sh` 全绿。

### 1.1 那一支压着几条断言、今天由谁守

另有**一条别族的属性也压着同一个相位**（不是这一票的地盘，只描述不编号，判据 17）：
`GameStateProperties.等着打牌的那家 14 张…` 里 `ResponseCause.Kan _ -> Some phase.Target` 那一支

**所以「谁在守」的答案是：具名用例与真牌谱对拍在守引擎的行为，属性在空转。**

### 1.3 为什么随机采样到不了

不是「采样太稀」，是**引擎只在真有人抢得了时才进那个响应阶段**（`GameState.fs` 的 `responsesTo`：
空表就当场成立，连响应阶段都不建）。要造出一个抢杠局面得**三件事同时成立**：

1. 有人把碰升成加杠（或暗杠，且规则集允许国士抢暗杠）；
2. 另一家正好听那张；
3. 那家不振听、且和了时有役。

取值域里十三条轨迹没有一条同时满足：`kanSeeking` 从不碰（碰不进它的偏好表），`nakiSeeking` 从不杠也从不和，
随机选手三件事撞一起的概率低到 400 颗种子 × 25.3 万个局面里一次都没有。

**这条牌山的机关是「无役」**（牌理全由引擎复核，判据 19）：

```
座位 2 的配牌 1m 2m 3m 4m 5m 6m 7p 8p 9p 4s 6s 9m 9m：向听 0，听 5s
Oya 第 1 巡打出 5s 那一手，座位 2：和不了（无役，不能和）
被问的座位：[1]
抢杠那一轮，座位 2：抢杠
```

**为什么非得无役不可**：抢杠要先有人碰、再摸进第四张，因此那张 5s 必然先被打出来一次，
而被抢的那家听的就是它——**它会在第 1 巡就被问荣和，见和就和的选手当场收场，一个杠都摸不到**
（`kakanScript` 配见和就和的选手正是这样，三步就完）。让它荣和时一个役都没有
（嵌张听不成平和、带 1m/9m/9p 不成断幺九，三色 / 一气 / 混全带一个不成），
`无役不可和` 就把第 1 巡那一次拦住了：**它压根不被问**（上面第三行：被问的只有座位 1），
因此连见逃都算不上，也不落同巡振听；到抢杠那一轮，**抢杠本身就是役**。

顺带：Oya 的配牌是九种幺九牌（第 0 步的 `九种九牌(0)`），座位 1 除两张 5s 外全是字牌对子
（它手切出去谁也碰不走、吃不了），座位 3 一手孤张——**九步里没有一步是靠运气的**。

## 3. 挂进取值域表买得到什么（探针算的，不是估的）

一个样本命中的概率 `p = (w / (33 + w)) × 密度`，一趟（100 个样本）至少开一次口 `1 − (1 − p)^100`：

| 权重 | 采样 p | 一趟开口率 |
| ---: | ---: | ---: |
| 1 | 0.3268% | 27.916% |
| 2 | 0.6349% | **47.109%** |
| 4 | 1.2012% | 70.135% |
| 8 | 2.1680% | 88.829% |
| 16 | 3.6281% | 97.517% |

```
抢杠局面在这条轨迹里的密度 11.1%（9 步里 1 步）
要一趟 99% 开口，需要 p ≥ 4.5007%，即这条轨迹独占权重表的 40.5%（权重 22 / 合计 55）
```

**11.1% 就是这类轨迹的天花板**：要加杠得先碰、再等一整圈回到自己摸牌，最短就是
「摸切 → 碰 → 手切 → 三家各一手 → 加杠 → 抢 → 终局」这九步，一条轨迹里只可能有一个抢杠局面。

还有一笔账要记：**加权重就是从别人碗里舀**（97 立的规矩）。抢杠这条轨迹喂不到任何一条立直局面，
因此哪怕只加权重 1，`riichi-naki` / `riichi-dahai` / `riichi-declared` / `riichi-response` /
`riichi-ankan-offered` / `ippatsu` 六族都会掉——要不掉就得把三条立直轨迹一起抬，
连锁下来权重表得从 33 涨到 39 上下，固定轨迹的份额从 1/3 涨到 46%。
**买到的是一趟 47%、九个锁死的局面；卖掉的是随机牌山的份额（66.7% → 58%），而新 bug 只从随机牌山里出。**

十条红分四类，逐类查了根因：

### 第一类：属性对「被抢的杠」本来就不成立，作者自己写过（1 条）

`KanProperties.杠数与新宝牌…`：它把事件流里的 `Kakan` 当成立的杠数，而**被抢的那个杠不成立**，
`GameState.kanCount` 是 0，两边对不上。同一个文件里 `pendingKanDora` 的注释白纸黑字写着这条前提：

> 前提与 `kanEvents` 同一条：被抢的那个杠不算成立（那时事件数与 `kanCount` 就对不上了，下面那条合取先报）。

**也就是说：这条属性一直是错的，只是取值域到不了那里所以没人知道。** 判据 3 的教科书形态。
（本票的锚点因此把它排在外面，并在代码里写明为什么——判据 4，不是把它调松。）

### 第二类：终局那一手的张数（1 条）

`GameStateProperties.等着打牌的那家 14 张…`：抢杠收场时**宣言杠的那家手里仍握着刚摸进的那张**
（14 张，副露仍是碰），而它既不是「等着打牌的那家」也不是自摸和了的那家 —— 属性要求它 13 张。
引擎是对的（那张牌确实还在手里，KanTests 也按住了这一点），属性缺了「抢杠收尾」这一种终局形态。

### 第三类：一发（1 条，只在「抢的那家先立直」时出现）

`RiichiProperties.一发只可能亮在立直成立的那家头上，任何鸣牌之后全场都没有一发`：
它的 `lastIsNaki` 把 **`Kakan` 事件**算作鸣牌，于是在「杠宣言了、还没成立」那一刻就要求全场没有一发。
但引擎给出的和了是 **立直 + 一发 + 抢杠（3 番 40 符 5200 点）**，而这是对的——
**被抢的杠没有发生，一发不该被它打断**。属性的过近似在抢杠局面上翻车。

### 第四类：观测 / 决策包 / 掩蔽流 —— fold 与引擎在「杠还没成立」这一段分了家（7 条）

最值钱的一类。抢杠那一步逐字段对下来（探针第四之二节，用的是 `ObservationFixtures.mismatches`
——**那份判据拿引擎的权威状态当锚点**，因此对不上就只可能是 fold 那侧错了）：

```
== 加杠抢杠：观测 vs 引擎的权威状态 ==
 7 座位 0 对不上：others.1.tehai_count、others.1.naki
 7 座位 1 对不上：self.tehai、self.tsumo、self.naki
 7 座位 2 对不上：others.1.tehai_count、others.1.naki
 7 座位 3 对不上：others.1.tehai_count、others.1.naki
   引擎那侧：0:13 张[] 1:11 张[Pon] 2:13 张[] 3:13 张[]
 8 座位 0 对不上：others.1.tehai_count、others.1.naki
 8 座位 1 对不上：self.tehai、self.tsumo、self.naki
 8 座位 2 对不上：others.1.tehai_count、others.1.naki
 8 座位 3 对不上：others.1.tehai_count、others.1.naki
   引擎那侧：0:13 张[] 1:11 张[Pon] 2:13 张[] 3:13 张[]
```

引擎那侧：座位 1 手里 11 张 + 刚摸进的 5s，副露仍是 **Pon**；fold 那侧：10 张，副露已经是 **Kakan**。
**第 8 步是终局**（抢杠已成立、那个杠永远不会成立了），fold 那份仍旧显示着那个杠。

**根因**：`kakan` 事件一播出去，fold 出来的观测就把那组碰**原地升成了杠**并把那张牌从手里拿走；
引擎则要等杠成立才动（宣言不改局面，被抢时无需回滚，`ResponseCause.Kan` 的注释写着）。
于是抢杠那一轮两边差一张牌、差一个副露种类；**被抢之后那个杠永远不成立，而观测那份再也没回滚**。

这条不只是测试的事：**座席看到的历史就是这份 fold**（`Observation` 是掩蔽事件流的 fold，票 29a），
浏览器里的回放与 Agent 收到的观测都走它。真牌谱里抢杠 22 局（`tests/fixtures/paifu/README.md`），
一旦回放到那一局，牌桌上会显示一个**从未成立的杠**。

暗杠那一条另有两条红（`Masked/不出现他家暗牌`、`Obs/序列化不漏暗牌`）：国士抢暗杠时那四张 7z
**必须**亮给别家看（不然没法决定抢不抢），而它们在引擎里仍是暗牌——「掩蔽流里不出现他家暗牌」
这条不变量在那个窗口里本来就不成立。这一条要的是把「宣言中的暗杠」在术语上认成公开信息，
不是把断言调松。

**四类里第一、二、三类是断言要改，第四类多半要动 `src/Janpo.Engine/Observation.fs`。两者都出了这一票的边界**
（不碰 `src/**`、不改别人的断言），因此**只报不改**，建议调度器各立一票（§7）。

### 5.2 锚点长什么样、红过两次

`KanProperties.摊好牌山的两条抢杠轨迹：抢杠那一轮真的到过，杠的不变量逐步都成立`：

- **先自证覆盖**：两条轨迹各至少一个抢杠局面，成因分别是 `Kakan` 与 `Ankan`，
