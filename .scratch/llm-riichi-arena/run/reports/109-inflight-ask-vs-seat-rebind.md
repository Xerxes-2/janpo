## ② 口径那一判：开局作废**算**花掉的钱

**这是这一票真正要想的事，理由摆在这里，供人推翻。**

### 判「算」的三条理由

1. **`Table.usage` 那句话已经定了**：票 79 立、票 108 写进 `Table.usage` 的注释里——
   **账单报的是花掉的总额，不是落了子的那几手的总额**。「开下一局」不改变
   「provider 被调过、token 被计过费」这个事实，因此它不该改变账单。
2. **不这么定，账单就变成一个说不清的数**。同一次问话，从被问出去到它的钱算不算数，
   今天有三条路会先发现它已经没用了：`drain` 的剪枝、拨座位的撤票、开下一局的清表。
   三条路谁先跑到，取决于**回执什么时候回来、人什么时候点那一下**——**都是人看不见的时序**。
   要是其中一条不记账，那么「这一桌花了多少」就成了一个**与时序有关的随机数**。
3. **它与「不留决策记录」是配套的一对，不冲突**（票 108 立的那条）：
   「这一手没有发生」说的是**牌桌与牌谱**，「这一笔花掉了」说的是**账单**。
   两句都是实话，而说得出前一句的记录是 `VoidedAsk` 而不是 `DecisionRecord`。

### 判「不算」要付的代价（我没选这条，但把它写全）

若判「不算」，账单那一行到此刻的口径就得改写成：
**「这一桌花掉的钱里，被开下一局清掉的那几笔不算」**——用户看到的数会比 provider 的账单少那几笔，
而且**少多少他没法自己核**（页面上没有任何东西说得出「有几笔被清掉了」）。
更糟的是它**不稳定**：同一局同一手，回执早回来 200 ms 就进账、晚回来 200 ms 就不进账。

### 落地之后账对不对得起那句话

- `Table.usage` = 决策记录 + **全部**作废的问话（三种起因一视同仁），**开局清表不许让它变小**。
  用例里带着真实数字：那份假回执写死的是 `Input 812 / CacheRead 1344` → **2156 tok**，
  断言 `Assert.Equal(2156, Usage.promptTokens (Table.usage (tableOf late)))`，
  外加一条 `>=` 直接钉「开下一局把账单弄小了」这句话。
- 修前那一刻的实测（把 `turned` 撤掉重跑）：
  ```
  【现场】开下一局之后：在飞 0 份、作废 0 笔；那 2156 tok 的回执回来之后：账单 0 tok、作废 0 笔、决策记录 0 条
  ```
  **钱整笔蒸发**，而且蒸发得一声不响——`Answered` 那条 `creditVoid` 找不到可补的记录，恰好是个空操作。

## ④ 修法：三条路一段账，起因分成三个 case

### 4.1 `VoidCause`：作废的**起因**从一句存下来的中文变成三个 case

`VoidedAsk.Reason: string` → `VoidedAsk.Cause: VoidCause`，中文那句由 `VoidedAsk.reason` 现算：

| case | 谁触发 | 它是什么 |
| --- | --- | --- |
| `Expired` | `drain` 顶上的 `swept`（票 92 / 108） | **兜底**：牌桌已经绕过那份问话往前走了，而没有任何一处语义说过要撤它 |
| `Rebound of taker` | `SeatBound` 换了人（票 109） | **语义**：这一席交给了别人，旧回执是上一份配置答的 |
| `NextKyoku` | `KyokuAdvanced`（票 109） | **语义**：这一局连同它在飞的那几次问话一起翻篇 |

三条理由分成三个 case 而不是塞进同一句中文里，是判据 12 那条（拒绝理由各有各的 case）：
它们的起因、能不能避免、以及「这一席还该不该被重新问」都不一样，**而阴性对照要数的正是其中一种**
（`Table.revoked`）——混成一句中文的话，那个数就只能靠字符串匹配。

**存起因而不存那句话**：措辞是算得出来的，存一份现成的，改措辞的人就得记得同时改历史里那几条。

### 4.2 三条路共用 `harvested`

```fsharp
let private harvested (cause: VoidCause) (doomed: DecisionPackage -> bool) (table: Table) (live: LiveTable)
```

- `swept`：`doomed = 不是当下的那几份`，`cause = Expired`
- `rebound`：`doomed = 这一席的那几份`，`cause = Rebound taker`
- `turned`：`doomed = 全部`，`cause = NextKyoku`

各写一遍的代价是：「回执已经到了的那几份当场就知道花了多少」与「强 AI 基线那几份没有账单」
这两件事要在三处各记得一次（Duplicated Code + Data Clumps，票 108 的 review 已经在这一段上栽过一次）。

### 4.3 撤票的判据：**换了人**才撤

```fsharp
let before = (SeatingPlan.bindingAt seat live.Seating).Choice
…
if before = choice then live else rebound seat (taker seat seating) live
```

**拨到它已经绑着的那一项不算换人**：面板上点一下当前那一项同样发一条 `SeatBound`，
而那一下什么都没改——**误撤一票就是白花一次钱、白等一趟**。阴性对照量的就是这一条（§⑤）。

**「凭什么拨给别的模型时，旧回执不算这一席的答复」**——三句：

1. **它是另一份配置答的**：provider / 模型 / key / baseUrl / 超时都可能换了，
   人格与模板也可能换了（那两样在可缓存前缀里）。用例把这件事钉在值上：
   两份档案的 `Provider` / `Model` / `ApiKey` 三格全都不同，撤票之后那一席被重新问出去，
   断言 `fresh.Config.Model = rival.Model`、`fresh.Config.Provider = rival.Provider`。
2. **牌谱会把那一手记在新那一位名下**：`start_game` 那一列 `names` 是**导出 / 分享那一刻**
   由这一桌此刻的配桌推导出来的（`Table.events` → `Roster.names`，不是逐手录下来的），
   于是旧回执落下去的那一手就成了「谨慎的老李打的」——而它是凶狠的老张答的。
   **不撤票的话，这句假话连一处可以对质的地方都没有。**
3. **它连「这一席此刻是不是模型」都不保证**：拨回 bot、拨给真人、拨给强 AI 基线时，
   这一席根本没有「模型的答复」这回事。三种一视同仁地撤，判据只有一条：**这一席换了人**。

### 4.4 撤票是语义、剪枝是兜底，两个都留着

`swept` 一个字都没删。它守的是**将来**新长出来的绕行路，以及 `Table.Fault` 之后
`Table.pendings` 变空那一种（那时在飞的全都不是当下的）。
**代价**：它今天的执行次数是 0（§⑦ 第 1 条，交回调度器）。

## ⑤ 阴性对照：撤票 0 次（判据 20 的量点）

用例 `` 阴性对照：没换人的一整场，撤票 0 次 ``：

- 四席全模型、**打完一整场**（正序与倒序各一场），每次挑最能搅乱局面的那一条动作；
- **每一次回执落下去之前，都在在飞的那一席上按一下它已经绑着的那一项**（`SeatBound(seat, 同一个 choice)`）
  ——那是面板上真点得到的一下；
- **量点停在 `Table.result` 有值之后**（判据 20），断言 `Table.revoked table = []` 且 `table.Voided = []`，
  并且账单**恰好等于那几条决策记录的合计**（没有第二笔来源）。

**三条阳性对照防空转**（判据 3）：这一场真打到了终局精算、真遇到过多席同时在飞（`most >= 2`）、
**那几下真的在问话在飞时戳出去了**（`pokes > 0`）。第三条尤其重要：不戳的话这条阴性对照
就退化成票 108 那一条的复读。

## ⑥ 跨局补账：票号会不会撞、补到哪一局的账上

**两个问题各有一句确定的答案，各配一条用例。**

### 票号

`LiveTable.Ticket` 是**全局递增**的一本账（四席共用），**`KyokuAdvanced` 一个字都不动它**
（`Restarted` 也不动，但那时整张牌桌连同 `Voided` 一起换新，旧回执在新桌上找不到可补的记录，
`creditVoid` 恰好是个空操作）。因此**跨局的票号不可能撞**。
用例 `` 跨局补账：两局各撤一票，回执倒序回来也各归各的账 `` 把它钉死：

- 第一局造一只鬼（撤票），**把第一局真的打完**，`KyokuAdvanced` 开第二局，第二局再造一只鬼；
- 断言 `ghost2.Ticket > ghost1.Ticket`（撞号的话这一句当场红）；
- **回执倒序回来**（后一票先回、先一票后回，并发最坏的错位到达）：
  两笔各自拿到自己那一份 `Usage`，`Table.usage = billed + billed`、`paidVoids = 2`、
  `Table.revoked = 2 笔`、`Decisions` 仍旧是空的（两手都没发生）。

### 补到哪一局的账上

**`Table.Voided` 是一本跨局累计的流水账，不按局分册**；一笔作废落在哪一局，由 `VoidedAsk.Turn` 说了算
——它是**作废那一刻的 `Table.Turns`**，而 `Table.Turns` 跨局累计、`Table.nextKyoku` 不把它归零。
于是**一笔作废永远记在它真的发生的那一刻上**，晚回来的 token 只是往那一格里填个数，
不会因为「回执是在第二局回来的」就跑到第二局去。用例逐条断言：

```fsharp
Assert.True(one.Turn < opened.Turns, "第一局那一笔该记在第一局里")
Assert.True(two.Turn >= opened.Turns, "第二局那一笔该记在第二局里")
```

（`opened.Turns` 是第二局开局那一刻的手序号。）

**`loop.ts` 没碰——而这一票本来最有理由碰它，所以理由写全**（票面第 6 条，与票 95 的记法闸门 /
票 107 的逐数溯源都不相干，是**账**的问题）：

> **「撤票」要不要真去 abort 那趟 fetch？** 三种做法与代价：
>
> | 做法 | 账怎么记 | 代价 |
> | --- | --- | --- |
> | **A：不 abort（本票选的）** | 那一趟照常跑完、照常报用量，回执回来在 `creditVoid` 里补账，**一分钱不漏** | 白等一趟（不占墙钟：牌桌不等它），白花一次钱 |
> | B：abort，账记「已发出但被取消」 | 得**新立一种记账**：token 数**永远不知道**（`Usage = None` 永久），页面上那一行从此有一类花销报不出数 | provider 侧多半**照样计费**（请求已经进了它的队列），于是账单比真实少一截——正是票 108 修掉的那个病换个地方犯 |
> | C：abort，账不记 | 无 | 与 B 同病，且更彻底：钱花得不明不白 |
>
> **判 A 的理由**：`Table.usage` 报的是**花掉的总额**，而 abort 之后**我们就再也不知道那个数了**——
> 「已发出但被取消」这一笔要不要留一格，是同一个问题的另一半，而它的答案在 provider 那边，不在我们这边。
> **省下来的那点钱是假的**（provider 已经在算了），**丢掉的账是真的**。
> 要真做 B，先得量一次「abort 之后 provider 到底计不计费」——那要真 key，不在 CI 里（判据 14：先量再判因果）。

### review 两轴（fixed point `2cfabdf0` = 集成头，两轴顺序各跑一遍）

**Standards**（`docs/agents/fsharp-style.md` + Fowler 坏味道基线 + 判据 9 / 12）。改掉的五处：

1. **三段几乎一样的记账 fold** → 一段 `harvested`（Duplicated Code）：第一版是
   `swept` 一份、`rebound` 一份、`turned` 一份，三份里各有一次「回执到了就当场记账单」
   与「基线那几份没有账单」——那两件事迟早在其中一处被忘掉。
2. **存下来的那句中文** → 起因的三个 case + 一个 `reason` 函数（判据 12 + 「算得出来的别存」）。
   顺带让阴性对照有了一个数得清的东西（`Table.revoked`），而不是拿字符串去匹配。
3. **`Table.revoked` 用穷举 match 而不是 `| _ -> false`**：`VoidCause` 将来加一种时，
   编译器会把这一处指出来——否则新起因会**默默地不算撤票**，而阴性对照仍旧是绿的。
4. **两处三层嵌套拆成管道**（fsharp-style 规则 3，自己写出来的）：
   `List.length (Table.revoked (tableOf model))` → `model |> tableOf |> Table.revoked |> List.length`；
   `Usage.promptTokens (Table.usage (tableOf late))` → 局部起个名字的 `paid`。
5. **`turned` 那个名字往注释里钉了一句**（Mysterious Name）：三个变换器各取自它的起因
   ——`swept`（剪）/ `rebound`（换人）/ `turned`（**翻篇**）。

① `taker` 只有一个调用点（看着像 Speculative Generality）：留着的理由是它把

② `turned` 的 `doomed = fun _ -> true` 看着像退化：这正是它要说的话——**开下一局就是全部翻篇**。
③ `VoidCause.Rebound of taker: string` 看着像 Primitive Obsession：考过改成 `SeatChoice`，

④ 用例里那个 `let pokes = ref 0`（fsharp-style 规则 5 的邻居）：它只在用例里、只为了
**数阴性对照真的戳出去几下**（判据 3 的执行证据）；要避开它得把计数器穿过 `playGame` 的 fold，
而那会把票 108 那个助手改得更多。`check-style.sh` 的 `let mutable` 预算不管 `ref`，且全绿。

（`Decisions` / `Voided`），**本票一个新字段都没加**（`VoidedAsk` 里的 `Reason` 还换成了算得出来的
