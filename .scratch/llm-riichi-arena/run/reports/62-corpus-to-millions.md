## 一、先量：那 6ms/局 拆开是什么

调度器的 6.1ms/局是 `dotnet test --filter PaifuDifferentialTests` 的墙钟（5.5s / 908 局），
含测试宿主的开销。**管道本身**（前任的 `paifu-cost.fsx`，87 场固件、预热 + 3 趟取最小）：

| 段 | 一趟做几次 | ms/局 | 占比 |
|---|---|---|---|
| mjson 解析 | 每行一次 | 0.355 | 8.3% |
| 天凤 JSON 解析 | 每场一次 | 0.047 | 1.1% |
| 牌山重建（`Wall.ofOrdered`） | 每局一次 | 0.207 | 4.8% |
| **引擎重放（逐事件 `step`）** | **每动作一次** | **3.379** | **78.9%** |
| 比对（事件流 + oracle） | 每局一次 | 0.288 | 6.7% |
| 其余（含读盘） | 每场一次 | 0.004 | 0.1% |
| 合计 | | **4.281** | |

「引擎重放」还得再拆一层才有资格下因果结论（判据 14）。在工作区**临时**给 `PaifuReplay`
加计时器、Release 重编、量完就撤（没提交），量到的是真编译产物：

| 重放内部 | ms/局 | 占重放 |
|---|---|---|
| **`GameState.step`**（61 次/局，约 37µs/次） | 2.278 | **93.0%** |
| 牌山重建 | 0.074 | 3.0% |
| 事件流比对 | 0.053 | 2.2% |
| 驱动器其余（队列、对齐） | 0.039 | 1.6% |
| `GameState.horaOf` + `GameState.events` | 0.006 | 0.2% |

**结论：热点是引擎本体，不在本票能动的任何地方**（对拍票不改引擎；`GameState.fs` 还是票 59 的地盘）。
测试侧驱动器只占 ~2%，优化它是镀金。**能把整年包变成 routine 的改动只有一件事：别解包、分片跑。**

## 二、流式扩语料：改了什么、跑多快

新增三件（都不含规则逻辑，对拍仍走 `PaifuDifferential.game` 这一个 CI 也在跑的 API）：

| 文件 | 做的事 |
|---|---|
| `scripts/paifu/zip-index.py` | 列出年度包全部成员的读取坐标（名字、本地头偏移、压缩尺寸；zipfile 管 Zip64），索引放 `/tmp` |
| `scripts/fsi/paifu-scan-zip.fsx` | **流式**扫描：按索引 `Seek` + `DeflateStream` 逐场解压到内存，处理完即丢；每 500 场一条 `CK` 断点（可续，断点校验末场 id）；D/S 差异行**即时落盘**；逐局覆盖只累计不落盘 |
| `scripts/paifu/summarize-scan.py` | 合并分片、断点重做的重复行去重、差异场按签名归类、吐 `suspects.txt`（oracle 只对它取） |
| `scripts/paifu/extract-from-zip.py` | 按 id 从包里提取牌谱（oracle 阶段与留证据用） |

为什么不直接 `ZipArchive`：它把中央目录整个实体化，25 万成员一个进程就是几百 MB，
索引 + 裸 `FileStream` 每进程几十 MB。为什么断点记「已处理数 + 末场 id」而不是全量 id 日志：
分片按排序后行号取模，顺序确定，计数即断点；全量 id 日志一年包要 ~10MB×n 且没多买到什么
（净增长判据优先）。中断恢复实测过：从 500 场断点接着跑，终态计数与不中断的那趟逐字段相同。

**改后每局开销（生产数字，不是微基准）**：2025 整年包 4 分片 `nice -n 19` 各 29.1–29.7 分钟，
1,893,891 局 / (4×~1760s) ≈ **3.7ms/局/进程**，合计 **2.0 核时**。
**整年包从「50 小时单核」的票面担忧变成 30 分钟墙钟（4 进程）**——不必动 RUNBOOK 的进程上限，
也不必动引擎。剩下 17 个包（约 11.4GB、外推 ~240 万场）全扫一遍约 26 核时 ≈ 6.5 小时墙钟（4 进程），
是 routine 级别。

**先修正票面一个数**（判据 13：查当下事实问权威源）：「任意一个整年包约 190–290 万场」算错了
一个数量级——845MB × 10.4 / 47KB ≈ 18.7 万场才是那道算式的结果。**实测 2025.zip = 178,888 场**。
「百万场」要全部 18 个包（约 240 万场）；「百万局」一个整年包就到了（189 万局）。

**验证**：先拿 2026.zip（票 57 的已知答案）流式重扫——12,188 场 / 129,179 局 / 和了 109,592 /
终局点数对拍 116,991，与 57 报告逐项相同；免 oracle 差异 112 处 / 58 局，签名归类
**28 / 24 / 6，与 57 的 A / B / D 三类的局数完全一致**，未归类 0。管道与归类器都对得上已知答案。

### A 的钱错变种（13 场，oracle 确认）

57 写过：「全量语料里『明杠欠着 + 再杠 + 当场岭上开花』出现 0 次，所以这 28 处目前全是顺序差异……
换一张就是钱错」。**2025 里它出现了 13 次**：欠账的指示牌在第二次杠成立时翻出（天凤），
紧跟的岭上自摸把它数进番里；引擎把欠账攒到打牌那一刻，这一局没有打牌，于是少数：

```
2025010623gm-00a9-0000-24148b93 第 3 局：番（含宝牌）天凤 12，引擎 8；
                                表宝牌 9 vs 5；和了点 24000 vs 16000
2025102612gm-00a9-0000-59acbabc 第 2 局：番 8 vs 4；表宝牌 4 vs 0；和了点 16000 vs 8000
```

修法与 57 第三节 A 同一条（`completeKan` 在明杠那支补摸岭上牌之前 flush 欠账）——
**这 13 场是那张票最硬的验收证据**，修完重扫应当归零。

### E. 立直后的暗杠：D-8 的第三条判据被天凤 20 次实证否掉（新，只报）

`RiichiState.allowsAnkan`（09-G / 裁决 D-8）要求三条全过，第三条是「立直时的手牌在**每一种**
和了读法里都把那个牌种当暗刻用」。2025 里**20 局**天凤让立直家暗杠了、我们拒绝
（20 局全核验过：暗杠前都有 `reach_accepted`）。逐场看的第一例：

```
2025010516gm-00a9-0000-63ff5735 第 11 局 座位 0
  立直手：3m4m5m 7m9m | 3s3s3s 4s5s6s 6s6s，听 8m
  摸进第 4 张 3s 暗杠 → 杠前杠后都只听 8m（②过）
  但和 8m 的读法里索子可读作 3s3s + 3s4s5s + 6s6s6s——那读法里 3s 不是暗刻，③不过 → 引擎拒
```

即天凤的实际口径是「**听不变就许**」，不附加「每种读法都是暗刻」。D-8 当时的反例
（`123m 66m 333s 44s 555s` 摸 3s）证明③不是摆设，但它证明的是「③会拦下一些杠」，
不是「天凤也这么拦」——现在有 20 局说天凤不拦。影响不止顺序：这 20 局重放全部中止，
后续钱流全对不上。**要改的是 `RiichiState.allowsAnkan` 去掉/放宽③（连同它的单元测试），
属于改规则判定，本票不动。** 复现：`suspects-2025` 里 20 场都在，
`JANPO_PAIFU_DIR=/home/xerxes2/janpo-corpus/suspects-2025` 一跑就红。

### F. 同巡振听没被自家鸣牌解除（新，只报，4 场）

```
2025012911gm-00a9-0000-7cadedf9 第 2 局 座位 2（吃之前听 6s/9s，河里过了 9s×2、6s 见逃）
  chi 6s（5s7s）→ 打 8s → 新听 2s/5s（2s/5s 从没被放过）
  下家打 2s，天凤允许荣和（断幺九满贯 8000）；引擎报「振听（同巡），不能荣和」
```

同巡振听在天凤是**到自家下一次摸打为止**——鸣牌打出一手同样解除；引擎只在自家摸牌时清，
鸣牌那条路不清，而且吃碰之后听牌都换了。4 场里 3 场表现为「引擎没进响应阶段」、
1 场是显式拒绝，钱流差到 ±8300。**要动 `PlayerState.refreshFuriten`/鸣牌路径，本票不动。**
（与票 13 修过的「立直宣言牌换听不解振听」是同一个器官的另一条边。）

## 五、oracle 的账

| | 票 57（盲取） | 本票（先筛后取） |
|---|---|---|
| 取了多少 | 1,041 场 / 28 分钟 | **58 场 / 2 分钟** |
| 判定了什么 | 全部役 / 符 / 番对拍 | 43 场未归类的定性 + 3 个已知类各 5 场的年度复核 |

如果盲取 2025 的同比例样本（~1.5 万场）要 6.4 小时——**先筛后取把对天凤的打扰缩了两个数量级**，
而且每一次都答了一个具体问题。代价是：整年包的役 / 符逐项对拍只盖住这 58 场，
役种覆盖用引擎读法普查代替（上表）；这是设计好的取舍（票面第三节），不是遗漏。
