## 3. 两档对照（同一种子 2088、同一座位 1、同一模型）

### 3.1 整场

| | **Bare（裸奔）** | **Assisted（信息辅助）** |
|---|---:|---:|
| 局数 | 4 | **7**（东2局连庄 ×3） |
| 决策记录 | 91 | 153 |
| 事件 | 618 | 997 |
| 整场耗时 | 189.7 s | 328.2 s |
| 兜底 / 重试 | 0 / 0 | 0 / 0 |
| 和了 | **0** | **3**（荣和 1、自摸 2） |
| 流局时模型听牌 | 0 / 4 局 | **2 / 4 局**（各收 3000 听牌料） |
| 终局点数 | 25000 / **25000** / 25000 / 25000 | 21400 / **41300** / 15900 / 21400 |
| 模型的顺位 | 2 位（四家全平，按起家方向） | **1 位** |
| prompt token | 191,755 | 473,828 |
| 其中命中缓存 | 88,704（**46%**） | 140,672（**30%**） |
| 输出 token | 10,276 | 15,592 |
| 牌谱字节 | 214,318 | 657,045 |

**Bare 那一场四局全是荒牌流局、四家都没听牌、点数一点没动**：这不只是模型的问题 ——
三家随机选手是**均匀随机**（`Kyoku.randomPlayer`：从合法动作集里等概率挑一个），
本来就极少听牌（§7.3 有实测：1..2000 号种子里只有 15 场出现过立直）。
Assisted 那一场的三次和了全是模型自己打出来的。

### 3.2 按同样手数截断再比（命中率随手数上升，不截断没有可比性）

取两场的**前 91 手**：

| 前 91 手 | Bare | Assisted |
|---|---:|---:|
| prompt token | 191,755 | 275,785（**1.44×**） |
| 命中缓存 | 88,704（**46%**） | 80,128（**29%**） |
| 付全价 | 103,051 | 195,657（**1.90×**） |
| 输出 token | 10,276 | 9,251 |
| 延迟中位数 / 均值 | 1,764 / 1,823 ms | 1,759 / 1,768 ms |
| prompt 尾部均值 / 最大 | 617 / 816 字 | 1,774 / 3,074 字 |

**两档的可缓存前缀是同一段**（票 29b 的设计：档位只动尾部）。命中率之所以 46% → 29%，
不是缓存变差了，是**分母变大了** —— Assisted 的尾部平均 2.9× 长，每手都要付全价。
换句话说：**信息辅助档的钱花在尾部，不在历史上。**

| | | | | | 东2局 3本场 | 25 | 74,847 | 33% |
| | | | | | 东3局 4本场 | 21 | 68,351 | 24% |

逐手看（Bare）：一局之内从 ~20% 爬到 **70%**，开下一局掉回 ~20% 重新爬 ——
**掩蔽事件流是一局一条**，开新局历史清零，前缀跟着重来。这条曲线是 29a/29b 那次形态返工的直接读数。

### 3.4 prompt 的差异（同一手、同一局面，两档逐字节对照）

两场的**第一手**是同一个局面（模型还没做出任何选择，牌局尚未分岔），因此可以逐字节比：

- **preamble 完全相同**（395 字，`janpo-default@08fcaec3`），**工具定义形状完全相同**（368 字）；
  两场的 `prompting.preambles` 都只有 **1 份**（整场没换过人格）。
- **Bare 的尾部 517 字，是 Assisted 那 2,371 字的字节前缀**（公共前缀 = 517，一字不差）。
  Assisted 多出来的 1,854 字就是那一节：

```
【引擎算好的数】（下面这几个数是引擎算出来的事实，不是建议）
当前向听数：3 向听
逐张试打（进退向 0 为不变，+1 为退向（向听戻し）；有效牌括号里是那张牌的剩余枚数）：
- id=3（手切9万）：打完 3 向听，进退向 0，有效牌 28 枚 8 种：1m(4) 4m(4) 8p(3) 3s(3) 6s(4) 9s(4) 2z(3) 7z(3)
- id=0（手切2万）：打完 4 向听，退向 +1，有效牌 77 枚 22 种：…
…（14 条动作各一行）
```

有威胁时再多一节（真跑那一场第 7 手起）：

```
危险度排序（有威胁的家：下家有副露）——现物 / 筋 / 壁 / 宝牌周边四条规则算出来的启发式，
不是概率；排在前面的更安全，同级并列：
- 第1位 id=1（手切2万）：筋 —— 下家 5m 筋
- 第2位 id=0（手切1万）：无依据
…
```

**决策差异**：同一手同一局面，Bare 选了 `id=8 手切3索`（理由「3索孤立无靠张，先切掉闲张保持搭子」），
Assisted 选了 `id=3 手切9万`（理由「打9万孤张保持3向听……维持向听数不倒退」）——
**Assisted 选的正是脚手架里标着「进退向 0」的那一支，Bare 选的是标着「退向 +1」的那一支**。
一手不能下结论，但整场的结果与它同向：Assisted 三次和了、两次流局听牌，Bare 全场零和了零听牌。

## 4. 账单、延迟、兜底

### 4.1 token 与费用

**只报 token，不报钱**（裁决 29b-6：单价随价表漂，牌谱是可分享物）。这台机器上没有核实过的价表，
因此下面只给可以自己乘价的数与**倍数**：

| | Bare（整场 91 手） | Assisted（整场 153 手） |
|---|---:|---:|
| prompt token 合计 | 191,755 | 473,828 |
| ├ 命中缓存（便宜的那档） | 88,704 | 140,672 |
| └ 付全价 | 103,051 | 333,156 |
| 输出 token | 10,276 | 15,592 |
| 写缓存 | 0（DeepSeek 这一档没报这个数） | 0 |

**命中失效时的最坏估算**（换模型、改一个字的 preamble、改任何一行历史的措辞，都会让整段前缀作废）：
付全价的 prompt token 从 103,051 → 191,755（**+86%**，Bare）、333,156 → 473,828（**+42%**，Assisted）。
Bare 受伤更重，因为它的可缓存部分占比更高。

**一整场的量级**：两档合计 **66.6 万 prompt token + 2.6 万输出 token**，加上断电演习那 255 次 401，
就是这一票的全部账单。

### 4.2 延迟分布（毫秒，取自牌谱里每条记录的 `latency_ms`）

## 10. 形态返工的账（29a / 29b）—— M1 最值钱的一节

### 10.1 为什么发生

20 号票我们要的是「某座位能合法看到的一切」——**一个名词、一个快照**。实现者精确地做了要求的东西，
而当时仓库里的证据全指向另一边：引擎内核是 `fold(events) → GameState`；ADR-0002 说事件流是唯一可分享物；
22 号票同一个人写的是「UI 状态 = fold(事件前缀)」。**围观者拿到的是历史形态，LLM 拿到的是快照形态，
同一份信息两种形态，没人察觉不一致。**

**它没有暴露，因为快照式能跑**：23 号票真跑一局 0 兜底，模型还宣言了暗杠。没有红灯，
代价是隐形的（钱 + 缺一整类可读的事实）。

**告警信号是补丁**：28 号票先要给投影补 `PendingKan`（抢杠窗口），又要补立直宣言牌与宣言巡。
一次是巧合，两次是形态错了 —— 而当时把它们当「补漏」处理，没当症状读。

**问题的真实规模**（按「牌手合法感知的历史事实」清点，快照只能表达第一项）：
河里有哪些牌与手切摸切 ✓；每张牌第几巡打的、跨家先后 ✗；立直宣言牌与宣言巡 ✗；
立直**之后**通过的牌 ✗；第几巡碰了什么、鸣完打了什么 ✗；杠宝牌何时翻开 ✗；
**见逃し（哪些牌过了一圈没人要）** ✗；九种九牌等途中宣言 ✗。

**见逃し是最锋利的例子**：它不是一个事件，是一个事件的**缺席**。任何快照都表达不了「什么没发生」。
所以这不是缺几个字段，是「**是什么**」与「**发生过什么**」是两个不同的信息空间，而我们只给了前者。

### 10.2 代价：出人意料地小

| 项 | 代价 |
|---|---|
| `Observation` 类型 | **一个字段没改** |
| `Observation.ofState` 签名 | **没变**（内部换成「掩蔽 + fold」） |
| 下游三票（22 牌桌 / 24 脚手架 / 25 Danger） | **一行没改** |
| 黄金用例 | 29a **一字未动**；29b 因为决策包多一段 `history` 而 **412 行纯新增、0 行改动** |
| prompt | 改了**一次**（三段形态：preamble / 历史 / 尾部） |
| 牌谱格式 | 改了**一次**（v1 → v2，只存尾部；v1 仍读得动，且 v1 读进来写出去仍是 v1） |
| 性能 | 直算 0.46 ms/局 → 增量 fold 0.56 ms/局（1.2×）。**一次性重头 fold 是 29.0 ms（63×），所以增量维护是必须的，不是加分项** |
| 迁移风险 | expand → 闸门 → contract 三步，属性测试断言两种实现逐字段相等，**一次跑绿，零反例** |

**为什么这么小**：因为它不是重做，是**换供给方**。类型不变，来源从「直算 `GameState`」换成
「fold 掩蔽流」，下游根本不知道换过。第一次给主人的方案里我们把代价写成「重做 20 号票的一部分 +
牌桌每帧要 fold」——**两句都不准**，因此主人第一次选了「并存」；纠正之后才有了 29a 这一票。
**教训的一半在这里：把代价估高了，会让人选一个更糟的方案。**

### 10.3 收益：可量化的那部分

- **prompt 的可缓存前缀真的命中了**：这一票整场实测 Bare **46%**、一局之内从 ~20% 爬到 **70%**。
  快照式下命中的只有那个恒定的 preamble（29b 实测约 46% 且**不随手数上升**），
  所以要看的不是绝对值，是**它随手数怎么走**。
- **牌谱瘦了**：每手存整份 prompt → 只存尾部，Bare 档省 **69%**、Assisted 省 **43%**；
  更要紧的是**旧格式随手数线性增长（整场就是 O(n²)），新格式近似恒定**。
  这一票的实测：Assisted 那场 153 手的牌谱 657 KB，其中 preamble **1 份**（395 字）、
  工具形状 **1 份**（368 字）——旧格式要各存 153 份，每份前缀还得带上那一手的整段历史。
- **多出来的信息进了 prompt**：九项历史事实全部可读（巡目、跨家先后、手切摸切时序、
  河与鸣的时序对齐、立直宣言牌与宣言巡、立直后通过的牌、见逃し、杠宝牌揭示时机、途中宣言）。

### 10.4 那条判据（这一节存在的理由）

> **当你要给同一个投影补第二个「发生过的事」的字段时，停下来问 ——
> 是不是该给它历史，而不是再加一个字段。**
>
> 换一种说法：**一个投影里出现第二个只能从历史算的字段，就是形态错了。**

**这条判据当场就抓到了一个孪生兄弟**：26 号票的 `DecisionRecord` 每手存 prompt 全文与 tools 全文，
而 prompt 是 (事件流 + 座位 + 渲染版本 + 脚手架档位) 的派生物、事件流就在同一份牌谱里。
快照式下它只是浪费 4.6 KB，29a 落地后它会变成 O(n²) —— 修复并进票 31，成了上面那 69%。

**它早就摆在代码里没人看**：手切摸切（`tsumogiri`）恰恰是整个快照投影里**唯一用历史形态实现的字段** ——
实现者当时就发现它没法从状态里读、只能从事件流里 `List.choose` 出来，于是写了那段代码。
**如果一个字段只能从历史算，形态本身可能就该是历史。** 告警信号早在 20 号票的代码里亮着。

### 10.5 还欠着的一笔（M2 要知道）

25 号的 Danger 现在吃的是 fold 出来的 `Observation`，与快照时代相同。现物与筋只需要全部河牌，
所以 M1 没问题；但**捨て牌読み**（立直巡目、副露进度、手切摸切的时序模式、见逃し）本质上是历史推理。
29a 之后 Danger **有条件**直接吃流了。M2 若要加强危险度，从这里入手，**别再给快照加字段**。
