## 那三个问题的答案（先答，再讲理由）

### 问题一：这笔账属于谁？——**这一次会话的事实，不是这一桌的事实。判：不进牌谱。**

**判据只有一条**：牌谱是「这一场发生过什么」的记录，而一次作废的问话**恰恰是没有发生的那一手**；
它发生在**这台浏览器驱动这张牌桌的过程里**，而不是牌桌上。

四条证据，每条都指得出代码或数：

1. **三种起因里两种是坐在这台浏览器前的人按的那一下**（`VoidCause`）：`Rebound` 是他把座位拨给了自己 /
   别的模型 / bot，`NextKyoku` 是他点了「下一局」；第三种 `Expired` 是**一趟 HTTP 与牌桌时钟的竞态**。
   三种没有一种是「这一局的牌怎么走」。
2. **同一份事件流换个人打开，这几笔一笔都复现不出来**。`Table.replay` 里 `Voided = []` 不是偷懒：
   回放里没人要出手，因此**一次问话都不会发生**，更谈不上作废。
   这就是票面那句「只属于此刻这个浏览器」的形状。
3. **牌局的历史里根本没有它**。牌谱今天的每一样都对得上事件流：局面是 fold 出来的，
   决策记录有 `Turn` 当锚、`ActionIds` 与 prompt 尾部都能从事件流重算。
   一笔 `VoidedAsk` 在牌谱里**没有任何对照物**——收到牌谱的人只能信。
4. **钱是「谁的 key」的事，不是「这一桌」的事**。落了子的那几笔跟着那一手走（它们是「这一手是怎么来的」
   的一部分）；没落子的那几笔只回答「我这一次会话花了多少」。

**ADR-0002 与账单口径这两句话在这件事上打不打架？——不打。是我在票面上读到的那个冲突被误设了。**

- ADR-0002 说的是**「一场对局对外只有一种序列化形式」**（不许出现第二套格式），
  它没说「这台浏览器里的一切都要进牌谱」。判「不进牌谱」不新增任何格式，因此**它是 ADR-0002 的顺从，不是例外**。
- 账单口径那句「账单报的是**花掉的总额**」管的是**牌桌上那一行**（`Table.usage`），
  它一个字也没说牌谱要带着它走。
  **顺带一条订正**（判据 19：人工可核对的东西先核一遍）：票面把这句口径记在「票 83 / 79」名下，
  查过两份报告——**票 79 长出了那一行 token 账单**（79 报告只写了 token 总量与「没写成钱」的理由），
  **票 83 只是把它归位到牌桌那个盒子里**（83 §1 第 3 条，核过 DOM）；
  **「花掉的总额」这句措辞是票 108 写进 `Table.usage` 注释、票 109 §② 正式立的**。
- 于是真正的冲突不在 ADR 与口径之间，而在**同一句话在两处说的是两件事**：
  Live 那一行报的是「花掉的总额」，牌谱 fold 出来那一行报的是「落了子的那几手的合计」。
  **这一票要治的就是这个**——不是把两个数弄成一样，是**让每一处说清自己报的是哪一个**。

### 问题二：若进牌谱，牌谱还可复算吗？——**fold 不会坏，但那不是它的代价所在。我真做了一遍来量。**

- **fold 不会坏**：`Replay.traceOfPaifu` 只吃 `paifu.Events`，作废的问话不改任何事件；
  它进了牌谱也只会像 `Decisions` 那样被挂在旁边（`recordAt` 按 `Turn` 摆）。
  **所以「不可复算」不是否掉它的理由**，我不拿一个站不住的理由去挡。
- **真正的代价是「可分享物里多了一段谁也核不了的数」**，外加它把这一层的概念推进引擎。
  我把这条路**真写了一遍**（throwaway spike，§③ 有代价的量与它红出来的原文）：
  `VoidCause` / `VoidedAsk` 两个类型得**搬进引擎**（`Paifu.fs` +122 行），牌桌那侧少 74 行，
  `Paifu.create` 多一个形参（7 个调用点），而**引擎从此认得「人在面板上把座位拨给了谁」这种东西**。
  跑完量完就**整段撤了**，仓库里一个字节都没留。

### 问题三：不进牌谱 → 导出之后账少了一块，页面说不说？——**两头都说，而且分开说。**

**没说出来的缺失就是骗人**，所以缺口的**两头**各说一句，两句话都在同一行上（`table-usage`）：

| 在哪一头 | 那一行现在写什么 | 谁守着 |
| --- | --- | --- |
| **Live（人要按「导出牌谱」的那一刻）** | `这一桌累计：… 输出 94 tok——其中 1 笔花了钱没落子（1 笔是换人撤的），导出的牌谱不带这几笔。` | 第 19 趟的 ⑨ + 3 条 dotnet 用例 |
| **牌谱进来（回放 / 导入 / 首页那份 Demo）** | `这一桌累计：… 输出 192 tok——牌谱只带得走落了子的那几手的账，当时花掉的只多不少。` | 「从外面进来」那一趟 + 1 条 dotnet 用例 |
| **URL 分享** | **一行都不长**：`stripAudit` 把决策记录整段抹掉（票 77），那一屏 0 tok，`usageLine` 在 0 tok 时不占位 | 同上那条用例末段 |

**第三条路那一格是这一票查出来的一件好事**：分享链接那一屏**连一个会被误读的数都没有**，
因此也没有要声明的缺失——**没有数就不必解释**。三条出牌桌的路各是什么形状，现在有用例钉着。

## ③ 我真做了一遍「进牌谱」：代价与它红出来的样子

**这是被否掉的那条路，不是猜的**（判据 14：先量再判）。改法是**最诚实的那一种**——
不新造第二个格式，就把这本账放进 `Paifu`：

| 改哪 | 量出来是多少 |
| --- | --- |
| `VoidCause` / `VoidedAsk` **搬进引擎**（`src/Janpo.Engine/Paifu.fs`） | +122 行（两个类型 + 一个 DU 的 wire 形态 + 两对编解码器） |
| `src/Janpo.Web/Table.fs` | −74 行（类型搬走） |
| `Paifu.create` 多一个形参 | **7 个调用点**（CLI 1、页面 2、用例 4） |
| `Paifu.stripAudit` | 多一个判断：URL 分享带不带这本账（我选了不带——**又一处要维护的口径**） |
| 浏览器闸门 | **0 处**（wire 加一格可缺省字段，页面那侧不用改） |
| 既有 dotnet 用例 | **0 条红**（317 条照旧全绿；红的只有本票那两条守着判断的） |

**代价不在「哪里编译不过」，在两件编译器管不着的事**：

1. **引擎从此认得一个只有页面才有的概念**。`VoidCause.Rebound of taker: string` 里那个 `taker`
   是**面板上那枚名牌此刻写着什么**（票 109 §9 判过：它是「当时录下的事实」，不是 `SeatChoice`）。
   引擎里因此会多出一个字段，它的含义要读页面的配桌面板才说得清。
2. **可分享物里多一段谁也核不了的数**：牌谱里其余每一样都对得上事件流（§「问题一」第 3 条），
   这一段对不上任何东西。**而格式是只进不出的**——`Paifu.supported = [1; 2; 3]`，
   加进去的可缺省字段以后要撤，得让解码器永远认得它。

**它红出来的样子**（把 spike 打上之后跑本票那两条用例）：

```
Janpo.Web.Tests.StaleAskTests.牌谱带不走这笔账：导出再导入一趟，少的正是那两笔没落子的花销 [FAIL]
  Assert.Equal() Failure: Collections differ
  Expected: ["version", "ruleset", "events", "decisions", "prompting"]
  Actual:   ["version", "ruleset", "events", "decisions", "voided", ···]

Janpo.Web.Tests.StaleAskTests.回放那一行自己说出账少了一块：而且不许编一个「几笔没落子」的数 [FAIL]
  Assert.Equal() Failure: Values differ
  Expected: 0
  Actual:   2
```

**这就是那条判断的执行体**（判据 2：写下一条不变量先问谁执行它）：
往牌谱里加这一格的人会当场撞上这两条，而**那是 ADR-0002 的修订，该走提案**（见文末给调度器那一条）。

## ④ 形态债：`Voided` 是不是票 87 否掉的那个形态？——**不是。判：留在 `Table` 上不动。**

### 4-1 两条判据摆在一起就分得开

| | 票 87 的 `LiveTable.Human` | 本票手里的 `Table.Voided` |
| --- | --- | --- |
| 它存的是什么 | 「此刻轮到真人了吗」——**局面算得出来的一件事** | 「有过一次没落子的 provider 调用」——**局面、事件流、决策记录里都没有的一件事** |
| 有没有第二个来源 | **有**（局面本身），于是它**会与局面对不上** | **没有**。它与谁都对不上不了 |
| 它真的漂过吗 | **漂过**：`?table=1` 一打开，座位 0 是亲、牌在手上，而那一格还是空的，页面说「轮到别人」 | 漂不了：`voidAsk` 只往后追加，`creditVoid` 只往那一格里填 token |
| 正确处置 | **删字段、现问**（`TableState.handOf`） | 删掉就是把钱抹了（票 108 §2.2 量到的那个病） |

**判据 9 的那句话要连着它的判法一起读**：「一个投影里出现第二个**只能从历史算**的字段」——
判法是问「这个字段还有没有第二个来源、会不会与那个来源对不上」。
`Voided` 不是「只能从历史算」，**它是历史里根本没有的**：一次没有落子的问话不在事件流上留任何痕迹。
**会漂的字段才是形态债；漂不了的原始事实是账本。**

### 4-2 三种做法与代价（我选的是第一种）

| 做法 | 代价 | 判 |
| --- | --- | --- |
| **A：留在 `Table` 上不动**（本票选的） | `Table` 上有一格在**回放那一侧恒为空**（`Table.replay` 里 `Voided = []`），读代码的人会问一次「为什么」——所以那一格的注释与本票的用例得把答案写死 | **选它** |
| B：挪去 `LiveTable`（与 `Passed` / `BaselineTroubles` 两本同类的账做邻居） | **「花掉的总额」那句口径的执行者会从 `Table.usage` 搬到页面那一层**：`Table.usage` 退成「落了子的那几手的合计」，而页面另有一个把两半加起来的 `usage`。**两个名字近似、含义相反的取值器摆在一起**，正是裁决 26-6（「两份计数只会漂」）那个形状。外加 ~25 处用例断言要跟着改（票 108/109/111 的地盘） | **否**：换来的只是「同类的账住在一处」这种整齐，而**整齐不是执行体** |
| C：从 `Decisions + 事件流` 现算 | **算不出来**：一次没落子的问话不在事件流上留痕，也没有决策记录。现算的唯一办法是先把它存下来——那就是 A/B | **否**（不是取舍，是不成立） |

**留给下一个人的触发条件**（免得他拿判据 9 来推翻这一条，或者相反地永远不敢动）：
**若 `Table` 上再长出第三本「不进牌谱」的账，或者 `Table.usage` 的口径再分叉**（例如要「按局分册」），
**那时就该把这几本账一起挪去一个专管账的地方**——那时搬家有执行体上的收益，今天没有。

**Standards**（`docs/agents/fsharp-style.md` + Fowler 坏味道基线 + 判据 2 / 3 / 7 / 18 / 20）。改掉的三处：
