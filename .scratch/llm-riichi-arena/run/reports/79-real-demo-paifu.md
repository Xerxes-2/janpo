## 1. 产线：`web/scripts/demo-game.mjs`（上一位写的，我回收 + 补了两个旋钮）

它不是闸门、不进 CI：拿真 key 跑一场四席真对局，把导出的牌谱存下来，并把挑局与记账要的数
一次算齐。上一位派工被 watchdog 砍在跑第一场，脚本本身是完整的，我加了两处：

| 加了什么 | 为什么 |
|---|---|
| `--thinkers none` | 原来 `"none".split(",").map(parseInt)` 解析成 `[NaN]`：**场子照跑，但记账把四席全算成「不是直觉档」**，两档延迟数会当场串味。顺带只摆真有人坐的那几份档案（没人坐的档案留在库里，事后读牌谱的人会以为那一场开过思考） |
| `--tier bare\|assisted` | 见 §3：裸奔档的四席 8 局里**一次都没听牌**，一份合格的资产根本产不出来。档位是座位级配置（`ScaffoldTier`），本来就该能从命令行拨 |

跑法（一场一条命令，跑完看账再开下一场）：

```sh
cd web && pnpm run fable
JANPO_KEY_FILE=/tmp/deepseek_key node scripts/demo-game.mjs \
  --seed 15 --thinkers none --tier assisted --keep /tmp/79-games/seed-15-assisted.json
```

**key 的规矩**：只从 `JANPO_KEY_FILE` 读、落进浏览器 localStorage 为止；
导出的字节与文件名里出现它就当场红（与 `verify-export` 同一条断言，每一场都跑过，全绿）。
换上去那份资产我另外手查过一遍：**不含 key、不含本机档案名（「思考档」/「直觉档」）**。

**票 74 留的那个问题（「flash 档四路并发的整场收益要票 79 的真跑来量」）有答案了：整场收益接近零。**

### 3.4 气泡的等待感（26-11 / 票 76 留给这次实测定的那件事）

- 直觉档：**一手 1.7 秒**（p95 2.4 s）就有一句 40–90 字的中文理由；
- 思考档：**一手 11.8 秒**（p95 25 s），最长的一手 30 秒以上。

**结论：气泡不用做成流式，先做「已等秒数」就够——但那只对直觉档成立。**
2 秒的等待人根本不需要流式；25 秒的等待要的也不是流式（thinking 是一坨没结构的文本，
边流边跳只会更吵），而是**现在这个「在想：已等 N 秒 / 上限 M 秒」的计时**，票 76 已经做了。
提议：**判不做**（写进 `DECISIONS.md` 79-4），等 M3 真有人开思考档跑长局时再看。

### 3.5 模型打得怎么样（spec：裸 LLM 的低段位表现本身是内容）

**裸奔档（bare）两场、8 局、32 手牌：立直 0 次、和了 0 次、听牌 1 次。** 四局全是流局，
其中 6 局四家**没有一家听牌**。它不是不会打——每一手的理由都像模像样（「保留进张面广的筒子」），
但**它算不清自己离听牌还有多远**：整整 739 次问话里，「立直」与「和了」这两个动作
**一次都没被摆到它面前**（因为压根没到听牌），所以那两句人格里写的「能立直就立直」是空谈。

**换成信息辅助档（assisted，prompt 尾部多一节算好的向听 / 逐张试打 / 有效牌 / 危险度）之后，
同一个模型、同样的人格、同样的思考预算：3 场里 2 立直起步、和了 1–4 次、听牌成了常态。**
这是这一票最值得记的一件事：**这一档的差别不是「打得好一点」，是「打不打得完一副牌」。**

零散的观感：会为了「保留孤张字牌」拆好搭子；副露非常凶（34 次里 24 次是吃，
「爱鸣牌」那一席确实最凶）；有一手四张 2 索直接暗杠、理由写得头头是道；
危险牌意识只在 assisted 档的危险度那一节出现之后才偶尔提一句。

## 4. 体积与首屏：新旧两份，同一台机器同一个探针

量法照票 75 §4：一次性 playwright 探针（**跑完删了，没进仓库**），
`--enable-precise-memory-info --js-flags=--expose-gc`，量的是 `vite preview` 托管的**打包产物**，
每轮开一个新 context（不吃缓存），5 轮取中位。

| 量 | 旧资产（bot，票 71） | **新资产（真对局）** | 差 |
|---|---|---|---|
| 资产字（`String.Length`，断言数的就是它） | 21,485 | **1,122,337** | ×52 |
| UTF-8 字节（磁盘上、`fetch` 之前） | 21,485 | **1,766,503** | ×82 |
| 过线字节（gzip 之后的 response body） | 2,421 | **151,631** | ×63 |
| 帧数 | 256 | **470** | +214 |
| 首屏（打开 → `table-board` 出现） | 154 ms | **218 ms** | **+64 ms** |
| 留住一份帧多占的 JS 堆 | 2.5 MB | **7.9 MB** | +5.4 MB |

**汉字一个字三个字节**：`assetText.Length` 数的是 UTF-16 字数，磁盘字节是它的 1.57 倍。
断言的单位没换（仍是 `String.Length`），但报告里两个数都给，免得下一位按字节去估。

**体积上限从 512 KB 提到 1.25 MiB（1,310,720）**，理由与代价都写在
`HomePageTests.sizeBudget` 的注释里：**定在实测值上方 17%**——它挂得住下一份资产，
再胖就该重新量一遍首屏（或者剪 thinking），而不是默默把这个数往上推。
先红一次（判据 1）：把上限按回 512 KB，那条断言当场红——

```

  Demo 牌谱 1122337 字节，超出 524288 字节的预算
```

**播完一整场要多久**：470 帧 × 300 ms（首页默认 2×）= **2 分 21 秒**（旧的是 1 分 17 秒）。
这是这份资产唯一让我犹豫的地方，见 §8 待审项 2。

## 5. 那条红线：`ReplayTimelineTests.拖到中间那几个游标…`（**诊断到底了，但不该由我修**）

### 5.1 症状

换上真资产之后，票 75 那条「拖到某一处 = 直接 fold 同一前缀」的用例，
**5 个切点里有 2 个对不上**（事件 756 条，切点 94 / 189 / 378 / 567 / 755）：

```
cut=94  cursor=57  不一致
  座位2 手牌 fold=[1万 4万 5万 1筒 1筒 4索 7索 8索 8索 9索 9索]
             帧=[    4万 5万 9万 1筒 1筒 4索 7索 8索 8索 9索 9索]
cut=567 cursor=354 不一致（同样只差一张）
```

它不是「差一帧」：整份 470 帧里**没有任何一帧**与截断 fold 出来的那个局面一致。

### 5.2 谁错了：**第三锚点错了，帧是对的**

拿**第四条路**判（`dotnet fsi`，只按事件流做加减法：起手 + 摸 − 打 − 副露吃掉的，
谁的实现都不靠——判据 18 说的「引入第三个锚点」）：

```
只按事件流手算：座位 2 在第 93 条事件之后的手牌（10 张）
  [4万 5万 1筒 1筒 4索 7索 8索 8索 9索 9索]
```

- **帧那一侧** = 这 10 张 + **9万**。9万正是第 94 条事件（`Tsumo 座位2 9万`）摸进来的那一张：
  帧比截断点**快一步**，而这一步是票 75 那条用例的注释里**已经写明并接受**的相位差；
- **截断 fold 那一侧** = 这 10 张 + **1万**。**1万从来没被发给过座位 2**
  ——事件流里座位 2 摸过 9筒/东/中/…（十次）没有一次是 1万，起手也没有。
  它是 `Replay.game` 拿**截断**的流重建时，从**自己推断出来的那座牌山**替座位 2 摸的一张。

也就是说：截断点正好落在「这一家该摸牌了」那一瞬时，第三锚点会**自己摸一张假的**，
于是它给出的手牌与真牌谱无关。**产品那一侧（人拖时间轴看见的帧）没有问题。**

### 5.3 它以前为什么不红：切点撞不上

| 语料 | 事件 | 杠 | 5 个切点里对不上的 |
|---|---|---|---|
| 旧 bot 资产（票 71） | 404 | 0 | 无 |
| 种子 3 assisted | 977 | 1 | 无 |
| 种子 79 bare | 614 | 2 | 1 个（切点 307） |
| 种子 79 assisted | 627 | 1 | 1 个（切点 156） |
| **种子 15 assisted（新资产）** | 756 | 1 | **2 个（切点 94、567）** |

`total/8`、`total/4`… 这五个位置**是否落在某家的摸牌相位上**纯属语料的运气。
旧资产 404 条事件时五个切点都没撞上，于是这条断言绿了三票。

### 5.4 我为什么不动它

- 硬约束 3：**测试只许往更硬的方向改**。把切点挪开、或把手牌从比较里摘掉，两种都是放宽；
- 票面边界：**「不改任何代码逻辑去迁就这场对局，真跑里发现的 bug 只报不修」**；
- 它是**票 75 的用例**，改它的锚点是那一票的事（硬约束 6：只动自己票里的文件）；
- 修法我给出建议（谁接谁看）：**把第三锚点从「`Replay.game` 截断流」换成「直接按事件流做加减法」**
  ——就是 §5.2 那段二十行的 fsi 探针，它不需要牌山、不会自己摸牌，而且比现在这条**更硬**
  （现在这条与被测实现共享 `Replay` 那一族代码，第四条路一条都不共享）。
  次选是**把「fold 到了要摸牌的相位」这件事显式做成一个值**并在那些切点上换一组更弱但仍精确的断言
  （判据 4：覆盖不到的要写出来，别留在注释里当旁白）。

### 5.5 顺手改硬的两条（同一族，**没有放宽**）

`ThinkingBubbleTests` 与 `ReplayTimelineTests` 各有一句 `Assert.Empty demo.Decisions`
——「首页那份 Demo 是 bot 牌谱」这个前提从此不成立。两处都**翻成 `Assert.NotEmpty`**：
它们本来就要「一条记录都没有 / 只有一条」的语料，各自用 `loadedWith []` / `{ demo with Decisions = [record] }`
现造，而这一句现在成了**那一步的阳性对照**（资产要是空的，换不换都一样，下面整段就什么都证不了）。

## 8. 留给人的待审项

1. **§5 那条红线怎么裁**（挡着这一票收工）：三条路——
   (a) 立一票给票 75 换第三锚点（我的建议，§5.4 有具体写法）；
   (b) 判「这条用例只在旧资产上成立」并把它的语料显式钉成旧那一份（**我不建议**：那等于让
   一条防漂的用例从此不看真语料）；
   (c) 换一份切点撞不上的真资产（种子 3 assisted 那一份 5 个切点全过，但它**以流局终**，
   会顶掉 `Demo 以和了终` 那一条——除非顺位/内容判据也一起重议）。
2. **首页播完一整场要 2 分 21 秒**（旧的 1 分 17 秒）。资产更长更好看，但门面页要不要这么长，
   是产品口味；`TableState.demoSpeed` 一行能改（现在 2×，改 4× 就是 70 秒）。
3. **Demo 那一场是 `assisted` 档打的**，不是裸奔档。裸奔档在真 provider 上**打不完一副牌**（§3.5），
   而 spec 说「裸 LLM 的低段位表现本身是内容」——这句话仍然对，但它**不适合当门面**：
   访客第一眼看四局流局，看不到役也看不到点棒。**首页用 assisted、擂台赛用 bare** 是我的建议，
   请主人终审（这也是 M3 分档对照的第一份真数据）。
4. **思考档的两个数值得单独看一眼**：单手中位 11.8 s、输出 1,599 tok/手、资产 6.9 KB/手。
   四席全开思考的一场东风战要 **约 105 分钟、约 3.2 MB**。**首页不该用它**；
   要留一份「思考全文」的样品，建议单独跑一局半庄之外的短样本挂在文档里。
5. **气泡被面板切掉最后一行**（§6.2 最不满意那条），建议另立一票。
