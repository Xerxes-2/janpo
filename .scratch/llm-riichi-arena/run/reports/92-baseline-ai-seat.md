# 票 92：强 AI 基线坐一席 —— 实现报告

**结论先说四句。**

1. **它坐得下、也打得动。** 配桌里多了第四种选手（`SeatChoice.Baseline` / `SeatPlayer.Baseline`，
   牌谱里叫 `baseline`），四席怎么混都行。**八颗种子、八场东风战、3466 手，兜底 0 次。**
2. **它比自带 bot 强，而且这句话是对照出来的**：同样八颗种子、同样坐座位 0，
   换成强 AI 之后**一位 6 次 / 二位 2 次**（换回自带 bot 是**一位 1 次**）。
3. **懒加载与降级各有一道红过的闸门**（破坏实验的红字在第 ④ 节）。
   **「它不会说话」那一条在 CI 里由 dotnet 用例守着**——浏览器那一趟在 CI 里量不到它，
   因为 CI 里那 6 MB 根本不在场，那一席是降级态的 bot。**这件事写在闸门自己的输出里。**
4. **翻译层撞出两处静默错译**，票 91 的「零拒绝」覆盖不到它们：
   字牌（它印 `E`，janpo 写 `1z`）与场风（riichienv 认不出 `2z` 就当东场）。
   两处都不报错，只会算错。各有一条用例钉着。

## ① 形态：它与另外三种选手完全同级

```
SeatChoice.Baseline ──► SeatPlayer.Baseline ──► Demand.Baseline of DecisionPackage
                                                        │
                          Baseline.ask（F#，只传字符串）─┘
                                                        ▼
                          web/src/baseline/baseline.ts ── decide(request) ─► { action_id }
```

- **它消费的是同一份决策包**（`DecisionPackage.encoder` 的产物，一个字段都没改写）——
  与 LLM 席、真人席一字不差。**强度参照系必须与被参照的那几席看同一张牌桌**，
  否则它强在哪里就说不清了。
- **回来的只有一个 id**（ADR-0005）。TS 侧拿不到 `GameState`，也构造不出 `Action`。
- **它不留决策记录**（走 `Table.apply` 而不是 `applyRecorded`）：没有 thinking、没有一句话理由、
  没有 token 账单。于是气泡（读 `Table.Decisions`）与账单行（读 `Table.usage`）
  **在结构上就为空**——不是显示一个空气泡或者「0 tok」。**牌谱格式一个字段都没加。**
- **拉不动时的退回发生在配桌那一层**（`TableState.degraded`）：`SeatPlayer.Baseline` →
  `SeatPlayer.Bot Opinionated`。于是牌谱里那一列 `names` 说的是实话——
  真正把这几手打出来的就是 `opinionated`。页面上那几处 `data-seat-name` / `data-seats`
  跟着改读配桌（`TableState.seatNames`），两份写法不会漂。

**新增的状态只有三格**（`LiveTable`）：`Baseline: BaselineStatus`（整桌一份，不是每席一份）、
`Consulting: Consult list`（在飞的问话）、`BaselineTroubles: string list`（兜底代打的原因）。

**`Consult` 刻意不并进 `Awaiting`**：并进去就得给它造一份假 `LlmSeat`，
而那份假配置会从气泡、状态线一路漏到牌谱里去——**这一席不会说话，就不该有一个能说话的表示**。

## ② 翻译层：三处形态差 + 两处静默错译

票 91 报告第 ④ 节列的三处形态差按它说的做了（`web/src/baseline/mjai.ts`）：

| 差在哪 | 怎么翻 |
| --- | --- |
| `actor` 全线缺失 | **不补**：`actor` 一律不进比对键（包里每条动作恒是被问那一席的，比它等于比常量） |
| `reach` 把宣言与宣言牌融成一条 | **扔掉 `reach_dahai`**：janpo 会**再问一次**宣言牌，那一手它自己决——与上游 `predict_reach_discard` 做的是同一件事，而且不必扣着状态 |
| `hora` 缺 `pai` | 只按类型配（一包里至多一条 `hora`，和的是哪张由引擎说了算） |

**票 91 没查到、票 92 撞上的两处**（都不报错，只会算错）：

1. **字牌两侧写法不同。** riichienv 的 `mjai_to_tid` 读得懂 `1z`（进去那一半没事），
   但 `tid_to_mjai` 印出来的是 `E`/`S`/`W`/`N`/`P`/`F`/`C`——**出来那一半非翻不可**。
   不翻的下场：它每次打字牌都配不到包里那一条，整手掉进兜底。
2. **场风走的是另一张对照表。** `state/event_handler.rs` 里是个手写的
   `match bakaze.as_str() { "E" => …, _ => Wind::East }`，而 janpo 的 `Kaze.toMjai` 印的是 `1z`…`4z`
   ——**南场会被它当成东场**，而场风是它观测张量里的一路通道（自风与役牌全靠它）。

**票 91 那句「janpo 打出来的事件流零拒绝」量的是 serde 解析**，
而牌面与场风是解析之后由 `parse_mjai_tile` / 那个 `match` 读的，读不懂时**静静地退回默认值**。
这不是票 91 的错，是「零拒绝」这条证据的射程本来就到不了那里。

**掩蔽流怎么进去**：`DecisionPackage.history` 的 `start_kyoku` 只带自家那一手（`tehai`，单数），
翻译层把它摊成 mjai 服务端那种四格 `tehais`、他家那三格填 `"?"`。
**每问一手就从这一局的头重喂一遍**：riichienv 的 `start_kyoku` 处理本身就是一次整局重置，
因此这样是正确的，也免掉了一份「上次喂到哪儿」的游标（那份游标只要错开一条就会静静地算错整局）。

**这个设计贵不贵——量过**（`/tmp` 的一次性脚本，方法写在这里）：拿一份真实牌谱的头一局
（152 行、座位 0 的 24 个决策点），每个决策点都从头重喂再推理，
**中位 0.64 ms / p95 0.84 ms**，整局合计 19 ms。喂一行约 4 µs，**重喂的代价埋在推理的噪声里**。

## ③ 「它到底看不看得见他家的手牌」——量出来的，不是读代码读出来的

**这是本票的地基**：它消费的是掩蔽流（他家的配牌与他家摸的牌在里面根本没有位置），
而票 91 量的全是**完整**的天凤牌谱。两者不是同一份输入。

`probe/akagi-wasm/mask-parity.mjs`：同一份牌谱喂两遍（一遍原样、一遍把他家三家的配牌换成
13 个 `"?"`、他家摸的那张也换成 `"?"`），逐个决策点比它出的那一手。

```
牌谱 111 份、座位 0/1/2/3、决策点 69318 个
掩蔽之后被引擎拒掉的行：0
两份输入下出的手不同的决策点：0
```

**69,318 个决策点，遮与不遮逐条同一手。** 于是两件事一起有了答案：
掩蔽流喂得进去（它不会被 13 张 `"?"` 弄崩），以及**它不看他家的手牌**——
那不是「读上游 `obs.rs` 的通道表得来的印象」，是量出来的（判据 19 那条教训的同一族）。

## ④ 闸门与它们红过的样子（判据 1）

新增一道浏览器闸门 `web/scripts/verify-baseline.mjs`（四趟）与 13 条 dotnet 用例
（`tests/Janpo.Web.Tests/BaselineSeatTests.fs`）、15 条 TS 用例（`web/tests/baseline/mjai.test.ts`）。

**破坏实验，逐条**（改**产品代码**，重编 Fable 之后跑那一趟）：

**① 懒加载**——把 `started` 里那句「这一桌没有强 AI 基线席就什么都不做」去掉：

```
强 AI 基线这一道没过：
不选强 AI 基线的对局拉了那份资产 1 次：http://localhost:4173/baseline/janpo-baseline.wasm
不选它的那一页却有强 AI 基线那一行（data-baseline=loading）
```

**② 降级**——把 `degraded` 里那条「拉不动就退回自带 bot」去掉：

```
强 AI 基线这一道没过：
退回之后 data-seats 该四家都是 opinionated，却是「opinionated,baseline,opinionated,opinionated」
资产拉不动之后这一局没打完（走了 2 手）
第 1 手卡住了
```

**③ 它不会说话**——让 `settleBaseline` 留一条决策记录（等于**给它编了一句理由**）：

```
强 AI 基线这一道没过：
强 AI 基线那一席长出了气泡（data-bubble=spoke）      ← 站点上有那份产物时
失败 …BaselineSeatTests.它出的那一手不留决策记录：没有气泡、没有 token 账单、也不是「0 tok」
```

**第 ③ 条第一次做破坏实验时一声不吭**，理由值得记下来：那一趟原本掐着资产跑，
于是那一席早已退回自带 bot——**量到的「没有气泡」是「bot 席没有气泡」**
（`verify-bubbles` 早就钉着的那件事）。改法是那一趟**不再掐资产**，
并让它把**走的是哪一档**印在总结里：

- 站点上有那份产物 → 「它真出手了一整段，那一席仍旧没有气泡、没有账单行」
- 没有 → 「那一席这一趟是降级态的自带 bot：这一趟量的不是「它不会说话」」

**CI 里守这一条的是 dotnet 那条用例**（上面第二行红字），它不需要那 6 MB。

**④ 与真人同桌**：真人坐 0、强 AI 坐 1、两个 bot。他家三席的手牌行里
一个 `data-pai` 都没有——票 87 那条结构性不泄露照旧绿。

## ⑤ CI 覆盖不到什么（判据 4，逐条写出来）

**那 6 MB 不入版本控制**（ADR-0006 边界 6），因此 **CI 里那份产物不在场**。后果逐条：

| CI 里跑到的 | CI 里**跑不到**的 |
| --- | --- |
| 懒加载全部四条断言（包括「拨上它就恰好 1 次请求」——回的是 404，但请求真发出去了） | 那 6 MB **真的下得下来、编得动、起得来** |
| 降级整条路（掐掉那次请求 / 站点上没有那份文件，两种失法同一个下场） | **它真出的那一手对不对**——一手都没验过 |
| 「它不会说话」的**结构判据**（dotnet：那一手不留决策记录 ⇒ 没有气泡、没有账单） | 「它不会说话」的**DOM 判据**（浏览器那一趟在 CI 里量的是降级态的 bot 席） |
| 翻译层的每一条形态差与两处静默错译（TS 用例，一个字节的 wasm 都不加载） | 翻译层在**真输出**上的覆盖面（它印出来的那些形状，用例里是手写的） |
| 与真人同桌时的结构性不泄露（那一席是降级态的 bot） | 与真人同桌时**它真在打**的那一局 |

**真推理只在本机演习那一档**：按 `web/public/baseline/README.md` 造一份产物放进
`web/public/baseline/`，再 `cd web && node scripts/verify-baseline.mjs --asset`。
那一档多跑第 ⑤ 趟（它真坐一席打完一局、牌谱里认得出它、兜底 0 手、仍旧不长气泡）。

**没有开 Rust 工具链那条 CI**（票 91 建议过的那条单独 workflow）：本票没做。
理由是它属于**上线**那一步（Pages 部署前造一份产物），而上线形态本票只做到「怎么造、放哪儿」
（见 ⑦）。**这一条留给人裁**。

## ⑥ 真跑一局：它打得怎么样

浏览器里（`vite preview` 的产物形态），强 AI 基线坐座位 0、其余三家「有主见」，
八颗种子各打一整场**东风战**，**对照组是同样八颗种子、座位 0 换回「有主见」**：

| 种子 | 强 AI 坐 0：手数 / 局 / 墙钟 / 座位 0 的名次与点数 | 对照（四家「有主见」）：座位 0 的名次与点数 |
| ---: | --- | --- |
| 2088 | 283 / 5 / 471 ms / **1 位 45600** | 4 位 17500 |
| 447 | 529 / 8 / 927 ms / **1 位 44300** | 3 位 22500 |
| 91 | 346 / 5 / 556 ms / **1 位 31600** | 1 位 28900 |
| 1234 | 274 / 4 / 429 ms / 2 位 28500 | 2 位 25000 |
| 7777 | 712 / 9 / 988 ms / **1 位 55200** | 4 位 15700 |
| 31337 | 495 / 7 / 716 ms / 2 位 40200 | 2 位 22500 |
| 55 | 459 / 6 / 651 ms / **1 位 35000** | 2 位 24100 |
| 909 | 368 / 5 / 522 ms / **1 位 41800** | 2 位 25000 |

**一位 6 次 / 二位 2 次，平均顺位 1.25**；对照组同一座位是**一位 1 次、平均顺位 2.50**。
**兜底 0 次**（3466 手里一次都没有「它出的那一手不在这一包里」）。

**别把这张表读成「它有多强」**：八场东风战是**八个样本**，而且对手只有一种（自带的「有主见」）。
它答的是**这一票要答的那件事**——「它接上去之后真的在打，而且明显不是随手打」。
真要一个雀力刻度，那是复盘对照（票 93）与更大规模跑批的事。

**墙钟**：一整场东风战（283–712 手）在浏览器里 **429–988 ms** 跑完，
对照组（四家 bot）是 141–295 ms。差额里**推理只占一小部分**（上面量过：单手 0.64 ms，
一局约 19 ms），大头是**每问一手都要把决策包编成 JSON 过一次界**加上 Elmish 重绘
——与 LLM 席那条路一模一样，只是那边被 1.7 秒的网络往返盖住了。
**延迟这一项对人完全不构成约束**（一手之间还隔着一记 600 ms 的定时器）。

## ⑧ 顺手撞出来的两件事

**1. 同一席在飞时被问了第二次（本票自己的 bug，已修）。**
`step` 里那张「已经问出去了」的表（`flying`）原本只装 `Awaiting`（模型席），
强 AI 基线席不在里面 ⇒ 每记定时器都把同一手再问一遍 ⇒ 两份回执各落一个动作，
第二个当场被引擎拒（`现在没有可响应的牌，座位 0 无从响应起`，牌桌停住）。
**它只在真跑那份 wasm 时才现形**（八颗种子里三颗中招），CI 的常规趟碰不到——
这正是第 ⑤ 节那张表要说的事。修法：`flying` 把 `Consulting` 也算进去。

**2. 一份过期的问话会拿旧包落子（`drain` 里加了一道剪枝）。**
响应阶段可能在别席答完之后当场散掉（有人碰了），那一席的待答整条消失，
而它那份在飞的问话还留着——包里的 id 是按**旧**的合法动作集编的号。
`drain` 顶上现在按「引擎此刻给这一席的合法动作集与包里那一列逐条相同」剪一遍。

**同一族的问题在模型席那条路上也存在**（`drain` 找 `Awaiting` 同样是按座位找，没有这道剪枝）。
**本票没有动它**（票 74/73 的地盘，改它要重跑那几道闸门）。**这件事描述在这里，不编号。**

## ⑨ review 结论（两轴各自跑了一遍，fixed point `yzrwumvy`）

**Standards**（`docs/agents/fsharp-style.md` + Fowler 坏味道基线）。改掉的三处：

- `waiting` 里原本有个内联 `match` 塞在 `||` 链里（规则 3 的「变换链写成嵌套」的近亲）
  → 拆成 `stalled`。
- `BaselineLine.at` 里两处内联 `match ... | _ -> …`（视图里的通配符分支违背本仓库
  「match 故意穷举」那条文化）→ 提成 `className` / `bytes` 两个命名值，四态各自表态。
- `current` 这个谓词名字读不出它在问什么 → `stillCurrent`（Mysterious Name）。

**判断为「不算问题」的两处**：
① `BaselineStatus` 在五处各被 `match` 一次（Repeated Switches）——五处各答一个不同的问题，
而穷尽 match 正是本仓库拿来「加一个 case 时编译器指出该改哪里」的手段（`SeatPlayer` 有八处）。
② `baseline` / `baselineTroubles` 两个取值器同形（Duplicated Code）——
它们与同文件的 `passes` / `humanSeat` 是同一个三行惯用法，抽出来只会多一层。

**Spec**（票 92 + ADR-0006 的六条边界）：票面五条「要什么行为」与五道闸门逐条对照见第 ④ / ⑤ 节，
**五道里四道进 CI，第五道（真跑一局）在本机演习那一档**，覆盖不到什么逐条写在第 ⑤ 节。

**票面没要、但做了的两样，各有理由**：
① `TableState.seatNames` 与它在 `AgentLine` / `TablePanel` 上的两个消费点——
拉不动时那一席退回 bot（92-2），而这两处 `data-*` 自称「与牌谱里那一列同一份真源」，
不跟着改就成了第二份写法（判据 2）。**它动的是 `AgentLine.agentLine` 的签名，
不是 `web/src/agent/**`**（那个目录一个字没动）。
② `probe/akagi-wasm/mask-parity.mjs`——它是第 ③ 节那条地基结论的执行体，
在票的边界内（`probe/akagi-wasm/**`）。
