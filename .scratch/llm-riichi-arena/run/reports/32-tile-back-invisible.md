## 病灶与改法

`.tile.back` 同时写了 `color: transparent` 与 `background: color-mix(in srgb, currentcolor 25%, transparent)`。
`currentcolor` 已经是透明，于是底色与 `.tile` 继承来的 `border: 1px solid currentcolor` **一起透明**——
牌背整块不画。围观者看到的是「手牌 10」后面一片空白（暗杠两端那两张同理）。

改法（`web/src/styles.css`，一条规则）：

- 牌背的墨色**改成不吃 `currentcolor`**，取 `canvastext`（页面正文色，跟着 `:root` 的 `color-scheme: light dark` 走）：
  `border-color` 与斜纹用 55% 的它，底色用 8%。
- `color: transparent` **留着**：元素里那个「背」字仍然不许露出来。它本来就不是牌面
  （投影里没有牌面，`.back` 连 `data-pai` 都没有），但一排「背」字看着像一排明牌。
- 与明牌的区分是**底纹**：明牌是空底加字，牌背是 45° 斜纹加实线框。同样大小、同一行里一眼分得开。

被否决的两种：

1. **保留 currentcolor，改用别的办法藏字**（`font-size: 0` 要另写死一个 `height` 才不塌；
   `text-indent` + `overflow: hidden` 会让「背」字从 padding 那 0.15rem 里露出一条边）。
2. **干脆把「背」字显出来**。它不泄露牌面，但 13 张带字的牌与明牌一眼分不开——违反票面第一条。

顺带一处（同类隐形，见下）：`TablePage.boardHead` 里**供托为 0 时整个「立直棒」字段不画**了。

## 同类隐形的扫查（标签有、值为空）

扫的范围：README 那张图上出现的整页（牌桌页 `TablePage.fs` 的场况栏、四家面板、结算面板、危险度面板、
LLM 配置面板）＋ `web/src/styles.css` 里所有会让元素画不出来的写法。曳光弹页（`App.fs`）不在这一票的范围里。

| 位置 | 判断 | 处置 |
|---|---|---|
| `.tile.back` 牌背 | **真缺陷**：值在（投影给了张数），画不出来 | 修了 |
| 「立直棒」后面什么都没有（供托 0） | **值为零本就不该画**——立直棒是「供托 N 根」的实物画法，一根没有就没有实物；只留一枚标签看着像掉了东西，而根数本来就写在它左边 | 修了：`Kyotaku = 0` 时整个字段不画，与紧邻的「里宝牌指示牌」空表时不画同一形状 |
| 一家没副露时的「副露」空行 | **不是缺陷**：它是每家固定三行（手牌 / 副露 / 河）中的一行，「这家还门清」本身是信息；`.tiles` 有 `min-height: 1.6rem`，行位置稳定是这套最小牌桌的既有设计。删掉会让面板每次副露就跳一下 | 不动 |
| 开局时的「河 0」空行 | **不是缺陷**：标题自带计数，「河 0」自己把「没有」说清楚了 | 不动 |
| 「里宝牌指示牌」 | 早就是空表就整个不画 | 不动（本票照抄了它的形状） |
| 「上一手：」在还没走一手时 | 早就写成「还没走一手」 | 不动 |
| 危险度面板标题「有威胁的家：{…}」 | **画不出空的**：排序与威胁名单同出自 `Danger.threatened`，没有威胁的家时 `Danger.rank` 返回空表（`Danger.fs:367`），`dangerPanel` 见空表就整块不画 | 不动 |
| 结算的「役：」 | **画不出空的**：和了必有役，宝牌 / 里宝牌 / 红宝牌三行本来就是有才写；流局那一份的「听牌：」在一家不听时明写「无」（代码里有一句注释专门说这件事） | 不动 |
| LLM 面板里空着的 API key 输入框 | **不是缺陷**：输入框自己有边框，空是它正确的空状态 | 不动 |
| 其余吃 `currentcolor` 的地方（`.tile` 的边框、`--line`、`.bou` 的 `background`） | **安全**：全仓库只有 `.tile.back` 一处设过 `color: transparent`，其余元素的 `color` 都是正常值；立直棒的黑棒与副露的虚线框在上面两张证据图里都看得见 | 不动 |
