### 1.3 取 0.8 的理由，以及它不是什么

- **它落在分歧那一族的 p75（0.7210）与 p95（0.9229）之间**：按 p0 排，大约取分歧里最尖的那五分之一。
- **一局一席剩个位数**：中位 2、p75 3、最多 8（半庄）。这正是「值得看的那几手」该有的量级。
- **0.9 太狠**：46% 的席位一手都没有——一条一半场次都开不了口的判据，与没有它差别不大（判据 3 的同一族）。
- **0.6 太松**：中位 5、最多 20，与「有分歧」那一半的毛病同族。
- **分布上没有断崖**：0.75 / 0.8 / 0.85 分别命中 1147 / 876 / 642，平滑下降。
  因此这份报告不说「0.8 是数据里的边界」——**它是一个旋钮**，判据是「一局一席剩几手」，
  这句话原样写在 `Review.telling` 的注释里，好让下一个动它的人知道该重新量什么。
- **它不是一个分数**：页面上**不印这个数**（印了就得给它编一个来源，票 107 的逐数溯源），
  也不按它分档、不写「它很确定」这类度量词（票 103 的硬边界原样保留）。

## 2. 落地：判据、条数、看得见的东西

### 2.1 两条判据（`Review.worth`）

```fsharp
// 这一条为什么值得看：better / strong / both，都不占就是空串。
let worth (strong: ReviewStrong option) (note: ReviewNote) : string =
    match not (List.isEmpty note.Better), strong |> Option.exists notable with …

// 「它很确定，而你打的排在很后面」：p0 ≥ 0.8，且你排第 3 或不在它那几条里。
let notable (strong: ReviewStrong) : bool = …
let worthwhile (strong) (note) : bool = worth strong note <> ""
```

三件事值得点名：

1. **`notable` 蕴含 `Differs`**：排第三或不在候选里的那一手，必然不是它头一条挑的那一手
   （两边比的都是同一包里的 id）。于是「时间轴上由强 AI 点亮的每一枚都落在
   `Review.disagreements` 数的那几手里」是**从定义推出来的**，闸门再逐枚验一遍。
2. **`worth` 交的是一个词而不是一个布尔**：它上 DOM（`data-review-worth`），
   于是闸门得以**逐手**核「是哪一条判据点亮了它」。只交布尔的话，一条判据被改坏而另一条
   刚好盖住同几手时闸门一声不响——§4 红-3 就是那一幕。
3. **上游没给分布时 `notable` 恒 false**（老产物、或它这一手交不出候选）：
   那时「它有多确定」这件事我们根本没拿到，拿缺席当「它很确定」就是编一个数。

### 2.2 筛掉了多少，当场说出来（票面：不许静静地少显示）

`ReviewFilter.toDisplay` 的四种措辞，**两个数、同一个顺序**（`total` 与 `kept`）：

> 只看值得看的那几手：122 手里显示 22 手。判据是引擎的试打表里还有更好的换法；问过强 AI 之后还有第二条。
> 只看值得看的那几手：122 手里显示 25 手。两条判据：引擎的试打表里还有更好的换法，或者强 AI 给自己那一手的概率过了阈值、而你打的不在它头两条里。
> 这一列摆着全部 122 手，其中值得看的有 22 手（时间轴上标着的就是它们）。
> 只看值得看的那几手：7 手里显示 0 手——这一席这一场没有一手落进判据。按「看全部」摆出其余那些。

- **没问过强 AI 时不提第二条判据**：那几 MB 没拉之前它一手都筛不到，写出来就是声称一件
  此刻没有执行体的事（判据 2；同票 90/93 那条「没有的东西不占位」）。
- **「头两条」写成汉字**：那一句里只该有 `total` 与 `kept` 两个 ASCII 数字，
  阈值与「第 3」都不印（印了就得在两处各加一格来源）。
- 那一枚开关上写「看全部」/「只看值得看的那几手」，**一个数都没有**（同一件事不在两处各写一个数）。

### 2.3 三次「默认显示几手」的实测

| 那一席是谁在打 | 一整场几手 | 引擎那一半（有更好的换法） | 强 AI 那一半（notable） | 并起来显示 |
| --- | ---: | ---: | ---: | ---: |
| 首页 Demo 座位 0（janpo bot） | 115 | 25 | 7 | 30（26.1%） |
| **首页 Demo 座位 1（janpo bot）** | **122** | **22** | **6** | **25（20.5%）** |
| 首页 Demo 座位 2（janpo bot） | 112 | 22 | 11 | 25（22.3%） |
| 首页 Demo 座位 3（janpo bot） | 115 | 36 | 5 | 39（33.9%） |
| 闸门那一桌（永远点头一张的假人） | 96 | 52 | —（CI 里那份产物不在场） | 52（54.2%） |

**同一份牌谱里分歧是 61–72 手（53–63%）**，而收紧后由强 AI 点亮的只有 5–11 手——
这就是「收紧」两个字的全部内容。

**第三次测量：换个强选手坐这儿会剩几手**（`/tmp/t105/strongplayer.mjs`，一次性，没进仓库）。
同一份牌谱、同一批局面，问强 AI 会打什么，再看**它自己那一手**会不会被引擎的试打表帕累托占优：

```
座位 0：打牌 90 手｜牌谱里那位打的被占优 25（27.8%）｜强 AI 同一局面打的被占优 9（10.0%）
座位 1：打牌 92 手｜牌谱里那位打的被占优 22（23.9%）｜强 AI 同一局面打的被占优 11（12.0%）
座位 2：打牌 92 手｜牌谱里那位打的被占优 22（23.9%）｜强 AI 同一局面打的被占优 8（ 8.7%）
座位 3：打牌 89 手｜牌谱里那位打的被占优 36（40.4%）｜强 AI 同一局面打的被占优 11（12.4%）
```

**读法**：这条筛选**跟着选手水平走**——越会打，剩得越少（8.7–12.4% vs 24–40%）。
剩下那一成也不冤枉：帕累托那三项里**没有打点与役**（票 90 的硬边界：不加权、不造总分），
因此强 AI 为了役或宝牌留的那几张，在这条判据下确实「有更好的换法」。
**这也是「值得看」而不是「你打错了」的理由**：它说的是「这一手有东西可比」。

### 2.4 时间轴上那几枚（`TablePanel`）

```
[data-testid="table-timeline-marks"]（data-marks=N）
  └─ span.timeline-mark（data-timeline-mark=手序、data-timeline-mark-frame=帧号，left: frame/last %）
```

- **与滑块同一根坐标系**：分母就是滑块的上界 `timeline.Last`，因此一枚标记的位置
  就是拖到那一帧时滑块停的位置（左右各缩回半个滑块头，理由写在 CSS 里）。
- **不是按钮、不接鼠标**：一整场二三十枚挤在一根轴上，每枚实宽不到两个像素——
  做成点得动的东西就是在邀人点不中。跳到那一手的路子只有一条：复盘那一列里点它（票 76 的 `RecordOpened`）。
- **不跟着那一枚开关变**：拨回「看全部」只是把其余那几百条也摆出来，值得看的仍旧是那几手。
- **上帝视角下一枚都没有**（阴性对照）：标记是「**这一席**值得看的那几手」，没有主语就没有它们。
- 颜色用**靛青**而不是朱红（票 93 立的调色板纪律：朱红是赤牌・立直・兜底与警示）。

**我亲眼看过**（判据 7）：`/tmp/t105/{timeline,review}.png`（一次性 playwright 探针，没进仓库），
打开看过两次。看到的三件事：① 22 枚细墨线沿轴散着，右端到 78% 处收住（座位 1 最后一手值得看的是第 372 手，
这一场共 464 手）；② 复盘抬头右边那一枚「看全部」与「回到原处」同一排、同一种字号；
③ 筛选那一句排在那段说明下面、那一列上面——**筛掉了多少要在看到那几条之前就读到**，
不然人会以为这一局只打了二十几手。

### 2.5 形状：状态提到了一个钩子里（这一票唯一一处结构改动）

票 93 把强 AI 那一叠回执关在 `ReviewPanel.Panel` 自己的组件里（**不上 `TableModel`**，理由是
它不是这一场对局的事实）。这一票要的东西横跨牌桌上下两处：**时间轴在牌桌上面、复盘在牌桌下面**。

因此 `Panel` 组件改成钩子 `ReviewPanel.useReview`，交出 `{ Marks; Panel }`，
由 `TablePage.Page` 调一次、分给两处。**那一叠回执仍旧不上 `TableModel`**（票 93 的判断原样保留），
`TableModel` 上只多了**一格开关** `ReviewFiltered`（票面明许的那一格）。

被否决的两种做法：

- **让时间轴自己再问一遍强 AI**：那是第二条可以自己漂的算路（判据 9 同一族），
  而且要把那 6 MB 的推理再跑一整场。
- **把那一叠回执放进 `TableModel`**：与票 93 的判断相反，且会让「复盘的现算投影」
  变成对局状态的一部分（ADR-0002 的味道）。

## 3. 闸门：谁在守什么

### 3.1 dotnet 侧（`tests/Janpo.Web.Tests/ReviewTests.fs`，**+5 条**；296 → 301）

| 用例 | 钉的是 |
| --- | --- |
| **它很确定而你打的排在后面**：阈值两侧与排第几四种，各断言一次 | 六种情形（没给分布 / 排第 1 / 排第 2 / 排第 3 / 不在候选里且 p0=0.79 / 同上 p0=0.80）逐条摆明；**0.79 与 0.80 那两条钉的就是阈值本身**；`notable ⟹ Differs` 当场验；两侧各走到 2 与 4 次（判据 3） |

### 3.2 浏览器侧（`verify-review.mjs` 的 ⑰，**三程共用**；趟数不变，仍是 18 趟）

一程之内量两态：

1. **筛选开着**（默认）：这一列画的那几条 = 闸门**照规则**自己数出来的那几手
   （引擎那一半从 `ReviewCheck.expected` 的试打表推帕累托占优；强 AI 那一半从闸门**自己问出来的**
   那一叠 `mine.notes` 推 p0 与排第几——判据 8：期望值取自规则，不取自被检查那句话的来源）；
   逐行 `data-review-worth` 对「是哪一条判据点亮了它」；那一句里两个数逐数溯源；
   时间轴上那几枚与这一列**手序逐个相同、帧号逐个相同**。
2. **按「看全部」**：条数回到一整场，**轴上一枚不少**；票 90/93/103/107 那几条逐项对拍
   在这一态下跑（**一条不少**，计数改前改后逐字相同）。

外加两条阴性/阳性对照：**上帝视角下一枚标记都没有**；**跳到那一手之后，那一枚标记钉的
就是游标停住的那一帧**（第⑧条那一跳优先挑轴上标着的那几手，于是帧号有了一个与面板无关的锚）。

执行次数（闸门自己印出来，判据 3）：

## 8. 留给人的待审项

1. **收词**（改术语表要单票授权，因此一个字没写）。`CONTEXT.md` 的 `Review（复盘）` 词条
   今天没有「值得看的那几手」这件事。建议的措辞：

   > **默认只摆值得看的那几手**（`Review.worth` + `TableModel.ReviewFiltered`，执行者是
   > `ReviewTests` 票 105 那五条与 `verify-review.mjs` 的 ⑰）：两条判据，或的关系——
   > 引擎的试打表里还有帕累托占优你那一张的换法，或者强 AI 给自己那一手的概率 ≥ 阈值
   > 而你打的排第 3 或不在它那几条里。**「有分歧」本身不是判据**（实测一整场 122 手里分歧 64 手）。
   > 筛掉了多少当场说出来，那一句里的两个数同样逐数溯源；时间轴上那几枚标记
   > 与这一列**出自同一次 `Review.focused`**。

2. **阈值 0.8 是个旋钮**（§1.3）：分布上没有断崖，改它只需改 `Review.telling` 一处
   （闸门那一侧那个同名常数会当场红——那是有意的，它是这个数的执行者）。
   若主人希望「宁滥勿缺」，0.7 那一档一局一席中位 3 手；若希望更狠，0.9 那一档
   有 46% 的席位一手都没有。
3. **筛选状态不进 localStorage、也不进分享链接**：它是「这一屏怎么看」，不是这一桌的事实。
   换一席 / 换一份牌谱时它**不重置**（拨过一次就一直是那样）——这是我判的，若主人觉得
   每次坐下都该回到默认，改的是 `TableState` 那个 `React.useEffect` 旁边一行。
4. **摊开的那一手被筛掉时的样子**：拨到「只看值得看的那几手」而正摊开的那一手不在列里时，
   那一条会从列里消失（牌桌与「回到原处」照旧）。**没有为它开例外**：开了例外，
   「这一列摆的就是值得看的那几手」这句话就多了一个尾巴，闸门那一侧也得跟着多一条规则。
5. **时间轴上那几枚点不动**（§2.4）：真要点得动，得先把它们做粗（现在实宽 2 px），
   而那会把一整场二三十枚连成一片。这是产品口味，留给主人裁。
