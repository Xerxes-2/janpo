## 1. 上游给的是什么——先量，再写断言

票面点名了这件事：**不许先写一条 `sum = 1` 的断言再去调数据**。所以先量。

### 1.1 读源码得到的印象

`.upstream/native_bot/src/engine.rs`：

- `const SHOW_TOP_N: usize = 3;`——「HUD 的多行推荐卡要几条」；
- `Decision.candidates` 的注释：`Top legal actions ranked by policy probability (best first).`
  `action` 是 `candidates[0].0`，`Probabilities are a softmax over the legal set.`
- `action_codec.rs` 的 `rank_all`：**按 action id 去重**（同一动作的红 5 与非红 5 归成一条，
  优先留非红），softmax **只在合法动作集上**归一，再按 logit 降序**稳定排序**，最后
  `truncate(SHOW_TOP_N)`。
- 一处例外要记着：top1 是立直而 `predict_reach_discard` 失败时，上游把立直**从已经截断的那三条里删掉**
  ——于是那几手的候选会少一条（`engine.rs:251`）。

**但这只是印象**（判据 19 的同一族）。下面是量出来的。

### 2.1 三条设计取舍

**① 认不出来的那一条：丢掉，但把「上游给了几条」带过来。**
ADR-0005 只许 id 过界，因此一条落不进这一包的候选没法在页面上叫出名字。丢掉它是唯一选项，
**但票 92 的教训正是「扔了而没人知道」**——所以 `candidates_total` 是独立一格，页面上会说
「它给了 3 条（这一包里认得出 2 条）」。**实测触发 0 次**（首页那一局 122 手、上游共 341 条候选，
认不出 0 条），闸门为此专门数了一笔，非 0 就报红。

**② 序号取上游那一列的位置，不重排。** 中间一条认不出来时，第 3 条仍旧写「第 3」。
重排的话「第 2」就不再是上游那张表里的第 2 了——而「你打的它排第几」这句话的全部意义
就在于它说的是上游那张表。

**③ 两位小数只出现在给人看的那一句里。** `data-*` 上搬的是**最短往返表示**
（`string p`：.NET 与 JS 的 `ToString()` 都是它）。两头各拦一道：
`0 < p < 0.005` 写 `<0.01`（真语料里末一条的 p05 是 0.0004，写成 `0.00` 就成了「它给了零」），
`0.995 ≤ p < 1` 写 `>0.99`。**两句都是事实上的界，不是形容词。**

## 4. 逐位对拍：拿 node 那条路径当左侧

**闸门第⑮条**（`verify-review.mjs`）：抽 8 手（每 16 手一手），把页面那一侧**真正喂进去的那几行
mjai**（`mjai.historyLines`）搬到 node 里，用 `probe/akagi-wasm/probe.js` 的手写 ABI
起同一份 `.wasm`、喂同一串行、拿 `probe_decide` 的**原文**：

```
逐位对拍：抽了 8 手拿 probe/akagi-wasm 的 node 路径重问一次，页面上那几个概率与 wasm 直接印的严格相等 ✓（其中 22 个连字面都一样）
```

**为什么断言的是「严格相等」而不是「字符串逐字相同」**——这一条是量出来的，不是省事：
Rust 的 `{}` 对 f32 **从不用指数写法**（它印 `0.0000001`），而 JS 在 1e-6 以下换成 `1e-7`；
§1 那一趟里 **69,318 个决策点中有 217 个**至少有一条 p 落在这个区间。拿字面相等当断言，
那几手会**假红**，而假红比真红危险（判据 16）。所以断言是两条：

1. 两侧解析出来的双精度 **`===`**（一个 bit 都不许差）；
2. 页面上那一串本身是**最短往返表示**（`String(Number(s)) === s`）——**一位都没舍**。

实测这一局抽到的 22 个值**连字面都一样**（闸门把这个数印出来）。红-1 证明了它抓得住舍入。

**这条路径为什么算「另一条路」**：它在 node 里、不经过页面、不经过 F#、不经过 `Baseline` 那道口，
拿到的是 wasm 印出来的那段 JSON 文本本身。页面那一侧的翻译层（`mjai.ts`）两边共用——
**但「喂的是不是同一份投影」由第⑪⑫条守着**（票 93 立的，那两条各自重建投影），
这一条守的是**数字有没有在我们手里变形**。

## 6. 代价：它真的是免费的吗（判据 14：先量再说）

**改前那三趟是在 fixed point `xrmkwqlr` 上跑的**（同一台机器、同一份 6 MB 产物、
`node scripts/verify-review.mjs --asset`，首页那份牌谱座位 1、**122 手**）：

| 量的什么 | 改前（三趟） | 改后（三趟） |
|---|---|---|
| **逐手重建局面并推理**（页面自己报的 `ask_ms`） | **92 / 88 / 91 ms** | **88 / 87 / 89 ms** |
| 每手 | 0.75 / 0.72 / 0.75 ms | 0.72 / 0.71 / 0.73 ms |
| **按下去到有东西看**（端到端墙钟，含编码、解码、两次重绘） | 121 / 116 / 117 ms | 113 / 112 / 118 ms |
| 取那 6 MB 并起起来（本机 dev server） | 34 / 30 / 30 ms | 26 / 27 / 31 ms |
| 闸门那一侧逐手问（另一条路，122 手 + 抽样多问） | 83 / 82 / 83 ms | 82 ms |

**推理耗时没有顶上去**，而且**代码上就不可能顶上去**：候选与那一手出自 `probe_decide`
的**同一段 JSON**（`decideNow` 一次调用，`baseline.ts` 里那一处注释写着这件事）。
多出来的只有「把每条候选配回这一包」：`matchAction` 微基准 **0.20 µs/次**（14 条动作、最坏命中，
`/tmp` 一次性脚本），每手多 3 次 = **0.6 µs**——埋在推理的噪声里。

**跨界那一叠有多大**（闸门每趟印出来，走的就是页面那一枚按钮走的 `decideAll`）：

```
跨界那一叠（122 手）：20192 字节，把分布那两格拆掉是 5174 字节（多 290.3%）；逐手问 63 ms、连编解码共 65 ms
```

- **+15,018 字节 / 122 手 ≈ 123 字节一手**。相对数字（+290%）吓人是因为原来那一叠本来就小
  （一手只有 `{"action_id":N,"latency_ms":N,"turn":N}`）；**绝对量是 20 KB，在一份 6 MB 的资产旁边可以忽略**。
- **编码 + `JSON.parse` 合计约 2 ms**（65 − 63）。F# 那一侧的 Thoth 解码没有单独计时，
  它落在端到端墙钟里，而端到端墙钟改前改后落在同一区间（116±5 vs 114±3）。

**一件自己踩的事，写下来**：第一版闸门把 `askMs` 写在 `return` 里算，而那时 `decideAll`
