## 三、118 处差异，逐条判定

**没有一处是「看起来没事」放过的。** 118 处落在 68 局里，归成三家，另有一家（C）已在对拍侧抹掉：

| | 处数 / 局数 | 判定 |
|---|---|---|
| **A 打牌前连着两次杠时，明杠宝牌的翻牌时机** | 60 / 28 | **引擎错**（票 16 的 16-B 选错了，它自己说过「有反例就改」） |
| **B 大明杠 → 岭上开花的责任支付** | 46 / 24 | **引擎错 / 规则集口径**：天凤不采用大明杠责任支付，**24/24 全错** |
| **C 四家立直那手缺 `reach_accepted`** | 20 / 10 | **上游噪声**，钱流 10/10 证明棒确实放下了 → 已抹掉（第四节） |
| **D 三家和了被上游删成裸 `ryukyoku`** | 12 / 6 | **上游数据丢失**，天凤 JSON 逐条确认 |

两处引擎的账**只报不修**（票的要求）：两处都要动 `GameState` 的语义边界、
并且要改别的票的既有断言期望值，不属于「修法一目了然」。**下面每一处都给了可直接复现的定位。**

### A. 打牌前连着两次杠：明杠欠着的那张宝牌，天凤在下一次杠**完成**时就翻了

**票 16 的 16-B 明写着「语料零出现，取最保守的一种（欠账累加、打牌那一刻一次翻光），
有反例（哪怕一局牌谱）就改这一条」。现在有 28 局反例。**

天凤的真实顺序（`2026010113gm-00a9-0000-960f06ba` 第 9 局，加杠 → 加杠）：

```
kakan 2 9m      ← 第一次加杠，欠着一张
tsumo 2 C       ← 岭上牌
kakan 2 C       ← 第二次加杠（**抢杠窗口过去、这一杠成立**）
dora 3m         ← 天凤在这里翻出第一次加杠欠的那张
tsumo 2 P       ← 第二次加杠的岭上牌
dora 6p         ← 第二次加杠欠的那张，赶在打牌之前翻
dahai 2 P
```

引擎现在的顺序是 `kakan tsumo kakan tsumo dora dora dahai`——**两张都攒到打牌那一刻**。
28 局的形状分布（另 25 局是「暗杠打头」，两边一致、零差异）：

| 形状 | 局数 | 差异 |
|---|---|---|
| 加杠 → 加杠 | 19 | 有 |
| 大明杠 → 加杠 | 6 | 有 |
| 加杠 → 暗杠 | 3 | 有（此时天凤先补翻欠账，**再**翻暗杠那张） |
| 大明杠 → 暗杠 | 1 | 有 |
| 暗杠 → 暗杠 / 暗杠 → 加杠 | 24 | 无（暗杠当场翻，两边同） |

**规则一句话**：天凤是「**明杠欠着的指示牌，在下一次杠成立时（补摸岭上牌之前）或下一次打牌之前翻**」，
引擎现在只在打牌之前翻。**抢杠那一支两边一致**（`2026011700gm-00a9-0000-707dfd57` 第 3 局：
加杠 → 岭上 → 加杠被抢 → 那两张谁也没翻，零差异）——因为第二次杠没成立。

**它离算错钱只差一张牌**：`2026010202gm-00a9-0000-15240e94` 第 1 局是
`加杠 → 岭上 → dora(欠账) → 暗杠 → dora → 岭上 → 自摸倍满 24000`。
天凤翻了 2 张指示牌，引擎只翻了 1 张（欠的那张 `P`/白 至今没翻）——
**少的那张指示牌指向 4z 北，而那手里没有北，于是点数恰好没差**。换一张就是钱错。
全量语料里「明杠欠着 + 再杠 + 当场岭上开花」出现 **0 次**，所以这 28 处目前全是顺序差异。

**这 28 局的钱是全查过的**：事件流对拍每局最多报 3 条（`compareEvents` 里的 `List.truncate 3`），
但**终局点数那条对拍不截断**，而 28 局里一局都没报——也就是说顺序不同、钱相同。

复现：

```bash
JANPO_PAIFU_DIR=<含这一场的目录> dotnet test -c Release --filter PaifuDifferentialTests
# 或 nice -n 19 dotnet fsi --exec scripts/fsi/paifu-scan.fsx -- <目录> 0 1 | grep '^D'
```

**要动的地方**：`GameState.PendingKanDora` 现在只由 `applyDahai` 消费，
`completeKan` 里明杠那一支要在**补摸岭上牌之前**先把欠账 flush 掉；
`KanTests` 的「大明杠之后没打牌就又暗杠」那条（票 16 新增的 ④）**期望值要改**——
它钉的正是被这 28 局证伪的那个选择。

### B. 大明杠后的岭上开花：**天凤不让喂杠那家一家付光**（24/24）

`2026010123gm-00a9-0000-bf693ea8` 第 7 局（`daiminkan` 之后立刻自摸）：

```
牌谱   hora 3 3  -2100,-2100,-4000,8200     （30符4飜 2000/3900 + 1 本场）
引擎   hora 3 3  -8200,0,0,8200             （责任支付：喂杠的座位 0 一家付光）
```

`GameState.sekininOf` 的注释写着「**范围按天凤**：大明杠后的岭上开花与大三元 / 大四喜由副露凑齐」。
**前半句被 24/24 的实证否掉了**——语料里每一次「大明杠 → 岭上开花」天凤都按常规自摸分摊，
24 次里 22 次连带下一局的开局点数也对不上（另 2 次是整场最后一局，没有下一局可比）。
后半句（大三元 / 大四喜的包）**语料零出现，没有证据，不动它**。

这不是「规则集口径」可以打发的：**引擎里它根本没有开关**，是写死的。要修的话有两条路——
把大明杠那一支去掉，或给 `Ruleset` 加一项（默认关，天凤那套关着）。
**属于要人裁的语义边界，本票只报。**

### C. 四家立直那一手，上游没写第四条 `reach_accepted`（上游噪声，已抹掉）

10 局，形状完全一致：`reach ×4`，`reach_accepted` 只有 3 条，然后直接 `ryukyoku [0,0,0,0]`。
**那 1000 点到底收没收，由牌谱自己的钱流说了算**：10/10 局的下一局都是**四家各 −1000、供托 +4**。
即第四根立直棒确实放下了，只是转换器没写那条事件。**引擎是对的。**

处置与票 13 的 `denoiseUra` 同一形状：`PaifuReplay.denoiseSuuchaRiichi` 按**牌谱自己的**
「宣言了几条、收了几条、这一手怎么收尾」把缺的那条补回来（条件：以 `ryukyoku` 收尾、
宣言数 ≥ 座位数、有宣言没收的），**不问引擎**。终局点数那条对拍照旧严比——
引擎真要多收 / 少收 1000，当场还是红。

**反向自证**：抹之前这 10 局报 20 处差异，抹之后 0 处；全量差异 132 → 118（只少了这 20 处）。

### D. 三家和了：上游把三条 `hora` 宣言删成了一条裸 `ryukyoku`（数据源缺口）

6 局。症状是重放报「引擎拒绝了牌谱里的动作：座位 N 此刻宣言不了九种九牌」——
因为 `PaifuReplay` 把摸牌后阶段的 `ryukyoku` 当成九种九牌宣言（票 13 的注释写着
「只可能是九种九牌」，**这句话被这 6 局证伪了**）。

**天凤 JSON 逐条确认这 6 局写的都是 `三家和了`**（`sanchaho`）。mjai 流里那三家荣和的事实已经没了：
既没有 `hora`，也没有任何能区分「三响流局」与别的途中流局的字段。**重放喂不出来。**

因此**三家和了仍旧没有任何自动闸门**：它不在 CI 固件里，`Soak.unguarded` 里也仍旧留着它。
但**理由变了**——不是「随机选手到不了所以谁也到不了」，而是**这个数据源不带它**。
换一份保留宣言的牌谱源（或天凤原始 XML）就能守住。这一条已写进 `Soak.unguarded` 的注释与
`PaifuDifferentialTests` 里那条断言的 `unreachable` 列表（判据 4：到不了的要写成代码里的一个值）。

**本票没有改 `PaifuReplay` 去把这 6 局变成「显式跳过」**：现在这条路是
「引擎拒绝 → 报差异」，把它改成跳过，等于让「引擎错误地拒绝了一个真九种九牌」也变成静默跳过。
差异更吵，但更安全。留作待审项。
