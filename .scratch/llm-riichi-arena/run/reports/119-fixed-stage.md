# 119 — 固定舞台：缩放不重排，长卷死掉

**状态**：done（`./scripts/ci.sh` 全绿）　**基点**：`myvnruou`（票 117）
**改了**：`styles.css`、`verify-home.mjs`、`README.md`

## 1. 做法：只缩放根字号

```css
html { font-size: min(calc(100vw / 62), calc(100vh / 61.5)); }
body { overflow: hidden; }
```

样式表里 **204 个尺寸写的是 `rem`**，全都跟着根字号走；**53 个 `px` 几乎全是
`1px solid` 的发丝线**——那些正是不该跟着缩放的东西（缩了会糊）。
∴ **一条规则管全部，DOM 与其余 CSS 一个字不动**。

这比票面原先写的 `--u` + 每处 `calc(N * var(--u))` 好得多：后者要动几百处，
而且新写的尺寸随时可能忘了套。根字号那条**没有「忘了套」这回事**。

`100vw / 62` 是长度÷数值、仍是长度。两个方向取小者 ⇒ 宽高哪边先到头就由哪边定。

## 2. 三视口

| 视口 | 根字号 | scale | 牌宽 | 纵滚 | 横滚 |
|---|---|---|---|---|---|
| 1280×800 | 13.01 | 0.813 | **22.8** | 无 | 无 |
| 1440×900 | 14.63 | 0.914 | **25.6** | 无 | 无 |
| 1366×768（16:9） | 12.49 | 0.781 | **21.8** | 无 | 无 |
| 390×844（手机竖屏） | 6.29 | 0.393 | **11.0** | 无 | 无 |

**代价要说清楚**：牌从 28 px 缩到 22.8 px（−19%）。原因不是缩放本身，是
**这一页是个纵向长条**——内容约 61 rem 高，而 800 px 的视口只给得起 13 px/rem。
横向反而大片空着（牌桌 405 px 在 1280 px 的视口里）。

**这正是票 118 的两列能买回来的东西**：把操作条、状态字、图例搬进牌桌两侧的空地，
纵向堆叠就短了，根字号跟着涨，牌就大回去。∴ **118 与 119 是反向耦合的**——
起草时以为 118 依赖 119，实际上 119 的代价要靠 118 来还。

## 3. 新闸门（`verify-home` 第 ⑫ 条），三条

| | 断言 | 为什么不是同义反复 |
|---|---|---|
| ① | 四个视口都无文档滚动（横纵） | 整票的目的 |
| ② | 内容高/宽不超过视口 | `body { overflow: hidden }` 会把溢出**裁掉**而不是让人滚——光看滚动条会漏掉「看不见」这种更坏的情形 |
| ③ | **牌宽与牌桌宽都与根字号同比例缩放** | ①② 只说「装得下」，而装得下的办法可以是重排（媒体查询把三列变一列也装得下）。**③ 才是「结构不变」那句话的执行者** |

### 反证（每条都先红一次）

| 破坏 | 报的话 |
|---|---|
| 设计高写小（`61.5`→`52`） | 「1280×800 里出现了纵向文档滚动——长卷没死」+「内容高 937 px 超过视口 800 px」 |
| 拆掉高度那一半（只留 `100vw / 62`） | 同上，内容高 1256 px |
| 牌桌尺寸写死 px（`30rem`→`300px`） | 「根字号缩了 1.125 倍而牌桌缩了 1.000 倍——这一处没跟着根字号走，缩放改了结构」 |

**第三条反证第一版没打中。** 当时 ③ 只量牌宽，而我破坏的是牌桌——牌宽走
`--tile-w: 1.75rem`，照旧正确缩放，闸门全绿。
**阴性对照没打中 = 这条断言比我声称的弱**，于是把量点从一处加到两处，再验才红。

## 4. 闸门自己也错了两版，都是「量错了对象」

③ 第一版量 `.ops`、第二版量 `.page`，**都报假红**：这两个盒子的宽由**内容**撑着，
不是布局定的。实测 `.page` 在 1280×800 上是 **885 px**，而它的 `max-width: 52rem`
只有 676 px——min-content 顶开了上限。

∴ 最终只量**宽度由 `rem` 定死**的两处（牌、牌桌）。
**教训与票 117 那条「四个席区矩形一模一样」同源**：断言之前先问一句
「我量的这个数，是被我关心的那件事决定的吗」。

## 5. 闸门逮到一个我的临时探针没抓到的

设计高一开始按探针量的 795 px 定，闸门按**真实驱动路径**（开配桌→收起→走 32 手）
量到 **804 px**，超视口 4 px。探针量的是另一个状态。∴ 61.5 这个数是闸门逼出来的。

## 6. 看图逮到一个闸门没抓到的

图例（票 117 挪进牌桌左边距的那一句）被顶到**视口最左、字被裁掉**。
它 `left: 0` 挂在 `.board` 上，而 `.board` 的宽由内容撑到 885 px。
三条断言全绿——因为它们量的是滚动与缩放比，**没有一条问「字有没有被裁」**。
改成相对居中的牌桌定位（`left: 50%; margin-left: calc(var(--board) / -2 - 10.6rem)`）。

判据 7 这一票第二次兑现（第一次是票 116 那枚看不出可点的摘要行）。

## 7. 两块 media query 与两条像素闸门

- **两块 media query 已在票 117 删掉**（174 行死 CSS）——几何一变它们就一条也选不中了。
  ∴ 这一票只剩「核」的部分：确认没有第三块，`grep '@media'` = 0 条。
- **票 116 的 `BOARD_TOP_MAX_PX`（420）**：仍有意义但**已接近同义反复**——
  固定舞台之后牌桌顶边由设计稿定死（实测 202 px，上限 420）。留着当回归护栏，
  它现在守的是「别在牌桌上面再堆东西」，仍是真约束。
- **票 83 的 `OPS_TO_BOARD_MAX_PX` / 一屏跨度**：实测 547 px（上限 800）。
  同上——已宽松，但它守的「按一下与看结果在同一屏」在两列落地后会重新吃紧。
  **两条都不删**，报告里记明它们此刻的余量，等票 118 之后重估。
