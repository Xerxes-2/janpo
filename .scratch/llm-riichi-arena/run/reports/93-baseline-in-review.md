### 1.1 投影：一处构造、两处消费

```fsharp
// Review.noteOf（票 90 原本只取 scaffold，这一票把包本身留住了）
let package = DecisionPackage.forSeat seat before.State
let scaffold = package |> Option.bind DecisionPackage.scaffold
```

90 的向听/有效牌/危险度与 93 的这一行**读的是同一个值**。这不是省一次计算，是**取消一条算路**：
再写一份「复盘时怎么重建那一手的观测」就等于给同一件事立两个真源，而它们迟早会漂
（票面把这件事点名成「这一票的全部难点」）。

于是「不许拿上帝视角去问」这句话有了执行者，而且执行者不是纪律而是**类型**：
`DecisionPackage` 的构造子只有 `forSeat`，它内部走的是 `Observation.ofState`（掩蔽 + fold），
**外面根本造不出一份没遮过的包**。复盘手上确实握着整局（每一帧的 `GameState` 都在），
但要把它喂出去，得先绕开这个构造子——而绕开是看得见的（红-1 就是绕开的样子）。

### 1.2 那一行怎么算出来

```fsharp
let strongOf (note: ReviewNote) (actionId: int option) (latencyMs: int) : ReviewStrong option
```

- **算不动就整行不出现**：它交不出来（`ActionId = None`）、或者那个 id 压根不在这一包里 → `None`
  → 页面上**一个元素都没有**，不写「暂无」（与票 90 / 92 同一个规矩）。
- **同不同按 id 比**：两边都是同一包里的序号（`DecisionPackage.tryId note.Played package`）。
  一包里同一张牌只有一条打法（`mjai.ts` 的 `actionKey` 那段注释），**摸切与手切因此不会被误报成分歧**。
- **只标「不同」**：`ReviewStrong.toDisplay` 说的是「与你不同 / 与你相同」，**没有「你错了」、
  没有分数、没有百分比**。抬头那一句也只数手数（`122 手里有 64 手与你不同`）——
  一写成百分比，下一步就是拿它当分数（票面边界：不造总分）。

### 1.3 何时触发那一拉：**一枚按钮**（这一条是我判的，记在 DECISIONS 93-1）

ADR-0006 边界 1 是硬约束（首页与普通对局一个字节都不许拉），而复盘是一个**新的**触发点。
自动拉的话，任何一局打完都会闷不作声地多下 6 MB——而复盘的第一层（向听/有效牌/危险度）
本来就是零依赖的（M3 起草时主人裁的「零依赖的复盘是产品底线」），不该为了叠一行把它拖下水。

因此：`review-strong-ask` 那一枚按下去才 `load()`，按下去之前 `data-review-strong-state=untouched`、
资产请求计数为 **0**（闸门第 ⑩ 条量的就是它，破坏实验红-4 按红过）。
按下去之后一次问完一整场（120 手 ~0.1 s，见 §3）——**票面给的「点某一手才算那一手」那条退路没有用上**，
因为量出来的代价用不着它。

### 1.4 状态不上 `TableModel`

那一叠回执活在 `ReviewPanel` 这个组件的 `React.useState` 里（四态 `Consulted`），
**不进 `TableModel`、不进牌谱**：它是终局之后现算的一份投影，不是这一场对局的事实（ADR-0002）。
换一席 / 换一份牌谱就丢掉（`React.useEffect` 依赖 `seated` 与 `Review.signature`）——
上一席那一叠按手序对得上号却是别人的牌，那是一屏逐手都对得上号的假话。

### 1.5 为什么是「一叠进、一叠出」

`Baseline.askAll` 把一整场编成一个信封交给 TS，TS 那侧循环调 **同一个 `decide`**（没有第二条推理路），
回一张 `turn → id` 的表。理由是本仓库没有 `Fable.Promise`：在 F# 里串一百多个 `Promise` 要么
引一个新包，要么手写一条到处能漏错误的链路。**代价是那一叠 JSON 一次编完**（实测见 §3，可忽略）。

### 2.2 浏览器侧（`verify-review.mjs` 多了**第三程**，四条：⑩⑪⑫⑬）

- **⑩ 懒加载**：复盘面板摆在那儿、没人按那一枚时，那份资产的请求计数为 **0**；按下去之后**恰好 1 次**。
- **⑪ 同一份投影**：闸门拿 `ReviewCheck.asks`（**另一条路**重建的那 122 份包）**自己去问同一份 wasm**，
  逐手与页面上那一行对 **id**（顺带对那一串 key）。两边各自重建、各自去问——
  **页面若喂了别的东西，这一条当场炸**（红-1 就是它炸的样子）。
- **⑫ 上帝视角会打 A、该席视角只能打 B**：闸门造两份**故意的上帝视角**（§2.3），
  拿它们问同一份 wasm，挑出 A≠B 的那几手，**逐手断言页面给的是 B**。
- **⑬ 可复现 + 分歧照规则重数**：抽到的那几手**问两遍**必须同一个 id；
  每一行的「不同」由闸门照规则自己判一遍（`played_id ≠ id`），抬头那两个数也要对得上。
  **算不动那一路**（CI 的常规趟）断言：一行都没有、页面明说原因、**票 90 那几栏逐项照旧对拍**。

**执行次数**（闸门自己印出来，判据 3；本机演习那一档）：

### 2.3 两份「故意的上帝视角」是什么，以及**它们为什么真的不同**

`ReviewCheck.planEncoder` 造的两份（**只在闸门里存在，产品代码里一处都造不出来**）：

| 哪一份 | 怎么造 | 它给的 A |
|---|---|---|
| `god_later` | 同一席、同一局，但拿它**在这一局最后一次打牌那一刻**的那条掩蔽流 | 常常是一张**你那一刻手里根本没有的牌**（上面那条：`2m`，不在这一包里）——「它知道你后来摸到了什么」 |
| `god_all` | `GodView.stream state`（**一条不掩、一张不隐**，四家的手牌都摊着）包成 `MaskedEvent.Public` | 一张具体的别的牌（上面那条：`3m` vs `3p`） |

**必须写清楚 `god_all` 为什么会变**，否则这份报告会卖出一个更强的结论：
**这个基线本身对「遮不遮他家的手牌」是不敏感的**——票 92 的 `mask-parity.mjs` 在 111 份牌谱 ×
四个座位 × 69,318 个决策点上量过，**遮与不遮逐条同一手**。
`god_all` 之所以给出不同的答案，是因为 mjai 的**每席**线格式压根表达不了「我看得见四家」：
`mjai.ts` 的 `startKyoku` 认的是掩蔽流那一格 `tehai`（单数、自家），
喂一条上帝视角的 `start_kyoku`（四格 `tehais`）之后它读不出「自家那一手」，
于是**它是在另一副手牌上做决定的**。

所以这两份上帝视角证的是同一件事的两个侧面：**喂错了投影，出来的就是一个人做不到的答案**
（一张你没有的牌 / 一副不是你的手牌）——而不是「它看懂了他家的暗牌」。
真要一份「它看得见他家手牌」的对照，得先改上游的观测编码，那不在这一票里。

## 3. 代价：算一整局要多久（票面点名要给数）

首页那份真牌谱、座位 1、**122 手**，dev server + 无头 Chromium（本机）：

| 哪一段 | 实测 | 谁量的 |
|---|---|---|
| **按下去到有东西看**（端到端墙钟） | **111–134 ms** | 闸门（`Date.now()` 夹住那一次点击） |
| 取那 6 MB 并起起来 | **23–33 ms**（本机 dev server，**不是真站点的下载时间**） | 页面自己（`load_ms`） |
| **逐手重建局面并推理**（翻译 + 从这一局头喂一遍 + 一次前向 × 122） | **87–92 ms ≈ 0.72 ms/手** | 页面自己（`ask_ms`） |
| **重建 122 份投影 + 编码**（`DecisionPackage.forSeat` × 122） | **203–207 ms ≈ 1.7 ms/手** | 闸门那一侧（`ReviewCheck.asks`，`--god-every 0` 单独量过） |
| 逐手问（闸门那一侧，同样 122 手） | **64–83 ms** | 闸门 |

**这一票新增的那一层是第 3 行**（0.72 ms/手）：**重建投影那一层（第 4 行）不是新增的**——
票 90 的每一条标注本来就要建那一份包（它实测 122 条 185 ms），这一票**没有再建第二份**，
只是把同一份多消费了一次（§1.1）。编码那一叠 JSON 与两次重绘落在端到端墙钟与
`load_ms + ask_ms` 的差里（111 vs 120 ms），**小于测量噪声**。

**因此没有做「点某一手才算那一手」**（票面给的退路）：一整场 0.1 秒，那条退路会把一次点击
变成一百次点击，纯亏。

## 8. code-review（Standards + Spec 两轴，fixed point `mytpqkso` / `8597dabc`）

派不出 sub-agent，按 workbook 自己顺序跑的两轴。

### Standards

- **jj-only ✓**：全程 `jj st` / `jj diff` / `jj log` / `jj commit`，无远端操作。
- **工具强制的**：`fantomas --check`、`check-style.sh`、Biome、tsc 全绿；
  **`let mutable` 一处未新增**（那一叠回执用 `List.choose` + `Map.ofList` 收，不用可变累加器）。
- **F# 风格**（`docs/agents/fsharp-style.md`）：新代码是从左往右的数据流
  （`notes |> List.choose …`、`review.Answers |> List.choose (… >> Option.bind … >> Option.map …)`、
  `DecisionPackage.options package |> List.tryFind … |> Option.map …`）；
  `match` 一律穷举（`Consulted` 四态在 `stateWire` 与两处取值里各自表态，没有通配符分支）。
- **注释写「为什么」✓**：为什么那一格存的是包而不是「它打了什么」、为什么同不同按 id 比、
  为什么要有人按那一枚、为什么那一叠不上 `TableModel`、为什么是「一叠进一叠出」、
  为什么分歧不用朱红、为什么 `god_later` 挑的是最后一次**打牌**——都写在代码上。
- **术语 ✓**：`ReviewStrong` / `Consulted` 是渲染层的名字（同 `Bubble` / `ReviewNote`），
  日麻术语一个没自造；**`CONTEXT.md` 一字未改**（硬约束 5），提案见 §9 第 1 条。
- **ADR-0001 ✓**：中文只从 `toDisplay` 那一处出；闸门读的是 `data-*` 与 id，不从中文里认牌。
- **ADR-0002 ✓**：那一叠回执**不进牌谱、不进 `TableModel`**，换一席就丢。
- **ADR-0005 ✓**：新增的跨界口仍是「F# 调 TS、只传字符串」，回来的只有 id；
  TS 侧照旧构造不出 `Action`。
- **ADR-0006 ✓**：边界 1（懒加载）由那一枚按钮 + 闸门第 ⑩ 条守着，红-4 按红过；
  边界 2（降级不是 try/catch）由「算不动就整行不出现 + 页面明说原因」守着；
  边界 6（CI 覆盖不到什么）逐条写在 §5。
- **blocking：0。**

### Spec（票面 5 条行为 + 4 道闸门 + 4 条边界）

逐条对照见票文件的勾选框。四处值得写下来：

- **「分歧点在时间轴上看得出来」落成了「复盘那一列里一眼扫得到」**：复盘那一列本身就是逐手的轴
  （点一条就把票 75 那根轴搬过去）。**没有在时间轴控件上加标记**——那是
  `TablePanel` / `TableState` 的地盘，而票 89 正在那里改计时器与辅助档（派工单的硬边界）。
  留给人裁要不要在滑块上也标一排（§9 第 2 条）。
- **「它没坐这一桌时也能算」**：复盘那一层根本不问这一桌有没有强 AI 席——
  `Baseline.askAll` 自己会在需要时 `load()`，首页那份**四席都是模型**的回放里照样问得出来
  （§2.2 那 122 行就是它）。
- **「每一条对照都能复现」**：抽到的那几手问两遍同一个 id（⑬）。它**不带随机性**——
  探路件那个 `getrandom` 桩是确定性的（`probe/akagi-wasm/README.md` 坑 2），而这一层不洗牌。
- **「太慢就做成点某一手才算那一手」**：量出来用不着（§3），**因此没做**。

### 记录但没改的 nitpick

1. **问过之后没法「只看分歧那几手」**：一整场 122 行里 64 行是分歧，仍要滚很久。
   加筛选要一个状态，而这一票不往共享类型上加格子——与票 90 记的第 2 条 nitpick 同族。
2. **那一枚按钮不预告要下多少字节**（拉到了才知道是 5.8 MiB）：字节数得先拉一次才有。
   写死一个「约 6 MB」是第二份会漂的真源，因此没写。
3. **`verify-setup.mjs` 的文件头仍写着「十一趟共用一个浏览器」**（现在十七趟）——
   票 72 的文件，票 76/81/87/90 各记过一次，这一票同样没碰。
4. **闸门那一侧每问一手都从这一局的头重喂一遍**（与产品同一条路，见 `baseline.ts` 的注释）：
   122 手 64–83 ms，够快，因此没有为它做增量喂。
