## 1. 现场与根因（票 98 §4 第四类，没有重找）

引擎的 `declareKan`：**宣言不改局面**，因此被抢时无需回滚——那个杠只是没有发生而已。
而 fold 那一侧原来在 `Kakan` / `Ankan` 事件上当场就 `addKakan` / `addNaki`，于是：

```
 7 座位 0 对不上：others.1.tehai_count、others.1.naki
 7 座位 1 对不上：self.tehai、self.tsumo、self.naki
   引擎那侧：0:13 张[] 1:11 张[Pon] 2:13 张[] 3:13 张[]
 8（终局）同上 —— 抢杠已成立，那个杠永远不会成立了，fold 那份仍显示着它
```

**判据锚点是 `ObservationFixtures.mismatches`**：它拿引擎的 `GameState` 当锚，那一侧既不掩蔽也不 fold，
因此对不上只可能是 fold 那侧错。**修的是 fold，不是断言。**

**顺带修掉的第二处分家（票 98 没抓到，本票的探针在第三条轨迹上抓到）**：一发。
引擎在 `applyKan` 里打断一发，fold 原来在宣言那一刻就打断了——于是「杠宣言了、还没成立」
那一刻，引擎说一发还亮着，fold 说没了。见 §6.3 的反向自证。

### 2.2 再绿（改了什么语义）

`SeatStream` 多一个字段：

```fsharp
/// **宣言了、还没成立的那个杠**（抢杠那个窗口）：谁宣言的，与拼出来的那组副露。
DeclaredKan: (Seat * Naki) option
```

- `Ankan` / `Kakan` 事件：**只记不动**（`DeclaredKan <- Some(actor, naki)`），
  抢杠的 `PendingRon` 照旧当场算——判据里的手牌本来就没变；
- 下一条事件进来时先跑 `settleDeclaredKan`：
  - **被抢了**（`Hora`，或 `Ryuukyoku` 且形态是 `SanchaHora`）→ 原地作废，什么都不改；
  - **其余每一条** → 杠成立：`addKakan` / `addNaki`、他家那侧 `withNaki`、并 `interruptIppatsu`。
- 「其余每一条就是成立」凭什么：杠一成立引擎当场接上翻宝牌与补摸岭上牌（`completeKan`），
  **宣言之后不可能什么事都不发生**。四杠散了不在此列——它要等杠的那家打完一张才判
  （`Ryuukyoku.afterDahai`），那时这个杠早已落定。

**碰 / 吃 / 大明杠拆去了另一支**：它们是对打牌的响应，而响应收齐才产事件——事件播出去那一刻
引擎早已落定，因此照旧当场就改。原来五种鸣牌共用一支，正是这一段把「宣言」与「既成事实」
混成了一件事。

**这一段没有改任何断言。** 六条属性因此转绿（`Masked/不出现他家暗牌` 转不绿，见 §5）。

## 5. 术语建议：「宣言中的暗杠」是公开信息吗（**只出建议，`CONTEXT.md` 一个字未改**）

### 5.1 事实

国士抢暗杠时，`MaskedStreamProperties.任意局面任意座位，掩蔽流里不出现他家暗牌中的任何一张`
在那个窗口里**红**，而且**修 fold 修不到它**：

- 它比的是**掩蔽事件流**（`MaskedEvent.tiles`）与**引擎状态里这个座位看得见的牌**；
- 掩蔽流里那条 `Ankan(actor, [7z;7z;7z;7z])` 带着四张牌面（`MaskedEvent.forSeat` 把 `ankan` 原样放行，
  `MaskedEvent` 的注释白纸黑字写着「暗杠不在掩蔽之列……国士抢暗杠这条规则的前提就是它看得见」）；
- 而引擎那侧，**宣言不改局面**，这四张仍在 `PlayerState.hand` 里 —— 于是「他家看得见的牌」不含它们。

**两边都对，错的是词**：这四张在那一刻**必须**亮给别家看（不亮就没法决定抢不抢），
但引擎里没有地方安放「亮着但还没进副露」这个状态。

### 5.2 建议的措辞（供裁决，我没有改任何文件）

在 `CONTEXT.md` 的 `MaskedEvent` 词条里，把那句「暗杠不在掩蔽之列」从**旁白**升成**不变量**，
