### 牌山怎么重建（本票技术上最要紧的一块）

**没有新造注入机制**：把一列 136 张牌交给已有的 `Wall.ofOrdered`，开局走 `GameState.startFrom`。
难的是把牌谱的观测摆回牌山的物理位置：

```
[配牌 52 张，按 4-4-4-1 的取牌手顺倒推位置]
[可摸区的每一次自摸，按顺序]
[没露过面的牌补满可摸区]        ← 每杠一次，末尾这一段就被 drawRinshan 顶进王牌一张
[岭上牌，按补摸顺序]            ← 「紧跟在杠后面的那次自摸」就是它（中间可能夹一条 dora）
[（表, 里）成叠的指示牌，牌谱公开了几张摆几张，其余用余牌顶上]
```

余牌 = `Ruleset.wallTiles` 减掉全部露过面的牌。**多一张少一张都会当场报错并把这一局显式跳过**
（把 `Akadora` 关掉重跑，171/177 局立刻报「牌谱里露过面的牌凑不进整副牌」——机制自证有效）。

### 重放驱动

牌谱事件分两类：**引擎自己会产出的**（`tsumo` / `dora` / `reach_accepted` 与三条 game/kyoku 级）
跳过不提交，其余按引擎当前阶段提交对应 `Action`：

- 摸牌后阶段：`dahai` / `reach` / `ankan` / `kakan` / 自摸 `hora` / `ryukyoku`（只可能是九种九牌）
- 响应阶段：按引擎等答复的顺序逐座位交出牌谱里的宣言（荣和 / 碰 / 吃 / 大明杠），**没宣言的交「过」**

役与三种宝牌不在 `Hora` 事件里，因此每次和了都在**提交动作之前**先 `GameState.horaOf` 把读法记下来。

## 三、独立锚点：荒牌流局逐座位对拍天凤清算

备注 N-10 的要求：**期望值不能来自我们自己的实现**。这一条的期望值是天凤自己的钱流——
收听牌料的听牌、付的不听，与我们的实现无因果关系。

- **固件 72 座位、扩样本 1316 座位，0 处不一致。**
- 其中钱流直接反推的：固件 60 座位（15 局 `流局`）、扩样本 1156 座位；
  其余是天凤写明 `全員聴牌` / `全員不聴` 的零授受局（那时钱流全 0，反推不出来，取 oracle 的字面结论）。
- 九种九牌那几局的 `Tenpais` 记的是「谁亮了手牌」而不是「谁听牌」，**不参与这条对拍**（会误判）。
- R-3 研究在 72,204 个座位上做过一次但**用的是 Python 移植版**；本票用真引擎重做，
  规模小两个数量级，但证据强度不同：这一次跑的是会被 Fable 编译进浏览器的那份代码。

**没有 oracle 时这条锚点仍然成立**——它读的是 mjai 流自己的 `ryukyoku.deltas`。
只有 mjai 的大样本因此不必现取天凤 JSON。

## 四、日文役名对照表

`OracleYaku.japanese : Yaku -> string` 写成**穷尽 match**，因此「表漏了某个役」
由编译器保证不可能发生（`Yaku` 加 case 时这里当面报错）。

- 覆盖 `Yaku` 的全部 **43 个 case**；三个带参数的 case 各自展开（役牌 3 种、场风 4 种、自风 4 种）
  → **51 个具体役名**，两两不同，反向解析全部回到同一个役（有断言钉着）。
- 三种宝牌（`ドラ` / `裏ドラ` / `赤ドラ`）在天凤是役行、在我们的 `Yaku` 里不是，**单列**，
  与 `YakuTally` 的 `Dora` / `Uradora` / `Akadora` 三个计数比。
- **没有一个对不上**：两批语料 3116 行役全部落进表里（表里没有的役名会让整局显式跳过并计数，实际发生 0 次）。
- 两批语料真正走到的是 32 种：立直 735、門前清自摸和 428、断幺九 383、平和 353、役牌 中/白/發 422、
  一発 140、混一色 78、場風/自風 281、一盃口 64、三色同順 58、七対子 58、対々和 24、一気通貫 23、
  三暗刻 17、清一色 14、海底摸月 9、混全帯幺九 9、嶺上開花 7、両立直 5、河底撈魚 3、二盃口 2、
  槍槓 1、**大三元 1（唯一一次役满）**、純全帯幺九 1。
- 表里其余 19 种（国士、四暗刻、天和地和、四杠子、绿一色……）**语料零出现**，靠黄金用例守。

## 五、差异（本票的产出）

三处，按票里要求的三类分：

### ① 我们的 bug：立直宣言牌换了听牌，振听没被解除 —— **已修**

**症状**：牌谱里一家立直后荣和，引擎却连响应机会都不给（`重放` 类差异 2 处 / 2110 kyoku）。

**根因**：`PlayerState.refreshFuriten` 的闩死判据用的是 `RiichiState.isActive`，
而它对 `Declared`（宣言了、宣言牌还没落定）也为真。于是「**振听时立直、用宣言牌换掉听牌**」
这个常见手筋被闩死了：宣言牌那一手手牌还在变，振听本该重算解除。

样本里的实例（`2026010621` 东 3 局座位 0）：立直前听 `2m/5m/8m` 且自己河里有 `2m` → 振听（对）；
摸进 `9s` 立直打 `8m` 之后只听 `9s`，河里没有 `9s` → 天凤让荣和成立，我们不让。

**改法**：`isActive` → `isAccepted`（1 个标识符）。宣言牌那一手（`Declared`）不闩死，
立直**成立之后**照旧只置位不清除（那之后手牌不再变，闩死是为了留住「立直后见逃」那一位）。
`minogashi` 一字未动。

**验证**：541 个测试全绿（一条既有断言都没改）；扩样本的这 2 处差异消失，和了次数 1770 → 1772。
`RiichiTests` 里另加了一条摸好牌山的回归用例（「振听时立直，宣言牌换了听就解除振听」）：
把修复撤回去它就红（实测过）——对拍靠大样本才拓到这条路，而 CI 里只跑固件，没这条用例就守不住。

### ② 我们的 bug：**明杠的新宝牌指示牌翻早了** —— **未修，留给人裁**

**症状**：加杠 / 大明杠之后**当场岭上开花**时，引擎多翻一张表宝牌指示牌，
牌谱里根本没有那条 `dora`。2 局 / 2110 kyoku，其中 1 局**点数因此算错**：

```
2026011000gm-00a9-0000-6575fe32 南 1 局 1 本场
  牌谱   hora 1 1  -1400,+3000,-800,-800     （40符2飜 700-1300）
  引擎   dora 3z → hora 1 1 -4100,+8300,-2100,-2100   （多两番宝牌 → 满贯）
```

**根因**：`GameState.completeKan` 对三种杠都在补摸岭上牌之后立刻翻。真实数据（218 局）说得很清楚：

| 牌谱里的顺序 | 次数 |
|---|---|
| `ankan` → `dora` → `tsumo` → …（含 `→ hora` 6 次） | 116 |
| `kakan` / `daiminkan` → `tsumo` → **`dora`** → `dahai` | 87 |
| `kakan` → `tsumo` → `hora`（**没有 `dora`**） | **2** |
| `kakan` → `hora`（抢杠，杠没成立） | 1（引擎行为正确） |

即天凤是「**暗杠立刻翻，明杠等到打牌那一刻才翻**」。没有打牌（岭上开花）就不翻。
**暗杠那一支我们是对的**（6 次岭上开花后的暗杠宝牌都算上了，逐项相符）。

**为什么不在本票修**：改法要给 `GameState` 加一个「欠着几张明杠宝牌」的状态、
在 `applyDahai` 开头补翻，**并且要改 `KanTests` 里两条断言的期望值**
（`[Minkan; Tsumo; Dora]` 与 `[Tsumo; Dora]` 会变成杠那一步只出前两条、`Dora` 落到打牌那一步）。
整条事件流的顺序其实一字不变，变的只是「哪一次 `step` 吐出它」——但那是改别的票的既有断言，
RUNBOOK 的红线在那里。已写进 `DECISIONS.md` 的提案 13-B 待裁。

**影响面**：明杠 + 当场岭上开花，实测 2/2110 kyoku（0.09%），其中影响点数的 1 处。

### ③ 牌谱侧：上游转换器把双响的 `ura_markers` 抄在两条 `hora` 上

6 处 / 2110 kyoku，**全部是双响**，且后一家根本没立直。两边的**钱流一字不差**——
说明我们的处理（里宝牌只给立了直的那家、点数不受影响）是对的，上游多写了一份。

处置：对拍时按**牌谱自己的** `reach_accepted` 把这份噪声抹掉（判据取自牌谱而不是引擎，
立了直那几家的里宝牌照比不误）。写在 `PaifuReplay.denoiseUra`，附实证数字。

## 六、样本没走到的地方（别被「零差异」骗了）

对拍只能证明它跑到过的东西。以下规则在**两批语料里一次都没出现**，
拨错了也报不出差异（变异测试实测 0 差异）：

- **连风牌雀头符**（`DoubleKazeJantouFu`）：语料里的连风全是**刻子**（場風+自風 各计一番），
  从来没有连风牌当**雀头**的和了。
- **岭上自摸的自摸符**（`RinshanTsumoFu`）：唯一那次嶺上開花是跳満，天凤不写符 → 比不到。
- **国士抢暗杠**（`KokushiAnkanChankan`）、**三家和了**（`SanchaHoraRyuukyoku`）、
  **流し満貫**、**四杠散了**、**四家立直**：语料零出现。
- 役满只有 1 次（大三元），**役满的符 / 番天凤不写**，因此役满那条路只对拍到了和了点与役种集合。

其中两条另加了单元测试兜底（样本零出现，靠断言守）：
**流し満貫的 deltas 档位判据**（`{0,±1000,±1500,±3000}` vs `≥4000`）与**三麻 `nukidora` 的识别**。

## 八、给 14 票（soak）的提示

- **N-8 / N-21 的覆盖率问题在这里得到了另一种解法**：真实牌谱一次就走到了 32 种役、
  四种流局形态里的三种、双响、抢杠、海底河底、大明杠、役满。soak 的随机 Player 走不到这些，
  但对拍走到了——两者互补，别指望 soak 覆盖役种。
- **soak 若把 hora 偏好打开，会走到刚修的那条振听路径**（立直换听解振听）。修之前那条路是
  「引擎默默不给荣和」，soak 只会看到「和了次数偏少」，看不出错——所以这个 bug 只可能由对拍抓到。
- **明杠 + 岭上开花那条路目前是错的**（提案 13-B）。soak 若断言「点数与钱流自洽」不会报，
  因为引擎自己前后是一致的；只有对外部事实对拍才报得出来。
