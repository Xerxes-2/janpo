## 1. 闸门是什么形状：**溯源**，不是**措辞**

旧那道逐项对拍是**逐字段**比：向听 / 进退向 / 有效牌 / 危险度各一条 `Assert.Equal`（或 `same(...)`）。
它证明「**这几个**数没被改」，**不证明「没有第五个数被凭空加上去」**——这正是票 104 红-7b 的缺口：
往每一行末尾拼一个「总分 82」，整套 `ci.sh` 全绿。

⑯ 换一个问法：**这个数是谁的。**

1. 从**引擎那一份**（浏览器侧走 `ReviewCheck.expected` 这条独立路，dotnet 侧读 `ReviewNote` 上的
   `Scaffold` / `Trial` / `Better` 那几格）算出这一行**该印出来的那一串数，按顺序**：
   手序 → 这一手本身（牌名里的数字）→ 打之前的向听 → 打之后的向听 → 有效牌枚数 → 种数 →
   第几安全；第三句里每一条候选再来一轮（那一张 → 它的有效牌 → 多几枚 → 向听更好）。
2. 从**画出来那一句话**里把每一个数抠出来（`/[+-]?\d+(?:\.\d+)?/g`）。
3. 两串**逐个相等**，否则红，并把「哪一格 = 哪个数」整张表印在红里。

三个性质值得点名：

- **它认的是「数」不是「词」**：措辞怎么改都不动它（把「有效牌 20 枚 7 种」改成
  「有效牌 20 枚（7 种）」照样绿），而多一个数就红——**不论那个数有没有名字**。
- **「没有数」也是一格**：`听牌` / `和了` / 字牌 / `危险度 无依据` 印出来一个数都没有，
  来源表里就摆一个空串。于是「把听牌那一行悄悄写成 `0 向听`」同样红。
- **形状是白名单**：以后真要往复盘上加一个新的引擎量，得在**两处**各写一格来源
  （JS 一处、F# 一处）。这是有意的代价——那一格就是「谁批准了这个数」的签名。

**黑名单留着当第二道**（票面允许）：`ReviewTests.forbidden` 那 12 个词、
`verify-review` 里「暂无 / 评分」那一段，一条都没删。

**为什么强 AI 那一行的执行者在 dotnet 侧**：CI 里那 6 MB 产物不在场（ADR-0006 边界 6），
页面上那一行**根本画不出来**——写在浏览器闸门里等于一条永远执行不到的断言（判据 3）。
dotnet 那条用例拿五种情形各造一行（你打的排第 2 / 不在那几条里 / 中间一条认不出 /
末一条小到两位写不出 / 上游没给分布），把概率、条数、排第几逐个溯源。

## 4. 定义域的边界（读的人要知道）

- **档位那类词不在这条判据里**：`危险度 现物 / 筋 / 壁 / 无依据`、`（退向）`、`与你不同`
  都是词不是数，它们由旧那道逐字段对拍（`data-review-danger` 等）与那张黑名单守着。
  这一条只管「数」。
- **`ShantenDelta` 印不出来**：那一句写的是「2 向听 → 3 向听（退向）」，进退向本身没有数字形态，
  因此它不在来源表里（它另有 `data-review-delta` 逐项对拍）。
- **引擎自己那一层的渲染不在这里守**：`Action.toDisplay` 里的牌名数字是拿引擎那一份 label
  当来源认领的，因此「往引擎的 label 里塞一个数」这条路它拦不住——那属于 ADR-0001 的渲染出口，
  由引擎侧的用例守。这一票只管**复盘这一层**（票面边界：不碰引擎）。
- **强 AI 那一行在 CI 里只有 dotnet 侧的执行者**（见 §1 末段）。本机演习那一档
  （`node scripts/verify-review.mjs --asset`）今天也不核那一行的数——**没写**，
  理由同样是判据 3：那条路在 CI 里执行 0 次，写了也没人替它兜底。留给人裁（§⑦ 第 2 项）。

## 5. 顺路两件的证据

**① 叙述行里的勾必须由数据决定**（`scripts/check-narration.sh`，接进 `ci-web.sh` 的静态闸门段）：

- 判据两条：一个字面量 `✓` 要么**在判决之后**（同一个顶层函数里先 `return failure(…)` /
  手验那几份的 `process.exit(1)`），要么**在条件分支里**（最近的那个块头是 `if (…) {` / `} else {`）；
  两样都不是就红，并把 `tick` / `mark` / `markerSince` 三个助手指给你。
- 另盯一条：**`✓` 这个字符的真源只许有一处**——`browser-lane.mjs` 的 `tick`。
- 先红两次（红-5a / 红-5b），复原后仍绿。**106 改好的那 9 处一处都没动**
  （`jj diff` 里 `browser-lane.mjs` 与那 9 份文件一个字节都没改）。
- 今天扫出的 67 处**一处都没改写**：它们本来就在判决之后或分支里（与 106 报告 §④ 的结论一致）。

**② `ReviewCheck.fs` 那句「十七趟」**：改成**不写数**的那一种——
「会把**同一条跑道上其余那几趟**一起搞挂」（与 `verify-review.mjs` 里同一句话的措辞一致）。
并且**给它配了执行者**：`check-single-source.sh` 的跑道名单里加上 `src/Janpo.Web/ReviewCheck.fs`
（它就是 `verify-review.mjs` 的 F# 那一半），名单的那条自检算式改成 `lane_fixed`
（原来写死的 `- 3` 会因为多一份基准文件而失真）。红-6 是它的反向自证。

票面（顺路件 1）写的是：**「`web/scripts/verify-*.mjs` 里不许出现字面量 `✓`（助手之外），有就红」**。
**照字面做会红在今天的仓库上**：`verify-*.mjs` 里有 67 处字面量 `✓`。

我核过每一处（脚本核的，不是眼看的）：**它们全都在判决之后（62 处）或条件分支里（5 处）**
——与票 106 报告 §④ 的结论一致。照字面实现要做的事是：

- 把判决之后那 62 句改成 `mark(problems)`：那一刻清单必然是空的，**是 60 多条恒真式**；
  而这个仓库刚在判据里记下「**属性测试是恒真式**」是最难发现的一类假绿（判据清单开头第六例）。
- 那 5 处分支里的要改成 `tick(true)`，同样是恒真式。
- 而且要动 16 份**别人票的文件**（硬约束 6：干票时只动自己票里的文件）。

因此闸门守的是**同一件事的可执行形态**：「**每一处勾都指得出谁决定了它**」。
它照样红在票面点名的那一幕上（红-5a：飞行中无条件打印一个勾），而不制造恒真式。

**被否决的另外两种**（106 报告里也否过，理由这里补上执行细节）：

- **一趟红了它印出来的行里不许有 `✓`**：与「每一项各打各的勾」冲突——`verify-setup` 第 ⑥ 项
  真过了就该打勾，哪怕第 ③ 项红了。
- **按份数记一个预算（像 `let mutable` 那样锁住当前值）**：能拦住新增，但**拦不住说谎的那一种**
  （在分支里新增一个诚实的勾同样要改预算，而把预算 +1 是一个没有信息量的动作）。

**这条偏离的裁量权留给人**：真要一律禁，做法是另立一票，把 67 处逐句改成
`markerSince` / `tick` 的**飞行中**写法（那才是有信息量的改法，而不是把它们改成恒真式）。
