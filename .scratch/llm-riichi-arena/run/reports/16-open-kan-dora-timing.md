# 16 票 —— 明杠的新宝牌翻开时机

**STATUS: done**（13 票留下的提案 13-B 落地；扩样本对拍 **8 处差异 → 0**，不引入新差异）

一句话结论：**`GameState` 加一个「欠着几张明杠宝牌」的整数字段，`completeKan` 置位、`applyDahai` 消费**。
整条事件流的顺序一字未变，变的只是**哪一次 `step` 吐出 `Dora`**——于是「明杠之后当场岭上开花」
再也翻不到那一张，那一手也就吃不到它。**541 → 543 个测试，CI 39s（无回归）。**

---

## 一、改了什么

引擎侧一个文件、三处（`src/Janpo.Engine/GameState.fs`）：

| 位置 | 改动 |
|---|---|
| `type GameState` | 新增字段 `PendingKanDora: int` —— 明杠欠着还没翻的指示牌张数 |
| `completeKan` | 暗杠照旧当场 `Wall.reveal`；**明杠只把欠账加一，不翻**（`revealing` 恒为空） |
| `applyDahai` | 开头 `revealPendingKanDora`：把欠的逐张翻出来、欠账归零，`dora` 排在 `dahai` 之前 |

**谁置位谁消费**：`completeKan` 的明杠支路（大明杠走 `applyNaki`、加杠走 `applyKan`，两条都汇进
`completeKan`）置位；**唯一的消费点是 `applyDahai`**，也就是「明杠等打牌那一刻才翻」这条规则本身。
`ofStarted` 初始化为 0，别处一律 `{ state with ... }` 继承。

事件顺序对照（左边是改动前，右边是改动后）：

```
暗杠     ankan  → dora → tsumo                     ankan  → dora → tsumo          （一字未改）
明杠     kakan  → tsumo → dora │ dahai → …         kakan  → tsumo │ dora → dahai → …
                              ↑ step 边界                        ↑ step 边界
明杠+岭上开花  kakan → tsumo → dora │ hora         kakan → tsumo │ hora      ← 那一张压根不翻
```

**wire 名与字段一字未动**（`Event.Dora` / mjai `dora` / `dora_marker`），`Event.fs` 没碰。

### 为什么不放进 `KyokuFlags`

那份记录的注释写明「每一次迁移都把四个标志重算一遍」，而欠账**必须跨迁移留着**
（杠 → 补摸 → 可能再杠 → 打牌，中间隔着好几次 `step`）。放进去等于每次迁移都要记得搬运它，
正是那份注释想避免的坑。所以它是 `GameState` 的一个字段，与 `Kyotaku` 同级。

## 三、改了 `KanTests` 的哪几条断言，各自的理由

票明确授权改这里。**一条都没删**；下面前两条是改期望值的，其余是**只增不改**。

### ① `大明杠：先补摸岭上牌再翻新宝牌` → **改名 + 改期望值**

- 原断言：`[ Minkan; Tsumo; Dora ]`。
- 现断言：`[ Minkan; Tsumo ]`，接着**断言下一次 `step`（那家打牌）吐出 `Dora` 且排在 `Dahai` 之前**，
  并比对翻开前后的 `Wall.doraIndicators`。
- **理由**：这条测的就是「翻牌时机」本身（名字直说了），而那个期望值被 218 局真实牌谱证伪。
  留着原名字等于让文档说谎，所以连名字一起改成「新宝牌欠到打牌那一刻才翻」。
  **它没有变弱**：原来只钉一步，现在钉两步（欠着 + 补翻），还多钉了指示牌的实际张数。

### ② `加杠：原来那组碰**原地**升成杠，副露数不变` → **只改事件模式**

- 原断言：`[ Tsumo(actor, _); Dora _ ]`；现断言：`[ Tsumo(actor, _) ]`（失败消息同步改）。
- **理由**：这条测的是**杠的连带效果**（加杠原地升级、`taken` / `fromKawa` / `target` 三个字段、
  `kanCount = 1`），事件模式只是顺带断言。时机本身由 ① 与新增的 ③ 负责，这里不重复。

### ③ 新增：`加杠后当场岭上开花：新宝牌一张不翻，那一手吃不到它`（票要求的回归用例）

摊牌山构造出 13 票在真实牌谱上抓到的那个组合（`kakanRinshanScript` + `kakanRinshan`）：
座位 1 碰 5s → 摸进第四张 5s 加杠 → **没人抢得了** → 岭上牌正是它单骑听的 1z。
王牌是摆死的：开局指示牌 `2z`（宝牌 3z，它一张没有），**欠着的那张是 `4s`（宝牌 5s，而它刚杠了四张）**。

| | 番 | 点 |
|---|---|---|
| 现在（不翻） | 岭上开花 1 + 一气通贯 1 + 赤宝牌 1 = **3 番 40 符** | **5200**（`[-2600; 5200; -1300; -1300]`） |
| 撤掉修复（翻） | 3 + 宝牌 4 = **7 番** | **12000（跳满）** |

与真牌谱那局 `2700 → 8000` 是同一个错，只是摊得更狠一点，好让断言直接钉在钱上。

### ④ 新增：`大明杠之后没打牌就又暗杠：暗杠那张当场翻，大明杠那张仍欠到打牌`

两种时机同时在场的唯一形态，**两批语料 2110 局里一次都没出现过**。取最保守的一种
（欠账累加、打牌那一刻一次翻光），见 DECISIONS 的 16-B。用例把这个选择钉住：
暗杠那一步 `[ Ankan; Dora; Tsumo ]` 且指示牌 2 张，打牌那一步补翻到 3 张。

### ⑤ 四条既有用例**只加断言、不改期望值**

| 用例 | 加的断言 | 为什么 |
|---|---|---|
| `岭上开花：补摸的那张和了` | 暗杠后指示牌 **2** 张 | 钉住「暗杠是当场翻」——票的第一条验收（现状正确，加用例守住） |
| `一局里连着三个杠` | 三个暗杠后指示牌 **4** 张 | 同上，且证明暗杠一张也不欠 |
| `大明杠后的岭上开花：喂杠的那家一家付光` | 岭上开花时指示牌仍 **1** 张 | 大明杠那一支的「不翻」（③ 是加杠那一支） |
| `抢杠：荣和优先于杠的完成` | 终局指示牌仍 **1** 张 | 票的验收：抢杠时杠没完成，自然也不翻 |

### ⑥ `KanProperties` 的「1 + 杠数」那条属性

- 原：`doraEvents = kans && 指示牌数 = 1 + kans`。
- 现：`doraEvents = kans − 欠着的 && 指示牌数 = 1 + doraEvents`。
- **欠账是从事件流独立数出来的**（最后一条 `dahai` 之后的明杠都还欠着），**不读引擎的新字段**——
  这条属性的价值就在于两条路径互相验证，读字段等于自己验自己。
  强度没变：欠账在打牌那一刻归零，因此「一局打下来每个杠恰好对应一张指示牌」照旧成立。
- **票点名要保住的那两条属性（王牌恒 14 张、可摸区每杠少一张）一字未动**，照旧全绿。

## 四、边界路径逐条确认

| 路径 | 结论 | 怎么确认的 |
|---|---|---|
| **抢杠** | 杠没成立 ⇒ 欠账都没记上，指示牌仍 1 张 | `declareKan` 被抢时压根不进 `completeKan`；用例断言 + fsi 实测事件流 |
| **四杠散了** | 第四个杠是大明杠时，`daiminkan → tsumo → dora → dahai → ryukyoku`，指示牌 5 张 | fsi 实测（既有用例照旧全绿） |
| 明杠 → 打牌 → **他家荣和那张** | 新宝牌**照算**（`dora` 在 `dahai` 之前翻，与改前同） | `applyDahai` 先 flush 再算 `responsesTo`，行为与改前逐位相同 |
| 明杠 → 打牌 → **荒牌流局 / 河底** | 先翻再流局；翻指示牌不动可摸区，`Houtei` 判据不受影响 | 既有用例 + 属性（可摸区守恒那条没动） |
| 指示牌叠数用尽 | 不产出 `dora` 事件，杠照样成立（同 `completeKan` 原有处置） | 常规规则集走不到（可杠次数 4 < 叠数 5） |
| 里宝牌 | 表里成叠翻，欠着时两边同时欠 ⇒ 张数恒等 | 属性里那条 `ura = dora` 未改，照旧全绿 |
