## 一、两处根因与修法

### A. 打牌前连着两次杠：明杠欠的那张指示牌，天凤在下一次杠**成立**时就翻

- **根因**：票 16 实现的「明杠欠到打牌那一刻一次翻光」在**连杠**时把第一杠欠的也一起
  推到最后。16-B 当时明写「语料零出现，取最保守的一种，有反例（哪怕一局牌谱）就改」——
  票 57 拿到了 28 局反例（全量 129,179 局里明杠打头的连杠 29 局，28 局与天凤不符）。
- **修法**（`GameState.fs`）：`PendingKanDora` 多一个消费点。原来只有 `applyDahai` 消费；
  现在 `completeKan` 开头先 `revealPendingKanDora`（**补摸岭上牌之前**还清前一杠的欠账），
  暗杠不经抢杠窗口、「宣言即成立」，因此 `declareKan` 无人能抢那一支也先还清、
  欠的那张排在 `ankan` 事件**之前**。事件顺序与天凤逐条一致：
  - `kakan → dora(前一杠欠的) → tsumo`（加杠 / 大明杠为第二杠）
  - `dora(欠的) → ankan → dora(自己的) → tsumo`（暗杠为第二杠）
  - 抢杠那一支不受影响（杠没成立，欠账不动）。
- 推论：欠账取值恒为 0 或 1（下一次杠也消费它），`PendingKanDora` 的文档注释同步改写。

### B. 大明杠 → 岭上开花的责任支付：天凤不采用，引擎原来写死

- **根因**：`GameState.sekininOf` 把「大明杠后岭上开花由喂杠者独付」写死。全量语料里
  这个形态出现 24 次，**24 次天凤都按常规自摸三家分摊**，连带 22 处终局点数错。
- **修法**：按调度器裁决做成 `Ruleset` 开关 **`MinkanRinshanSekinin`，默认 `false`（＝天凤口径）**，
  `Ruleset.withMinkanRinshanSekinin` 打开；JSON 键 `minkan_rinshan_sekinin`（随
  `kokushi_ankan_chankan` 的 snake_case 体例）。大三元 / 大四喜由副露凑齐的包**不可配、不受影响**
  （语料零出现，没证据，没动）。开关的代价很小（一个字段 + 一个条件），没有触发裁决里
  「代价明显大于收益就删掉」的分支。
- **命名**：CONTEXT.md 第 85/280 行的体例是 `Ankan / Minkan / Kakan`（大明杠的标识符是
  **Minkan**），前任起的 `DaiminkanRinshanSekinin` 违反体例，已改名（见第六节）。
  术语表要不要给这个开关收词：**只报不改**，提案在 DECISIONS「## 59」。

## 二、`KanTests` 的期望值为什么可以改（判据 5/6）

改期望值的只有票 16 新增的第 ④ 条「大明杠之后没打牌就又暗杠」：

- 旧期望 `[ Ankan; Dora; Tsumo ]` + 打牌时补翻，钉的是 16-B 那个「最保守选择」——
  **16-B 自己写明它是无语料时的猜测，且「有反例就改」**。
- 反例不是推断出来的：全量语料里「明杠欠账 + 暗杠收尾」的 4 局（加→暗 3、大明→暗 1）
  重放后与天凤**逐事件零差异**，而零差异只有在引擎按 `dora → ankan → dora → tsumo`
  吐事件时才成立——牌谱赢，断言改。新期望更硬：从「两步」钉到「四条事件 + 指示牌逐张核对」。
- 其余：`大明杠后的岭上开花` 那条按开关拆成两条（默认口径 + 开关口径），**点数从相对断言
  （`-hora.HoraPoints`）改成绝对数字**（3 番 40 符、5200、`[-2600;5200;-1300;-1300]` 与
  `[-5200;5200;0;0]`），王牌摊死使宝牌恒 0 番——比旧断言硬。新增一条「连着两次明杠」
  剧本用例钉 A 类的大头形态。`KanProperties` 的杠数属性加了 `pendingKanDora ≤ 1` 合取、
  欠账 fold 改为「下一杠也还清」，仍从事件流独立重算、不读引擎字段。
- **一条测试都没删，`PaifuDifferentialTests` 的阈值只往上抬**（87→96 场、900→980 局、
  和了 840、符 615、役行 1520、清算 490、终局点数 880、役种 35→**38**、荒牌 120、九种 12）。
