# 票 97：让立直那一族属性真的开口 —— 改前改后的两组数

**结论先说四句。**

1. **「有家立直中」的采样概率从 0.103% 抬到 11.18%**，一趟属性（100 个样本）至少开口一次的概率
   从 **9.80% 抬到 99.999%**。做法是往 `GameStateArbitraries.Traces` 里补三条**摊好牌山**的立直轨迹
   （三家立直到荒牌流局 / 四家立直 / 立直一发荣和），一条引擎代码没动。
2. **票 96 §6.2 那个洞补上了**：「立直中且有副露」这一类局面**改前全域 0 个**，改后一趟必开口
   （99.6%）。它靠一个新选手 `riichiKanSeeking`（能立直就立直、能暗杠就暗杠、**从不宣言和了**）
   与新剧本 `sanchaRiichiAnkanScript`。
3. **一族都没掉**。加轨迹必然稀释别人，因此顺手**调了两处权重当补偿**
   （`nakiSeeking` 4 → 6、`ankan` 1 → 2）：逐族对照下来，22 条关键局面的「一趟至少开口一次」
   改后**逐条 ≥ 改前**（探针最后一行会自己判这件事）。
4. **没有新反例**：引擎全量连跑 20 趟，750 条全绿（改前 749 + 本票新增的那条锚点）。
   本票**唯一改硬的地方**是新增一条 `[<Fact>]` 锚点；一条断言没放宽、一条属性的语义与 `MaxTest` 没动。

**顺带报一个别族的空转**（不是本票的地盘，只描述不编号，判据 17）：
`KanProperties.抢杠那一轮只有荣和与「过」，宣言杠的那家不在被问之列` 的非空分支
**改前改后都是 0 次**——引擎只在「真有人抢得了」时才进那个响应阶段（`GameState.fs:1559`），
而整个取值域里没有一次。详见 §6。

## 1. 测的是什么、怎么测的（判据 13：数字要说清条件）

探针 `scripts/fsi/arbitrary-coverage.fsx`（本票留下的，3.4 秒跑完），它对每一类关键局面报**两个数**：

| 名字 | 定义 | 用途 |
| --- | --- | --- |
| **穷举占比** | 全部局面里命中的比例（与种子无关的固定轨迹按 400 次计） | 与票 96 的「21.7 万里 104 个」同一个口径 |
| **采样 p** | `Σ_轨迹 (w/W) · 那条轨迹里它的密度`——**生成器真正的抽中概率** | 「一趟开几次口」只认这个 |

`GameState()` 的抽法是：均匀取种子（1..400）→ 按权重取一条轨迹 → 在那条轨迹里均匀取一步。
因此**穷举占比 ≠ 采样 p**：短而密的摊好轨迹在采样里的份量远大于它的局面数。

> **一条要写明的对账**：票 96 报的「0.103%」看着像 104/217,574，其实那是 **0.0478%**；
> 0.103% 正是本票这份探针算的**采样 p**（两份独立探针逐位吻合：局面总数 217,574、
> 「有家立直中」104、p = 0.1031%、一趟 9.798%）。**两条路径互相对上了**，只是当初那个数
> 该叫「采样概率」而不是「占比」。

「一趟至少开口一次」= `1 − (1 − p)^100`（FsCheck 默认一趟 100 个样本；本生成器不看 `size`，
`Gen.choose` 与 `Gen.frequency` 都与 size 无关）。

**算出来的概率还用抽出来的次数复核过**（同一件事两条路径）：真拿 `GameStateArbitraries.GameState()`
抽 100 趟 × 100 个样本，`riichi-active` 实测 11.43%（解析 11.18%）、`riichi-response` 0.57%（解析 0.61%）、
`riichi-ankan-offered` 0.13%（解析 0.16%）。

## 5. 新的定点锚点（判据 1：先证明它红得起来）

`RiichiProperties.摊好牌山的三条立直轨迹：每一类立直局面都到过，六条不变量逐步都成立`：

- **先自证覆盖**：六类关键局面（立直中且有副露 / 立直成立且轮到它打牌 / 宣言牌还没打出去 /
  被问荣和 / 立直后暗杠进了动作集 / 一发亮着）逐类 `Assert.True(hits > 0, …)`；
- **再逐步验六条不变量**——**跑的就是那六条随机属性的函数本身**，不另写一份
  （另写一份就会各自飘，那正是判据 3 抱怨的「看着在守」）。

两次反向自证（都当场红过，随后原样恢复）：

```
# 把「三家立直后暗杠」那条轨迹从锚点里拿掉：
失败 …摊好牌山的三条立直轨迹：每一类立直局面都到过，六条不变量逐步都成立
错误消息: 三条立直轨迹里一个「立直中且有副露（99.6%）」的局面都没有：这条锚点已经退化成空转了

# 往不变量表里塞一条永远为假的：
失败 …（同上）
错误消息: 三家立直后暗杠 第 0 步破了「临时的假不变量」（立直中的手牌：）
```

**票 96 那条锚点没动**，仍旧守着「立直中摸进和了牌那一手」——顺带查明：
三条新轨迹里**没有**那一类局面（`riichiKanSeeking` 从不宣言和了，也没摸到过自己的和了牌），
所以那条锚点不可替代。反过来说，把 `stillTenpai` 换回票 96 之前那一版时**只有 96 的锚点报红**，
新锚点是绿的——两条锚点守的是不同的局面，**都得留着**。

## 6. 顺带查出来的：一条从来没执行过的属性分支（不是本票的地盘）

`KanProperties.抢杠那一轮只有荣和与「过」，宣言杠的那家不在被问之列` 的非空分支
**在整个取值域里是 0 次**（改前改后都是；`chankan` 那一行）。

根因不是采样稀，是**引擎只在真有人抢得了时才进那个响应阶段**：

```fsharp
match responsesTo declaring (ResponseCause.Kan naki) actor pai with
| [] -> // 没人抢得了：当场成立，不经响应阶段
```

而取值域里的十三条轨迹没有一条造得出「加杠正撞上别人的和了牌且它不振听」。
现在守着这件事的是 `KanTests` 的具名用例（`kakanScript` / `kokushiChankanScript`）。
**本票没改它**：那是另一族的取值域问题，按判据 17 只描述不编号。
