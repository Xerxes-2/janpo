不是 `--tile-w` 那个变量的字面值。左右两家的牌转了 90°，一律记成「短边 × 长边」。

## 2. 为什么两档的差是从小档那边让出来的（不是把大档抬上去）

先量了一遍所看那一席那条边上的**预算**（1280×800、种子 2088、走到自家 3 组副露那一手）：

- 牌桌边长 512 px；那一席从最左一张牌到最右一张牌吃掉 **450 px**；
- 余下 62 px 里 **39 px 是让给下家手牌的那个角**（`.tiles.naki-row` 的 `right`）；
- **真正的空档只有 23 px**。而大档每抬 10%，一条边上 13–14 张牌就要多吃 ~45 px。

四杠那种极端更紧：一条边上是 18 张牌宽（4 组杠 16 张 + 手里剩 2 张），
今天已经是 `18 × 0.0468 + 0.0638 ≈ 0.906 × board`，加上组间缝几乎顶满。

∴ **大档抬不动**。两档的差因此从小档那边让：所看那一席**与改前一模一样**（零回归），
其余三家缩到 0.85。这样做还顺带给那三家各自的边腾出了空。

0.85 是量出来的两头之间：×0.90 时 1280×800 上两档只差 2.4 px（看不出是两档）；
×0.80 时窄档（1100×800，牌桌只有 272 px）的小牌落到 10.2 px，牌面那张 SVG 认不出花色。

## 3. 一处越界修正：副露让角让的是**下家**那一档

`.zone .tiles.naki-row { right: calc(var(--tile-h) + 0.4rem) }`（票 132 装的）
让的量原本按**自己**的牌高算。四席一般大时这没有区别，**两档一立就有了**：
上家那条边的右端接的正是所看那一席（大档）的手牌，按小档让就会短 5.9 px。
改成一律按 `--tile-h-near` 让：它是两档里较大的那个，让够了对四条边都成立。

这是「四条边首尾相接」这个几何里的**隐性耦合**（我的让位量取决于下家的尺寸），
从前被「四席一般大」掩着。逐席去问「我下家是哪一档」要在 CSS 里再长一份座位算术，
∴ 取保守的最大值，不长第二份判据。

## 4. 新增的闸门与它们各自怎么先红的

全部落在 `web/scripts/verify-home.mjs`，跑在**五个视口**上（`STAGE_VIEWPORTS`）。
读的是**画出来的真盒子**（`readZones()`），不是 `--tile-w` 那个变量——
变量改对了而牌没跟着变，正是判据 22 那一族。

| # | 断言 | 反向自证怎么做的 | 红出来的样子（节选） |
|---|---|---|---|
| ① | **扇到几席**（不是 4 席就红） | 把选择器改成旧名 `.seat-zone[data-seat]`（M5 假绿表末行那个形状） | `两档牌宽：1280×800 里量到 0 席（该有 4 席）——这一段整个空转了`（五个视口各一句） |
| ② | **每席都量到牌**（0 张就红） | 加 `.zone .tile { display: none }` | `两档牌宽：1280×800 里座位 0、1、2、3 一张牌都没量到——牌还没摆出来就量，这一段量的是空桌` |
| ③ | **所看那一席大一档**（大出 ≥5%） | **不必造**：改 CSS 之前它就是红的 | `两档牌宽：1280×800 里所看那一席（座位 0）的牌宽 24.0 px，而座位 1（shimocha）是 24.0 px（要大出 5% 以上）` ×15 句 |
| ④ | **牌不越出牌桌** | `.zone .tiles.hand { left: -2rem }` | `两档牌宽：1280×800 里座位 0（self）的牌探出了牌桌的左边（牌 337,500 → 825,646；牌桌 368,140 → 880,652）`（四席 × 五视口） |
| ⑤ | **没有一席的牌压到邻席** | 把大档比例翻倍（`0.0468 → 0.0936`） | `两档牌宽：390×844 里座位 0（self）的副露压在座位 3（kamicha）的手牌上（重叠 3×18 px）` |
| ⑥ | **同比缩放 · 大档** | `--tile-w-near: 1.5rem; --tile-h-near: 2rem`（写死 rem） | `同比缩放：大档（所看那一席）没跟着牌桌走——1280×800 上牌宽是牌桌的 4.69%（牌桌 512 px），1440×900 上却是 3.92%（牌桌 612 px）` |
| ⑦ | **同比缩放 · 小档** | `--tile-w-far: 1.2rem; --tile-h-far: 1.6rem` | `同比缩放：小档（其余三家）没跟着牌桌走——1280×800 上 3.75%，1100×800 上却是 7.05%` |
| ⑧ | **同比缩放那两条自己没空转**（比不到 2 个视口就红） | 与 ① 同一次破坏 | `同比缩放：大档（所看那一席）只量到 0 个视口（要 ≥2 个才比得起来）——这条断言空转了` |
| ⑨ | **视角一换大的那一档跟着换席**（阳性） | 把 CSS 选择器改成 `.zone:not([data-seat="0"])`（在 CSS 里另立一份「谁是主语」） | `换视角：坐到座位 2 之后最大的那一档还在座位 0 上（各席牌宽 0:24.0 1:20.4 2:20.4 3:20.4）` |
| ⑩ | **原来大的那一席缩回小档**（阴性） | 同上 | `换视角：坐到座位 2 之后座位 0 还是 24.0 px、不比新主语那一席（24.0 px）小——两席同时占着大档` |
| ⑪ | **上帝视角下大的那一档在起家** | 改成 `.zone:not([data-seat="1"])` | `换视角：上帝视角下最大的那一档在座位 1（该是起家 = 座位 0）` |

**⑥⑦ 是两条而不是一条**（票面要求的「按两档分别量」）：证据是破坏 ⑥ 时 ⑦ 仍绿、
破坏 ⑦ 时 ⑥ 仍绿——两条真的各量各的一档。

**⑨⑩ 钉在同一下拨动上**（判据 21）：同一张牌桌、同一手，先按「座位 2」，
阳性那半句（大档搬到座位 2）与阴性那半句（起家缩回去）读的是同一次 `readZones()`。
先红的是阳性那半句。挑座位 2 而不是座位 0：坐到起家上时两个答案重合，那一按什么都没证明。

**执行次数报出来了**（判据 3）：narration 里印着「跨席比了 **225** 对排」——
⑤ 那一条在一趟里真开了 225 次口，为 0 时那行数字自己会说。

## 5. 躲开的两种假绿（M5 那张表）

1. **量合数**：头一版的「不压邻席」拿**整席**的外接框两两相交——当场五个视口全红，
   而牌一张都没错位。原因：一席的三排（副露 / 手牌 / 河）围成一个 **L 形**，
   四家的 L 形本来就套在一起。改成**一排一个框**（与 `verify-board.mjs` 的
   `checkNoCrossSeatOverlap` 同一个办法）之后，改前改后都绿，翻倍破坏时才红。
   ——**这就是那张表头一行的形状，我踩了一次，是先看数不对才回头看图的。**
2. **扇空集**：①⑧ 两条就是为这一族准备的，每条都报「扇到几个 / 比了几个视口」。

另外 ③ 那条的阈值**写成比例（大出 ≥5%）而不是像素**：头一版写「大 1 px 以上」，
390×844 上大档 6.4 / 小档 5.4，差**正好 1.0 px** 而设计上差着 15%——固定像素在那里既是废话又假红。

## 7. 越界发现（交给调度器裁，我没动）

1. **所看那一席那条边的预算已经快用完了，而没有任何语料到得了最坏那一档。**
   实测 1280×800、3 组副露时用掉 450/512 px，真正的空档 23 px；
   而**四杠 / 四组副露**那种极端（一条边 18 张牌宽）**仓库里一份语料都摆不出来**——
   `verify-board` 的 `NAKI_CORPUS` 最多摆到 2 组，`checkNoCrossSeatOverlap` 自己
   在注释里也写着「不敢声称四组副露那种极端也验过」。
   这是判据 4 那一族：到不了的情形该显式写成代码里的一个值（造一份四杠定牌山的 fixture），
   而不是留在注释里当旁白。**这一票没做**（要动 fixture 与引擎侧的发牌，超出边界）。
2. **手机竖屏那一档的小牌只有 5.4 px。** 主人在票 119 时已裁过「缩到能看不能读」，
   两档之后小档更小。若那句诚实立场还算数，这里不必改；若要改，得先重开手机那一档的票。
3. `verify-home.mjs` 已经 1300+ 行、十四段验收挤在一个文件里。这一票又加了三段。
   要不要按「真布局 / 牌桌几何 / 首页内容」拆成三份，值一张单独的票。

## 8. review 结论

自跑 Standards + Spec 两轴（fixed point `46d18444`）：

- **Spec**：票面五条验收逐条对上（两档、由 `--board` 派生、跟着视角换席、
  「同比缩放」按两档分别量、「不压邻席」新增一条）；边界五条一条没碰
  （`--board` 算法、`--plate`/`--rail`/`--rail-right`、桌心、副露图例位置、四席旋转）。
  `src/Janpo.Web/` 与 `web/scripts/verify-board.mjs`、`TablePanel.fs` 一行未动。
- **Standards**：闸门只断言用户看得见的保证（判据 24）——大小关系、不越界、不重叠、
  同比不变，没有一条断言「必须用某个 CSS 属性」；每条新断言都报得出扇到几个 / 执行几次
  （判据 1/3）；测试只往更硬的方向改，一条都没删没放宽。
  nitpick（只记录不修）：`crossSeatPairs` 与 `tierProblems` 里的两两遍历是同一段循环写了两遍。
