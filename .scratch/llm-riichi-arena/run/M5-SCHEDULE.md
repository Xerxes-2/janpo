## 起草时纠正的一个错

我先给主人的切法是「**先立新闸门 → 再搬骨架 → 最后删旧**」。**这行不通**：
新闸门断言的是「舞台在视口内」「牌不越出牌桌」这些**今天不存在的结构**,
它们要么当场红、要么扇空集零次执行（判据里那条「0 次就停」）。

票 83 的做法才是这个仓库的成规：**改动与它的闸门同票落地**，
然后逐条改产品代码让它红一次（83 §5 反向自证九次、每次 EXIT=1）。
三票因此各自自带闸门，按**场景**切而不是按「闸门 / 实现 / 清理」切。

## 这一串的特殊风险：假绿

原型阶段我**写坏了四条断言，每一条都是先信了数、再看图才发现**。
它们的形状值得每个接票的人先读一遍（`NOTES.md` 里有全表）：

| 断言 | 怎么假绿的 | 改法 |
|---|---|---|
| 几何三数 | 舞台被 `transform-origin: 0 0` 顶出视口、名牌压在河上，**三数照样全绿** | 量「牌不越出牌桌」而不是一个合数 |
| 横牌朝向 | 拿屏幕坐标量，**拆旋转与不拆都报 3 枚** | 改量「牌面与它自己的盒子同朝向」（与席区旋转无关） |
| 列内溢出 | `display:none` 的卡片矩形全零，`top 0 < 58` 被当成溢出 | 滤掉零尺寸子元素 |
| 名字被截 | 选择器还指着旧名 `.nameplate`，**扇了一个空集**，永远报「无」 | 改对选择器，**并同时报扇到几个** |

**共同的形状**：断言存在、能跑、退 0，而它守的不是那件事。判据 22（假绿比假红更危险）。
∴ 三票的交付里都写了「每条新断言先红一次」，且 117 把横牌那条的正确写法**抄进了票面**。

## 已经查清、不必再查的

- `ReviewShown` 三态（`Hidden` / `Unaddressed` / `Notes`）决定**复盘只能画在「终局 + 座位视角」**那一屏；
  未终局时整块不在 DOM 里（对局中给「换打会怎样」算作弊）。票 118 的票面写了。
- 列宽 256 + 名字 11 px 是**最长的真实模型名**定的（`google/gemini-2.5-flash-preview` 要 166.4 px）。
  `deepseek/deepseek-v4-flash` 在旧尺寸下**只差 0.2 px**——那是巧合，不是设计。
- `@media (max-width: 39.99rem)`（票 44）**从来没被渲染过一次**：
  仓库里最窄的闸门视口是 1180 px。它与 README「也没有为手机屏幕适配」互相矛盾，票 117 删它。
- 借雀魂的几何，**不借它的绿绒**：颜色仍是票 80 的四色相，没动第五个色相。
