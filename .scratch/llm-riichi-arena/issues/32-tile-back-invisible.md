# 32 — 牌背在牌桌上是隐形的（22 号票的逃逸缺陷）

**What to build:** 他家的暗牌在牌桌上画不出来 —— `.tile.back` 同时设了 `color: transparent` 与
`background: color-mix(in srgb, currentcolor 25%, transparent)`，`currentcolor` 已经透明，
背景与边框也就全透了。围观者看到的是「手牌 10」后面一片空白。修好它，并重出 README 的截图。

这个缺陷躲过了 22 号票的验收：DOM 里元素齐全、测试全绿、无头截图也交了 —— **但没人真的用眼睛看那张图**。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 牌背可见：他家每一张暗牌都画得出来，且**一眼能与明牌区分**（别修成看着像明牌）
- [ ] 摸切的虚线、赤牌的红字、刚摸那张的间距等既有区分**一个都不许弄坏**
- [ ] 顺手扫一遍**同类隐形**：标签有、值空的地方（例如「立直棒」后面什么都没有），
      判断哪些是真缺陷、哪些是「值为零本就不该画」，把结论写进报告
- [ ] 重出 `docs/images/table.png`（围观视角、**不开上帝视角**，选一手有河有副露的局面）
- [ ] **自己用眼睛看那张图**，在报告里写明你看到了什么（几家的暗牌各几张、能否区分手切摸切）

## 边界

- [ ] **不做牌桌布局改造**（现在是四家竖排列表，观感像调试页）。那是 M2 的 UI 活，
      README 已经把它标成「最小牌桌」且全文 WIP。这一票只修**看不见**，不修**不好看**
- [ ] **不碰** `web/scripts/verify-*.mjs`（票 29b 正在改那些脚本的端口逻辑）；
      截图脚本的写死端口留给票 31 顺手清
- [ ] 不碰引擎、不碰 `web/src/agent/`、不碰 prompt

## 为什么单开一票

它是**已发布物**的一部分（README 首屏那张图），而 31 号票要动的是 prompt 与牌谱，两件事的验收方式
完全不同：这一票的验收标准是「人看图」，31 号的是「跑 CI 看数字」。混在一起前者一定被后者挤掉。
