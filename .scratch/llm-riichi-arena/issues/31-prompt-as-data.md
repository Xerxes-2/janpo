# 31 — prompt 降为数据、牌谱只存尾部、术语表追上新形态

**What to build:** 29b 把 prompt 的**形态**摆对了（固定 preamble + append-only 历史 + 尾部现况）。
这一票把它从**代码**降为**数据**：三段各自成为可替换的槽位，措辞与人格从配置注入而不必重编；
顺带把牌谱里那份「每手存一整段 prompt」的冗余削掉，并让术语表追上 29a 立起来的新形态。

**Blocked by:** 29b

**Status:** ready-for-human

## 一之二、prompt 从代码降为数据（主人 8/16 裁定）

现在措辞写死在 `prompt.ts` 里，改一句要重编；同档位的措辞全局唯一，没法让两个座位跑不同风格。
这一票本来就要重切渲染器，**顺手做成槽位注入是边际成本；等 M2 再做要把这一票刚写的再拆一次**。

- [x] 三段各自成为**可替换的槽位**：固定 preamble（人格与规则说明）、历史渲染、尾部现况与动作
- [x] prompt 成为**数据**：模板与措辞能从配置注入，不必改代码重编。
      默认模板仍在代码里（有个能跑的缺省），但不再是唯一可能
- [x] **座位级的人格/风格文本**：两个座位可以同模型不同人格，M2 的对照实验要它
- [x] **system 槽位**：固定 preamble 放进 system 消息（各家的缓存语义也更认这个），
      user 消息只留历史 + 现况 + 动作。注意这会改动缓存的边界，指标要能看出差别
- [x] 档位（Bare/Assisted）与人格是**两个独立维度**，别把它们缠在一个枚举里
- [x] **前缀稳定性测试要盖住新形态**：换人格文本不该破坏同一局内的前缀单调性
      （人格在 preamble 里，preamble 一局之内不变）

## 三、牌谱只存 prompt 的尾部（同一个错的孪生兄弟）

26 号票的 `DecisionRecord` 每手存 prompt 全文（实测 7 条记录 4.6 KB，单手 485–721 字符）
与 tools 定义全文（每手 437–513 字符、几乎逐字相同）。**prompt 是
(事件流 + 座位 + 渲染版本 + 脚手架档位) 的派生物，而事件流就在同一个牌谱里**——存它是把派生值当事实存。
快照式 prompt 下这只是浪费；**这一票落地后它变成 O(n²)**：第 n 手的 prompt 含前 n-1 手的历史，
一整场约 120 手决策，存下的 prompt 文本会是它所派生的那份事件流的二十几倍。

这一票让修复变免费——prompt 天然分成前缀与尾部：

- [x] `DecisionRecord` **只存尾部**（【现在】+【可选动作】+ 脚手架 + 重试原因），前缀不存
- [x] 记 preamble 与渲染版本号，使「前缀 = fold(事件流) 重新渲染」可重建
- [x] 提供重建函数并测试：重建出的全文 ≡ 当时真发出去的 prompt（**审计价值不许打折**：
      渲染器出怪的地方在尾部会原样留证）
- [x] tools 定义整份牌谱存一次形状，不每手存；每手只留那一手的动作 id 集
- [x] 版本号按 26 号定的规矩演进（加可缺省字段不涨版本，改含义才涨）；旧牌谱要照样读得动

## 三之二、渲染版本号（调度器裁决，收 29b-A）

29b 没硬塞版本号是对的：手写的数字没有任何东西保证有人改措辞时会 +1。**prompt 降为数据之后，
「模板 id + 内容哈希」是算得出来、漏不掉的版本号**，此时写进 `DecisionRecord` 才立得住。

- [x] 渲染版本 = 模板标识 + 模板内容的哈希（**算出来的，不是手填的**），进 `DecisionRecord`
- [x] 版本变了不需要 CI 变红，但 M2 看命中率掉时要能一眼归因到「换了模板」
- [x] 记清运维含义：**改渲染 = 废缓存**，而前缀属性测试只保证同一次运行内单调，不保证跨版本一致

## 四、术语表追上新形态（解 29a-B；**本票获准修改 `CONTEXT.md`**）

29a 立了两个一等概念，而 `Observation Projection` 词条现在的定义（「全局状态 → 某座位合法观测」的纯函数）
描述的是**改前**的形态。RUNBOOK 平时禁止 agent 改术语表，**本票是调度器批准的例外**，改动限于以下三处：

- [x] 重写 `Observation Projection`：现在的形态是「全局状态 → 掩蔽事件流 → fold → 观测」
- [x] 新增**掩蔽事件流**（某座位亲眼看得见的那条历史）词条，含 _Avoid_ 列表
- [x] 新增**它 fold 到此刻的累加器**（历史与观测同出一源）词条
- [x] 顺带核对 Scaffold Tier 词条里 28 号票写下的「事件序列在前缀、场况在尾部」是否与 29b 的实现一致
- [x] 收 29b-B 的三个新词：`Usage`（token 账单，含缓存读写）、**可缓存前缀 / 尾部**这对位置词、
      以及 29a 立起来还没进表的**掩蔽事件流**
- [x] **其余词条一个字都不许动**（只多改了 `DecisionRecord` 那一句——它就是第三节改的那个字段，记 31-6）
