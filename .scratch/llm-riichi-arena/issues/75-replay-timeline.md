# 75 — 回放的时间轴：自由拖动 + 逐事件步进

**What to build:** spec 的 story 17：在回放里沿时间轴自由拖动、逐事件步进，复盘粒度到每一手。
票 71 的回放只会顺着播；这一票给它一根**游标**。ADR-0002 说回放就是「对事件前缀做 fold」，
所以这里没有第二份状态：**游标是权威，局面是它的函数**。

**Blocked by:** 71（Live / Replay 接缝与首页回放已经在了）

**Status:** ready-for-agent

## 既成事实（省你半天）

- 前缀 fold 的入口已经有：`Replay.game ruleset events` 吃一条事件流，
  `Replay.ofPaifu` 是它加牌谱自己的规则集。**前缀停在某一局中间不是错误**（26-10 就是为它留的形状），
  中间某局没走完才是（`ReplayError.Stranded`）。
- 播放控制已经是纯值（`Playback`，含世代号）：回放模式的一记定时器就是「游标 +1」。
- 一整场（半庄）约 1600 条事件（本机实测：有主见 bot 一场 1617 条、事件流 79.7 KB）。

## 要什么行为

- [ ] 一根时间轴：拖到哪，牌桌就是那一处的局面；拖动过程中跟得上手（**给数，见下**）
- [ ] 逐事件步进：前一步 / 后一步各一个按钮
- [ ] 播放 / 暂停 / 倍速在回放模式照旧可用（复用 `Playback`，不要第二套定时器）
- [ ] 轴上看得出「现在是第几手 / 第几局」；跳到局边界的路要顺手（哪种形态你定）
- [ ] 游标动时「上一手是谁做了什么」跟着变；那一手**有决策记录时把它显示出来**（原文即可，
      好看的气泡是票 76）
- [ ] 拖到末尾 = 票 71 今天的样子（含结算面板与役种）；拖回 0 = 开局那一瞬

## 性能：先量再决定

- [ ] 量一次前缀 fold 的耗时（半庄的头、中、尾各几个游标位置），把数抄进报告
- [ ] **只有量出来卡手才做缓存**（每个游标一份状态、或按局分段）；做了也要给出改善前后的数。
      别一上来就造缓存——它是第二份状态，而这一票的整个卖点是「没有第二份状态」

## 闸门

- [ ] 拖到中间某个游标：断言此刻的手牌 / 河 / 点数与**直接 fold 同一前缀**得到的一致
- [ ] 幂等：同一个游标来回到达两次，渲染逐字段相同（这条能抓住「增量维护漂了」这类错）
- [ ] 拖回 0 与拖到末尾各断言一次（末尾要含结算面板）
- [ ] 每条断言先红一次，红的输出进报告

## 边界

- [ ] **不碰 Live 的推进逻辑**：Live 模式这一票一行不改（Live 里点历史某一手是票 76）
- [ ] 不碰 `Paifu` 格式、不碰 `web/src/agent/**`、不碰引擎的规则判定
- [ ] 不做键盘快捷键、不做动画补间（spec 明写动画预算后置）
- [ ] 导入文件与分享链接不在这一票（票 78）：这一票的牌谱来源仍是首页那份 Demo 资产
