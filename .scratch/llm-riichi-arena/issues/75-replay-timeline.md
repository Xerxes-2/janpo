# 75 — 回放的时间轴：自由拖动 + 逐事件步进

**What to build:** spec 的 story 17：在回放里沿时间轴自由拖动、逐事件步进，复盘粒度到每一手。
票 71 的回放只会顺着播；这一票给它一根**游标**。ADR-0002 说回放就是「对事件前缀做 fold」，
所以这里没有第二份状态：**游标是权威，局面是它的函数**。

**Blocked by:** 71（Live / Replay 接缝与首页回放已经在了）

**Status:** ready-for-agent

## 既成事实（票 71 已并入 `main`，**这一票比当初写票时简单得多**）

- **帧已经物化了**：`ReplayTable = Loading | Failed of reason | Ready of frames: Table list * cursor: int`。
  `Table.replay : Paifu -> Result<Table list, string>` 把牌谱 fold 成**逐帧的 `Table`**
  （一帧 = 一手，`Action.None` 也占一帧；帧数 = 手数 + 局数）。
  **所以拖动是 O(1) 取帧，不要再 fold 一次，也不要另造缓存**。
  本票原文那句「游标是权威、局面是它的 fold」仍然成立，只是 fold 已经在载入时一次做完。
- 渲染只有一份：`shown : TableModel -> Shown` 取第 `cursor` 帧，往下还是
  `TableBoard.tableBody model table`。**决策记录已经按手序切到帧上**（`record.Turn < table.Turns`）。
- 结算面板的役与符番已经有了（`HoraReading` 在 `Table.apply` 里捐的，Live 与回放同一条路）。
- 回放侧控件挂在 **`TablePanel.replayControls`**（Live 侧是 `hostControls`，**那是票 72 的地盘**）。
- 首页现在自动播（`Playback.playing Speed.X2`），256 帧 ≈ 1 分 17 秒；载入时 fold 46–74 ms。

## 要什么行为

- [ ] 一根时间轴：拖到哪，牌桌就是那一处的局面；拖动过程中跟得上手（**给数，见下**）
- [ ] 逐事件步进：前一步 / 后一步各一个按钮
- [ ] 播放 / 暂停 / 倍速在回放模式照旧可用（复用 `Playback`，不要第二套定时器）
- [ ] 轴上看得出「现在是第几手 / 第几局」；跳到局边界的路要顺手（哪种形态你定）
- [ ] 游标动时「上一手是谁做了什么」跟着变；那一手**有决策记录时把它显示出来**（原文即可，
      好看的气泡是票 76）
- [ ] 拖到末尾 = 票 71 今天的样子（含结算面板与役种）；拖回 0 = 开局那一瞬

## 性能：量两个更大的数

帧已经物化（票 71 的形态选择），拖动本身不会慢。要量的是**它能不能撑住更大的牌谱**：

- [ ] 拿一场**半庄**的牌谱（约 800 帧，是首页那份的三倍）跑一遍：载入 fold 耗时、首屏耗时、
      拖动跟不跟手，三个数抄进报告
- [ ] 量一下**内存**（票 79 要上的真资产带 thinking，约 2.5 MB / 250 手）：
      帧里那么多份 `GameState` 会不会把页面吐死。超了就写下数与阈值建议，
      **但不要在这一票重构帧的形状**（那是另一张票，且要先有数）

## 闸门

- [ ] 拖到中间某个游标：断言此刻的手牌 / 河 / 点数与**直接 fold 同一前缀**得到的一致
- [ ] 幂等：同一个游标来回到达两次，渲染逐字段相同（这条能抓住「增量维护漂了」这类错）
- [ ] 拖回 0 与拖到末尾各断言一次（末尾要含结算面板）
- [ ] 每条断言先红一次，红的输出进报告
