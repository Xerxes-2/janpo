# 91 — 强 AI 探路：把它编成 WASM，在浏览器里出一手

**What to build:** 主人拿到了 [`shinkuan/Akagi`](https://github.com/shinkuan/Akagi) 的授权
（**Apache-2.0**，V3 是 Rust + Tauri 单二进制，内置的是「a pure-Rust neural net embedded in the binary」），
**且允许连权重一起公开分发到 GitHub Pages**。纯 Rust 的推理意味着 **WASM 这条路是通的**——
不必开后端，强 AI 直接进浏览器。

**这一票只探路，不接牌桌**：把它编成 WASM，在浏览器里对**一个固定局面**出一手，然后把数与许可查清楚。
接成选手是票 92。

**Blocked by:** None

**Status:** ready-for-agent

## 它推翻了 spec 里的一条，所以要先查实

spec 的 Out of Scope 明写「**Mortal 的 WASM 化明确不做**」，接入方式写的是「轻量容器 + WebSocket」。
主人的授权把这条翻了。**但翻案要有依据**——这一票的头等交付物是**事实**，不是代码：

- [ ] **它到底是什么网络**：是 Mortal、Mortal 的衍生，还是另一个？
      （Akagi 的 README 通篇没提 Mortal。查 `LICENSE.txt` / `NOTICE` / `Acknowledgements` / 源码）
- [ ] **权重多大、什么格式**（`.pth` / `.onnx` / 自研二进制 / 直接编进 `.rlib`）
- [ ] **许可与署名的确切要求**：Apache-2.0 要保留 `NOTICE`；权重是否另有许可；
      公开分发要在我们仓库里放什么（LICENSE 片段、NOTICE、来源 commit）
- [ ] 它对外说的是不是 **mjai**（若是，我们那条唯一接缝原样可用；若不是，翻译层有多厚）

**查完把「术语怎么定」的建议写进报告**：若不是 Mortal，`CONTEXT.md` 的 `Mortal` 词条
与 spec 里那一排「Mortal 基线」都要改成通名（例如「强 AI 基线」）——
**你不许自己改术语表**（没授权），只出建议。

## 要什么行为（探路件，可以粗糙）

- [ ] 一个能跑的最小路径：浏览器里加载 WASM + 权重 → 喂**一个固定局面** → 拿到它的出牌
- [ ] 那一手要**能人工核对**（局面简单到一眼看得出该打什么，或与 Akagi 本体跑同一局面对拍）
- [ ] 放在**不影响主站**的地方（例如 `?dev=1` 那一侧，或一个独立小页面），**不进首页、不进 CI 的常规趟**

## 必须量的数（票 92 靠它决定形态）

- [ ] WASM 产物体积、权重体积（**这是要跟站点一起上线的东西**）
- [ ] 首次加载耗时（冷缓存）、单手推理延迟（中位与 p95）
- [ ] 内存峰值（浏览器里跑一整局要撑得住）
- [ ] 与现有构建的关系：Rust 工具链要不要进 `flake.nix`、`ci.sh` 会不会因此变慢

## 边界

- [ ] **不接牌桌**（票 92）：不碰 `SeatChoice`、不碰决策循环
- [ ] 不碰引擎、不碰真人坐席那条线（票 87–90 在并行）
- [ ] 不改 `CONTEXT.md`、不改 `docs/adr/*`、不改 spec——**只出建议**，翻案的 ADR 由调度器写
- [ ] 安装预算照 workbook：单次下载超 200 MB 就停下来报（权重与 Rust 工具链都可能撞线）

## 交付

除常规五件外，报告里要有**一节「给票 92 的形态建议」**：懒加载怎么做、体积能不能接受、
要不要放 CDN、CI 里跑不跑得动、失败时怎么降级。
