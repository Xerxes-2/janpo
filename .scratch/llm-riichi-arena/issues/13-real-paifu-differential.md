# 13 — 真实牌谱对拍

**What to build:** 用真实牌谱重放来对拍引擎：以牌谱的动作序列驱动引擎，逐局比对和了的役种集合、符、点数与终局点数。样本量优先、可增量——N 先小后大，**不要把牌谱获取变成硬墙**。

**Blocked by:** 08, 09, 11

**Status:** ready-for-agent

## 数据源阶梯（按顺序尝试，够用就停）

1. **首选：已预转换的 mjai 数据集** —— `NikkeTryHard/tenhou-to-mjai` 提供天凤鳳凰卓 2009–2026 的 `.mjson`（gzip，每行一个 mjai 事件）。**用这个就不必自己写转换器**，本票工作量砍掉一大半。
2. **次选：自己转** —— `fstqwq/mjlog2mjai`（Python，mjlog XML → mjai JSON）走 `uv run`；原始牌谱取自 `https://tenhou.net/sc/raw/` 的 `scraw20XX.zip`。
3. **备选二次 oracle** —— `mjx`（自称 exact Tenhou compatibility）。
4. **雀魂路线：本票不做** —— 牌谱屋（`https://5-data.amae-koromo.com/api/v2/pl4/...`）只给对局摘要（uuid / 选手 / 点数），完整牌谱要走雀魂 WebSocket + protobuf **鉴权**。记为后续，夜间不碰鉴权。

## 验收

- [ ] 能读取 mjai 事件流牌谱并以其动作序列驱动引擎重放
- [ ] **对拍前按牌谱来源选定规则集**（天凤牌谱用天凤规则集）；规则集不匹配导致的失败不得计入差异——默认配置与天凤在双响、切上满贯、连风牌符值上都不同，配错会大面积假失败
- [ ] 对拍每次和了的役种集合、符、点数，以及每局终局点数
- [ ] 差异以可读形式报告：哪一局、哪一巡、期望与实际
- [ ] 首批样本量下差异为 0；样本量可通过参数扩大，**不改代码**
- [ ] 无法转换或含不支持规则变体的样本被**显式跳过并计数**，附原因，不静默丢弃
- [ ] 三麻牌谱不在本票范围（引擎只做四麻）；`mjai.ekyu.moe` 亦只收四麻
