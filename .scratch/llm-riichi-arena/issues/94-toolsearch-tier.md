# 94 — 脚手架第三档：ToolSearch（单步 what-if 查询工具）

**What to build:** `ScaffoldTier` 三档里的最后一档。`CONTEXT.md` 已经写死了它的判据：
「**ToolSearch 加的是自己去问的能力，不是又一批算好的数值**，因此不落在『感知 vs 计算』这条判据的两端上」。
主人裁定的形态：**单步 what-if** —— 模型可以问「假如我打 X，向听 / 有效牌 / 危险度变成多少」。

**Blocked by:** None（与真人那条线不交叉；但**与票 95 都碰 `web/src/agent/**`，别同波**）

**Status:** ready-for-agent

## 要什么行为

- [ ] 座位选 ToolSearch 档时，prompt 里多一个可调用的工具：
      `what_if(discard)` → `{ shanten, ukeire, danger }`（字段名与形状你定，但**必须是引擎已有的量**）
- [ ] 工具的答案**与 Assisted 档给的是同一个函数算的**（不许为工具另算一遍）
- [ ] 模型可以问**多次**（不同的牌），要有**上限**（防止一手问三十次把账单打穿）；上限值要给理由
- [ ] 问过的每一次都**进决策记录**（`DecisionPackage` / `DecisionRecord` 里那一格今天叫 `Tools`），
      这样气泡点开之后看得见它查了什么、查了几次——**这正是这一档的可观测性**
- [ ] Assisted 与 ToolSearch 的**可缓存前缀不许分叉**（`CONTEXT.md`：档位只动得了尾部）

## 必须量的数

- [ ] 多轮往返对**延迟**的乘数（对比 Assisted 档：票 79 实测直觉档单手中位 1.7 s）
- [ ] 对**账单**的乘数（票 79：缓存命中 45%；工具往返会不会把命中率打下去，要量）
- [ ] 模型**实际问几次**（中位与 p95）——它可能一次都不问，那本身就是发现

## 闸门

- [ ] 假端点上：模型发起工具调用 → 拿到答案 → 出牌，整条链路走通，决策记录里三样都在
- [ ] 工具的答案与 dotnet 侧同一个函数**逐字段对拍**
- [ ] 上限：让假端点无限发问，断言到上限就停且**这一手照常打完**（不许卡死）
- [ ] Bare / Assisted 两档**一个字都没变**（对照实验的自变量只许有一个）
- [ ] 真跑一局（真 key，不进 CI）：把上面三组数抄进报告

## 边界

- [ ] 不做多步搜索、不做「模拟到终局」——**单步 what-if**，主人裁的
- [ ] 不给真人做查询面板（真人那侧是票 89 的 Assisted 档）
- [ ] 不碰引擎的算法、不碰真人坐席那条线
- [ ] 不改 prompt 的记法与战略目标（票 95 在做，**两票别同波**）
