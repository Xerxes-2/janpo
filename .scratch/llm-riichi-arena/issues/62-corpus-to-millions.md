# 62 — 把牌谱对拍推到百万场量级：先量这条路的开销，再流式扩语料

**What to build:** 主人要继续扩大真牌谱对拍以逼出更多 bug。调度器查明两件事：

1. **上游那个 release 有 18 个年度包（2009–2026，共约 11.4 GB）**，我们只用了 `2026.zip`
   （55MB，12,188 场——今年的残包）。**任意一个整年包约 190–290 万场**（按 2026 的解包比外推：
   ×10.4 解包、47KB/场）。也就是说**语料可以直接大两个数量级，且每个包只要 1 次请求**——
   不必再多打扰天凤。
2. **这条路的开销是 6ms/局**（调度器实测：固件 87 场 / 908 局，对拍墙钟 5.5s）。
   在 12 万局上无所谓（分钟级），**在 3000 万局上就是 50 小时单核**。所以主人问的
   「性能还能不能优化」——**在新量级上是真问题**，而在旧量级上不是。

**Blocked by:** None

**Status:** ready-for-human
