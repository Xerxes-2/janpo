# 77 — 分享载荷的形状与编解码（引擎 + TS，不碰页面）

**What to build:** URL 分享要带的那份东西：**只有棋谱**（规则集 + mjai 事件流），
外加一层压缩与 URL 安全编码，和一道真往返闸门。页面上的按钮是票 78，这一票只做载荷本身。

**Blocked by:** None — can start immediately（与票 70 那条 UI 线零重叠）

**Status:** ready-for-human

## 主人裁定的分叉（照做）

**URL 只带事件流，推理一律走 JSON 文件。** 也就是说 `Paifu.stripThinking` 这一层不够——
决策记录与 prompt 前置**整段不上 URL**。理由是长度：带上每手一句理由后半庄要 25–50 K 字符，
而只带棋谱是 7 K 量级；而首页 Demo 与 JSON 导入导出仍是全量，**气泡有话可说的路径没有丢**。

## 要什么行为

- [x] 引擎里加一次**值上的变换**：牌谱 → 只剩规则集与事件流的牌谱（决策记录空、prompt 前置空）。
      与 `stripThinking` 同一种做法（26-7：不是第二个编码器），**编码器与解码器仍然只有一份**
- [x] 那段变换的注释要写清**URL 是棋谱、不是审计数据**，以及为什么（长度实测 + 主人裁决）
- [x] TS 侧一个模块负责压缩与 URL 安全编码（浏览器原生 `CompressionStream('deflate-raw')` 一档就够，
      **不引新依赖**）；方向照 ADR-0005：**F# 调 TS**，跨界只传字符串，接口形状与 `Agent.ask` 同类（异步）
      ——**偏离一处，待人追认**：压缩取 `deflate`（zlib）而不是 `deflate-raw`。raw 没有校验和，
      一份 7,463 字符的载荷逐位置改坏一个字符，**5,666 次解得开且解出另一份牌谱**，
      下面那条反向自证在它上面根本不成立（三档对照见报告 §4 与 DECISIONS 77-1）。
      仍是 `CompressionStream` 自带的一档，零依赖，代价 8 个字符（+0.1%）
- [x] 解不动的载荷要给**中文原因**，不许抛异常、不许静静地空手而归

## 闸门

- [x] **真往返**（浏览器里）：一份牌谱 → 变换 → 压 → 编 → 解 → 解压 → `Paifu.decoder` → `Replay`：
      事件流逐条相同、终局点数与顺位相同（形态照 `PaifuCheck` 那个入口，与 `Golden.check` 同类）
- [x] **反向自证**：把载荷改坏一个字符，闸门必须当场红，且红在「载荷读不动」而不是别处
- [x] **载荷里不许有那三样**：拿一份带 thinking、带 prompt 尾部、又拌了假 key 的牌谱做载荷，
      断言解出来的载荷里 thinking / prompt 尾部 / 那把假 key 一个都不在
      （票 34 那道 key 闸门的同族，做法照抄它）
- [x] **长度记账**：东风战与半庄各实测一次，字符数抄进报告。
      本机的先验数（python zlib level 9，仅供对照）：半庄 1617 条事件、事件流 79.7 KB
      → deflate 5.6 KB → base64url **7,444 字符**；浏览器的 `deflate-raw` 会略有出入，以你量到的为准
- [x] 每条断言先红一次，红的输出进报告

## 边界

- [x] **不碰页面**：一个按钮都不加，`src/Janpo.Web/Table*.fs` 与地址解析一行不改（那是票 78）
- [x] 不碰 `Paifu.Version`：这一票不改任何字段的含义与形状，只是少写几段（解码器读得动本来就允许缺省的那几项）
- [x] 不碰 `web/src/agent/**` 的 prompt 与重试
- [x] 不做「压缩算法可选」「载荷版本号前缀」这类前瞻设计——真需要时它是渲染侧的优化（ADR-0002 明写）

但载荷的字符集要保证放进 hash 不必再转义一层（`+` `/` `=` 都不许出现）。
