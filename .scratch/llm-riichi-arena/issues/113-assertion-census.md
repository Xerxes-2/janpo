# 113 — 断言执行次数普查：把「看着在守、其实没执行」的那些一次找齐

**What to build:** 判据 3（「执行 0 次的断言与不存在等价」）在这个项目里已经攒了**六个案例**，
每一个都是**偶然**撞见的：

| # | 案例 | 怎么被发现的 |
|---|---|---|
| 1 | 票 95 的记法闸门 | 收尾时才想起来问「在真语料上跑了几次」 |
| 2 | 票 96 的立直属性十趟九空转 | 红了之后才去查 |
| 3 | 票 98 的抢杠零次 | 票 97 主动去数取值域 |
| 4 | 票 104 的「没有总分」没有执行者 | 收词时逐条弄坏执行者 |
| 5 | 票 92 那道剪枝一条闸门都没有 | 票 108 修同族问题时撞见 |
| 6 | 票 112 的播放速度**连断言都没有** | 票 111 顺手交回来 |

**六次全是偶然。这一票把它做成一次普查。**

**Blocked by:** 无

**Status:** ready-for-agent

## 要什么产出

**一份可信的清单 + 一个能重跑的工具。不要求修任何一条。**

- [ ] **工具**：`scripts/fsi/assertion-census.fsx`（或 `web/scripts/`，或两侧各一份——你判）
      能回答：**一趟 `./scripts/ci.sh` 里，每一条断言/属性/闸门各执行了多少次**
- [ ] **清单**：按「执行次数」升序排的表，**零次的排最前**，每行写清：
      它在哪个文件、它声称守什么、**为什么执行不到**（局面到不了 / 只在某种配置下跑 /
      根本没有产生点 / 是恒真式）
- [ ] **恒真式也要抓**：票 98 证过「把断言改成必然为假，`dotnet test` 照样绿」的那一族。
      **有没有便宜的办法批量发现它们**（例如属性函数里根本没用到入参、
      或断言的两侧是同一个表达式）？做得到就做，做不到就写明为什么
- [ ] **排个序**：哪几条**值得**补执行者、哪几条**该删**、哪几条**留着当防御分支但要有单元执行者**
      （票 111 那条 `VoidCause.Expired` 就是这一档的先例，照它的形状判）

## 怎么量（自己判，但别自欺）

- 引擎侧属性：FsCheck 那族有现成的取值域探针（`scripts/fsi/arbitrary-coverage.fsx`，票 97 留的），
  **先读它、别重造**
- 页面侧不变量：票 95 / 104 / 107 那几道有「跑了几次」的先例（`verify-invariants.mjs` 会印次数）
- 浏览器闸门：`verify-browser.mjs` 的 `gates` 表是趟数的唯一真源（票 106），
  **但「一趟里那条断言被求值几次」是另一回事**
- **别把「代码行被执行」当成「断言被求值」**：覆盖率工具答的是前者，这一票要的是后者

## 闸门

- [ ] **工具自身要有阴性对照**：故意加一条**永远执行不到**的断言，普查表里它必须出现在零次那一行
      （做完撤掉，报告里留原文）
- [ ] 再加一条**恒真式**（例如 `fun _ -> true` 那种形状），若你的工具号称抓得住，它也必须被点名
- [ ] 普查表里**每一条零次的都要有一句「为什么」**——没查清的写「没查清」，不许留空（判据 4）
- [ ] `./scripts/ci.sh` 全绿（这一票不许改任何断言的语义）

## 边界

- **只读与新增工具**：不许改任何既有断言/属性/闸门在守什么
  （发现的问题**列出来交回调度器编号**，别顺手修——这一票的价值在清单的可信度）
- 不碰 `src/**` 的产品代码；不碰 `Paifu` / 账那一段 / `Review*.fs`
- 可以新增 `scripts/fsi/*.fsx` 与 `web/scripts/*.mjs`；**若要接进 `ci.sh`，先想清楚它值不值那点时间**
  （票 112 那一趟 16.5 s 已经是第二贵的，普查大概更贵——**默认不接进 CI**，做成手动跑的工具）
- 加闸门趟数不用手改总述（票 106）

## 顺手记着

这一票最容易做出来的废物是**一张看起来很全、其实统计口径可疑的表**。
宁可**只覆盖三分之一但每个数都站得住**，也不要一张「大概是这样」的全表——
**判据 4：抓不住的要写出来。** 覆盖不到的那三分之二，列个名单说清「为什么这一批没量」，
比给它们编个数有用得多。
