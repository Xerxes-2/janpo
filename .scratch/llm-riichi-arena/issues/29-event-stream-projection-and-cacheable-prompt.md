# 29 — 每座位掩蔽事件流投影，与前缀可缓存的 prompt

**What to build:** 让 prompt 变成「**固定 preamble + append-only 的观测历史 + 尾部的现况与动作**」。
现在的 prompt 是当前局面的快照，每手几乎每个字都变，前缀零复用；改完之后同一局内前一手的 prompt
是后一手的**字节前缀**，provider 的前缀缓存因此能吃到。

这件事的分量不在省钱。**mjai 本来就是 per-seat 的掩蔽事件流**——真的 mjai bot 消费的正是那个；
20 号票选了快照路线（`Observation`），这一票把 prompt 拉回协议原本的形态。副产品是一整类问题消失：
立直宣言牌与立直巡目、加杠宣言（抢杠窗口）、河的手切摸切——它们都是**「发生过的事」**，
用快照表达就要一条条补字段（28 号票原本就在补两项），在事件流里**天然就在**。

**Blocked by:** 28

**Status:** ready-for-agent

## 一、引擎：每座位的掩蔽事件流

- [ ] 掩蔽函数：一条事件 + 一个座位 → 该座位可见的那条事件（或不可见）。他家摸牌隐去牌面、
      暗杠隐去牌面、配牌只见自家——判据与 `MaskedSeat` **同源**，不许出现第二套说法
- [ ] **属性测试（不泄露）**：任意对局任意座位，掩蔽流里不出现他家暗牌中的任何一张
- [ ] **属性测试（与快照一致）**：把掩蔽流 fold 起来，结果在 `Observation` 的**每个字段上逐一相等**。
      注意是「在 Observation 有的字段上相等」而不是恒等——流 fold 出来的东西**可以知道得更多**
      （历史派生的事实，如宣言牌），那不算不一致。这条测试就是「一条掩蔽法则」的执行者：
      任一侧多泄一个字段就红（裁决：两个投影并存，靠这条钉在一起）
- [ ] 上帝视角对应的未掩蔽流也要有（围观与 M2 复盘要用）
- [ ] **手切摸切的规则蕴含不变量**（主人 8/16 提醒逼出来的，规则本身就要求，免费的一致性检查）：
      立直成立之后该家的打牌必须**全是摸切**（立直宣言牌本身除外——它通常是手切）；
      碰 / 吃之后的那张打牌必然是**手切**（鸣牌没有摸牌动作）；杠之后是岭上摸牌，允许摸切。
      违反即说明事件生成有 bug，属性测试钉住

## 二、Agent 层：prompt 翻转

- [ ] 形态定死为三段：**固定 preamble**（规则与任务，逐字不变）→ **【到目前为止你看到的】**
      （append-only，永不重写既有行）→ **【现在】+【可选动作】+（脚手架）+（重试原因）**
- [ ] **属性测试（前缀稳定）**：同一局内，第 n 手的完整 prompt 是第 n+1 手 prompt 的**字节前缀**。
      这条自动守住「前缀里不许出现会被重算的量」（巡目、剩余张数、序号、任何聚合数）
- [ ] 载体是**单条不断增长的 user message**（裁决），不是多轮对话——不把模型自己的旧理由锚进上下文
- [ ] 脚手架（向听 / 有效牌 / 进退向 / 危险度）**全部在尾部**；两档的差异仍然只有那一节
- [ ] 事件流带来的东西在 prompt 里**真的可见**：立直宣言牌与宣言巡目、加杠宣言与抢杠窗口、
      以及**河与鸣的时序对齐**——哪张牌在第几巡被谁鸣走。这是「28 号那两项补丁被正当抽掉」的验收，
      缺一样这票就没做完
- [ ] 注意手切摸切**本来就有**（`Dahai` 事件的 `tsumogiri`，prompt 里缀 `*`，被鸣走的那张仍留在河里
      因为现物与振听要求它留着）。这一票要补的**不是这个标记，而是它的时间轴**：
      快照里河是一串牌、副露是另一串组，两条串接不上；细心的牌手记的是「第几巡手切了什么」，
      早巡手切中张与终盘手切中张是完全不同的两件事
- [ ] 录制固件重录；Bare 与 Assisted 两档都跟着改

## 三、把缓存变成可观测的数字

- [ ] `DecisionRecord` 记 `cacheRead` / `cacheWrite`（pi-ai 的 `usage` 已有这两个字段，
      `openai-completions` 适配器已经在读 DeepSeek 的 `prompt_cache_hit_tokens`，不用自己拼）
- [ ] 报告给出真跑一局的：**缓存命中率**、账单对比（快照式 vs 事件流式）、单手延迟对比
- [ ] 报告给出**最坏情况**的账单：原始 token 数随手数线性增长（快照式每手近似恒定），
      命中失效时（换模型、改 preamble、改渲染措辞）比现在更贵。把这个数字摆出来
- [ ] 记一条运维含义：**改渲染 = 废缓存**，而 CI 不会因此变红（前缀属性测试只保证同一次运行内单调，
      不保证跨版本一致）。考虑把渲染版本号写进 DecisionRecord，让 M2 能解释命中率为什么掉

## 三之二、牌谱只存 prompt 的尾部（同一个错的孪生兄弟）

26 号票的 `DecisionRecord` 每手存 prompt 全文（实测 7 条记录 4.6 KB，单手 485–721 字符）
与 tools 定义全文（每手 437–513 字符、几乎逐字相同）。**prompt 是
(事件流 + 座位 + 渲染版本 + 脚手架档位) 的派生物，而事件流就在同一个牌谱里**——存它是把派生值当事实存。
快照式 prompt 下这只是浪费；**这一票落地后它变成 O(n²)**：第 n 手的 prompt 含前 n-1 手的历史，
一整场约 120 手决策，存下的 prompt 文本会是它所派生的那份事件流的二十几倍。

这一票让修复变免费——prompt 天然分成前缀与尾部：

- [ ] `DecisionRecord` **只存尾部**（【现在】+【可选动作】+ 脚手架 + 重试原因），前缀不存
- [ ] 记 preamble 与渲染版本号，使「前缀 = fold(事件流) 重新渲染」可重建
- [ ] 提供重建函数并测试：重建出的全文 ≡ 当时真发出去的 prompt（**审计价值不许打折**：
      渲染器出怪的地方在尾部会原样留证）
- [ ] tools 定义整份牌谱存一次形状，不每手存；每手只留那一手的动作 id 集
- [ ] 版本号按 26 号定的规矩演进（加可缺省字段不涨版本，改含义才涨）；旧牌谱要照样读得动

## 四、边界

- [ ] 牌桌 UI 不在这一票的范围（它自己已经是 `fold(事件前缀)`）。牌桌上把宣言牌横过来显示
      归 M2 的布局票一起做
- [ ] 危险度（25 号票）继续吃 `Observation` 快照，不改——现物与筋只需要全部河牌，不需要宣言牌
