# 43 — `render_version` 只哈希模板，认不出渲染器代码改动

**What to build:** 票 31 按裁决 29b-A 实现了「模板 id + 内容哈希」作为 `render_version`，
用意是让 M2 看到命中率掉时能归因到「换了模板」。但它**只哈希模板内容**——
**改渲染器代码不会让版本号变**，而改渲染器同样废掉全部缓存（前缀字节变了）。
也就是说这个版本号只挡住了一半，另一半静默。

裁决 29b-A 的原话是「算得出来、漏不掉」。现在漏得掉。**把另一半补上，或者如实缩小承诺。**

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

## 两条路，选一条并说清理由

1. **补上**：把渲染器的代码也纳入哈希（构建期算出渲染层源码的摘要注进去，或用别的漏不掉的办法）。
   要求：**改渲染器一定让版本号变**，而改无关代码**不该**让它变（否则版本号天天在跳，等于没有）
2. **缩小承诺**：承认它只覆盖模板，把名字与文档改成如实的（例如 `template_version`），
   并写清「改渲染器代码同样废缓存，但版本号看不出来」

- [ ] 选定并实现，理由记 `DECISIONS.md`

      或断言文档/字段名与实际语义一致（走第 2 条）。反向自证的输出抄进报告
- [ ] 顺带核一遍：牌谱里已有的 `render_version` 值在新方案下怎么解读（牌谱版本要不要涨？
      按票 26 的策略判断：**改含义要涨版本**）

## 边界

- [ ] 不改 prompt 的措辞与结构、不碰引擎
- [ ] 不做「自动废缓存」这种聪明事——版本号的职责是**可归因**，不是自动管理缓存

## 为什么它是 M2 的前置

M2 要做三档 prompt 对照实验、要看命中率与账单。**归因工具本身漏一半，实验数据就有一半不可解释**。
