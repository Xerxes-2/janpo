## 逐条

### 1. `TileProperties.解析任意字符串都返回值而不抛异常` 的 `Ok` 支从没进过

```fsharp
match Tile.parse text with
| Ok tile -> Tile.toMjai tile = text
| Error _ -> true
```

`NonNull(text)` 随机串**从来解析不出一张牌**，300 个样本里 `Ok` 零次。
**调度器亲手验过**：把 `Ok` 那一支改成 `false`，`dotnet test` **9 条全通过**——它等价于 `fun _ -> true`。

- [ ] 让 `Ok` 那一支**真的被走到**（生成器里掺入合法记法，或另开一条属性专管「解析得出来的那些」）
- [ ] **别把这条属性删掉**：它守的那句「不抛异常」是真的有价值，
      今天只是**后半句没人守**——两句话要各有各的执行者
- [ ] 改完后用普查工具复量，把 `Ok` 支的次数写进报告

### 2. `HumanCallTests.fs:252` 那条 `Assert.DoesNotContain` 坐在空循环里

- [ ] 查清那个循环为什么空（构造不出那种局面 / 前置过滤掉了 / 写错了）
- [ ] 让它非空，或**写明凭什么空**并换成一条真能执行的断言

### 3. `TableTests.fs:120` 的 `else` 支零次

- [ ] 同上：能走到就让它走到，走不到就说清并改形状

### 4. 六条缺执行者的防御分支（清单在 113 报告 §3）

- [ ] 逐条判：**留着 + 单元执行者**（多数应该是这一档，照票 111 那条的形状）还是**删掉**
- [ ] 每一条都要有一句判断理由，别整批处理
