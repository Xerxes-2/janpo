# 40 — prompt 里他家的副露用了观测者参照系，会说出不可能的话

**What to build:** `web/src/agent/prompt.ts` 的 `naki()` 在渲染**他家**副露时，把「来自谁」按**观测者**
（正在决策的那个座位）算，而正确的参照系是**副露方自己**。后果是 prompt 里会出现
**「吃 来自对家」这种规则上不可能的句子**（吃只能吃上家）。模型读到的是错的信息。

这处是票 38 在改牌桌渲染时发现的：牌桌那边已经按**副露方**参照系画对了
（并有闸门交叉核对「吃恒来自上家」），而 prompt 这边还是错的。**两处说法必须一致，而且都以副露方为准。**

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] `naki()` 渲染他家副露时，「来自谁」以**副露方**为参照系（与牌桌、与 `Naki.Target` 的语义一致）
- [ ] 自家副露的说法不许因此变样（自家的参照系本来就是自己）
- [ ] **加一条会红的用例**：断言「吃」的来源恒是**上家**（相对副露方）。
      先让它红一次再修好——那句「吃来自对家」就是它该抓住的东西
- [ ] 顺带核一遍 prompt 里**其它**用到相对方位的地方（危险度的威胁名单、历史行里的「来自」、
      尾部的他家小节）：每一处都要能回答「这个上家/对家/下家是相对谁说的」。
      发现同类错就一并修，确认对的就在报告里列出核过哪几处
- [ ] 牌谱与录制固件若因措辞变动而变，照既有流程重录（决策包没变，重录的应当只有渲染类固件）

## 边界

- [ ] 不碰引擎（`Naki.Target` 的语义是对的）、不碰牌桌（票 38 已画对）、不碰 `.github/workflows/`
- [ ] 措辞照 `CONTEXT.md` 与 `wording.ts`：仓库里用的是**「对家」**（不是「対面」）

## 为什么这条值得单开一票

它是**给模型的信息错了**，不是显示问题。而且它躲过了全部闸门：黄金用例逐字段钉的是**决策包**，
前缀属性测试钉的是**字节单调**，两者都不检查「这句中文说的是不是真的」。
**相对方位在多主体渲染里必须显式声明参照系**，否则必错——这条判据值得记住。
