# 40 — prompt 里他家的副露用了观测者参照系，会说出不可能的话

**What to build:** `web/src/agent/prompt.ts` 的 `naki()` 在渲染**他家**副露时，把「来自谁」按**观测者**
（正在决策的那个座位）算，而正确的参照系是**副露方自己**。后果是 prompt 里会出现
**「吃 来自对家」这种规则上不可能的句子**（吃只能吃上家）。模型读到的是错的信息。

这处是票 38 在改牌桌渲染时发现的：牌桌那边已经按**副露方**参照系画对了
（并有闸门交叉核对「吃恒来自上家」），而 prompt 这边还是错的。**两处说法必须一致，而且都以副露方为准。**

**Blocked by:** None — can start immediately.

**Status:** ready-for-human

- [x] `naki()` 渲染他家副露时，「来自谁」以**副露方**为参照系（与牌桌、与 `Naki.Target` 的语义一致）
      —— `NakiFrame` 把参照系当参数传进 `naki()`，他家那几组写成「来自**他的**上家」
      （“他的”是参照系的就地声明：固定 preamble 宣告的默认参照系是观测者），报告 §2 §4
- [x] 自家副露的说法不许因此变样（自家的参照系本来就是自己）
      —— 15 份决策包 × 2 档逐行对拍：自家那一行零变化，变的只有他家那几行，报告 §6
- [x] **加一条会红的用例**：断言「吃」的来源恒是**上家**（相对副露方）。
      先让它红一次再修好——那句「吃来自对家」就是它该抓住的东西
      —— 实跑过，红的原文在报告 §3：`decision-sequence[2] 的上家那组「吃」写着「来自对家」：吃只吃得了上家`
- [x] 顺带核一遍 prompt 里**其它**用到相对方位的地方（危险度的威胁名单、历史行里的「来自」、
      尾部的他家小节）：每一处都要能回答「这个上家/对家/下家是相对谁说的」。
      发现同类错就一并修，确认对的就在报告里列出核过哪几处
      —— 七处逐处核过（报告 §5 的表），**同类错只有副露那一处**；
      历史行与威胁名单确认是对的（观测者参照系），各新添一条用例钉住

      黄金用例 40 条 2069 个字段照旧绿，牌桌那道副露闸门照旧绿

## 为什么这条值得单开一票

它是**给模型的信息错了**，不是显示问题。而且它躲过了全部闸门：黄金用例逐字段钉的是**决策包**，
前缀属性测试钉的是**字节单调**，两者都不检查「这句中文说的是不是真的」。
**相对方位在多主体渲染里必须显式声明参照系**，否则必错——这条判据值得记住。
