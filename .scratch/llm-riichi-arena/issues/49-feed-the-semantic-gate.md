# 49 — 把语义闸门的语料喂饱：让空转的不变量真的被检验

**What to build:** 票 41 立了 11 条语义不变量，但交票时自己交代了两处**闸门咬不到东西**的地方。
两处同源：**闸门的语料不够有代表性**，于是有些断言在真实语料上从不执行——
而「从不失败的闸门等于没有闸门」是这个项目已经写进规矩的判据。

**Blocked by:** None（票 41 与 42 都已落地，这一票就是把两者接起来）

**Status:** ready-for-agent

## 一、「立直后全摸切」在真语料上空转

票 41 扫了 120 颗种子、10,653 手，**立直出现 0 次**——因为当时只有均匀随机选手
（票 42 实测：1..2000 号种子里只有 15 场立直成立）。这条不变量目前**只被反向自证证明过**，
真语料没检验过它。

而票 42 已经交付了**有主见的选手**（同样 2000 颗种子里 1996 场立直、1045 次一发）。

- [ ] 语义闸门的语料里**掺入有主见选手的对局**，让「立直后全摸切」「立直状态的说法」这类断言
      在 CI 的真语料上真的执行到
- [ ] **不要整批换掉均匀随机的语料**：票 42 的实测显示两个选手在振听上互补
      （同巡振听 25→0、永久振听 584→1242），副露形态也不同（有主见的**从不吃**，
      而票 41 挑种子正是按副露形态挑的）。**两种都要有**
- [ ] 报告里给出：掺之后每条不变量各被执行了多少次（**执行次数为 0 的要点名**，
      并说明是「语料还不够」还是「这条本来就罕见」）
- [ ] CI 时间不许失控（票 41 现在 5.4s、子进程封顶 4）；超了就减种子而不是减不变量

## 二、「碰的来源指错人」纯文本判不出

只有「吃」在规则上把来源钉死（必来自上家），碰与杠**任何一家都可能**，所以文本自身自洽也可能是错的。
真正能判的是**文本 ↔ 决策包里的绝对座位**对拍——票 40 有这道，但它只跑 15 份固件。

- [ ] 把「文本说法 ↔ 绝对座位」的对拍**搬到批量语料上**（与第一节同一批 prompt 一起过）
- [ ] 覆盖每一种副露的来源（吃/碰/大明杠/加杠），以及各座位视角（**参照系是副露方，见票 40 的裁定**）
- [ ] 反向自证：把某一处的换算临时漂掉，确认批量闸门当场红，红的输出抄进报告

## 边界

- [ ] **不改 prompt 的措辞与结构**（M2 对照实验的自由变量），不碰引擎、不碰牌谱格式
- [ ] 不新增不变量（那是票 41 的地盘，真想加就先报上来）
- [ ] 票 41 报告 §3.1/§3.2 记了两次「闸门自己的式子错」（岭上摸牌算巡目、加杠头一张仍在别人河里）。
      **新语料很可能再暴露同类**——那是好事，但要分清「不变量错」与「引擎错」，别改错一侧
