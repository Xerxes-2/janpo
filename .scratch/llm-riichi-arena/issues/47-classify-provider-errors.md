# 47 — 给 provider 错误分类：不值得重试的别重试

**What to build:** 现在**所有**失败一视同仁地重试 2 次，包括认证失败。27 号验收的断电演习实测：
一整场 85 手 × 3 次 = **255 次请求全部 401，其中 170 次是纯白烧的**——第一次 401 就已经注定后两次也是。

当初的理由是「分支越少越好解释」（决策 23-6），并明写「真要省，判据应当是**这个错误重试有没有意义**，
那需要 provider 错误的分类，不是一个 if」。现在有了实测代价，按那条判据做。

**Blocked by:** None — can start immediately.

**Status:** ready-for-human

- [x] 按「**重试有没有意义**」把失败分成两类，而不是按 HTTP 状态码堆 if：
      **不值得重试**（认证失败、请求本身不合法、模型名不存在这类"再问一遍还是一样"的）；
      **值得重试**（超时、限流、5xx、解析失败、动作 id 非法这类"再问一遍可能不一样"的）
      → `web/src/agent/retry.ts`。判据是 HTTP 自己的语义：**4xx 说的是「你这份请求不对」**
      （而重试发的是同一份请求）→ 不值得；**5xx 说的是「端点这一刻不行」** → 值得；
      4xx 里点名三个例外（408 / 425 / 429，它们说的是「这一刻不行」）。判不出来就当值得重试。
      分类表见报告 §1。
- [x] 不值得重试的**立刻走兜底**，不占额外请求；页面与牌谱里要能看出「没重试是因为重试没意义」，
      而不是看起来像少试了
      → 交不出来那句话分两种收尾：`（重试 2 次仍无结果）` / `（没有重试：<判据>，再问一遍还是一样）`。
      页面与牌谱读的是同一个字符串（`AgentStatus.Troubled` 与 `DecisionRecord.Fallback`），
      因此**没有改一行 F#**；牌谱那侧另有 `attempts`（不值得重试的那一手恒是 1）。见报告 §2。
- [x] `stopReason`/`errorMessage` 是**值**不是异常（票 23 的既有形状），分类逻辑照这个形状写
      → `retryOf(errorMessage: string | null): Retry`，`Retry` 是值（`{ worth: true } |
      { worth: false; because }`），`judge` 的每一支自己声明判据。一个 try/catch 都没加。
- [x] **限流（429）单独想清楚**：它值得重试，但立刻重试没意义。要不要退避？
      若不做退避就写清理由（M1 没遇到过限流，别过度设计）
      → **值得重试，不做退避**。三条理由（`Retry-After` 拿不到：pi-ai 的 `AssistantMessage`
      不透传响应头；退避要新增一个时钟接缝；代价上限是 2 个请求随即兜底）与**翻转它的条件**
      见报告 §5、DECISIONS 47-3。
- [x] 录制回放用例补齐两类各至少一条；**先红后绿**，红的输出抄进报告
      → 新录三份（429 / 503 / 404），不值得重试那两条**先红**（原始输出报告 §4.1）；
      值得重试那两条改之前就绿，因此**把分类反过来按红一次**（原始输出 §4.2，11 条红）。
- [x] 复跑一次断电演习给出对照数字：**255 次请求降到多少**
      → **85 次**（-170，正是票面点名的那 170 次白烧）。同一场：85 手兜底一手不少、
      事件流逐条相同、整场 80.4 s → 42.8 s。对照表与原始输出见报告 §3。

## 边界

- [x] **不许改兜底的行为**（交不出动作就由引擎 `Fallback.action` 代打，这条不动）
      → `jj diff` 里没有任何 `.fs`；变的只有「交不出来之前问了几次」。
- [x] 不碰 prompt、不碰引擎、不碰牌谱格式（若分类结果要进牌谱，先记 `DECISIONS.md` 再动）
      → **决定不进牌谱字段**（DECISIONS 47-4）：`attempts` + `fallback` 已经把这件事说完了，
      加字段是同一件事的第二种说法且要涨版本。牌谱版本仍是 2。
- [x] 打码那一层（票 36）在出口，分类在它之前发生——**别把错误原文的处理顺序搞反了**
      → 打码在 `decideWith` 出口，分类在循环里，因此分类看到的是原文（DECISIONS 47-6）。
      票 36 那条「三个出口」用例因此被按红了一次，**补强而不是放宽**（报告 §4.3）。
