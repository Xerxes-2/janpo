# 47 — 给 provider 错误分类：不值得重试的别重试

**What to build:** 现在**所有**失败一视同仁地重试 2 次，包括认证失败。27 号验收的断电演习实测：
一整场 85 手 × 3 次 = **255 次请求全部 401，其中 170 次是纯白烧的**——第一次 401 就已经注定后两次也是。

当初的理由是「分支越少越好解释」（决策 23-6），并明写「真要省，判据应当是**这个错误重试有没有意义**，
那需要 provider 错误的分类，不是一个 if」。现在有了实测代价，按那条判据做。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 按「**重试有没有意义**」把失败分成两类，而不是按 HTTP 状态码堆 if：
      **不值得重试**（认证失败、请求本身不合法、模型名不存在这类"再问一遍还是一样"的）；
      **值得重试**（超时、限流、5xx、解析失败、动作 id 非法这类"再问一遍可能不一样"的）
- [ ] 不值得重试的**立刻走兜底**，不占额外请求；页面与牌谱里要能看出「没重试是因为重试没意义」，
      而不是看起来像少试了
- [ ] `stopReason`/`errorMessage` 是**值**不是异常（票 23 的既有形状），分类逻辑照这个形状写
- [ ] **限流（429）单独想清楚**：它值得重试，但立刻重试没意义。要不要退避？
      若不做退避就写清理由（M1 没遇到过限流，别过度设计）
- [ ] 录制回放用例补齐两类各至少一条；**先红后绿**，红的输出抄进报告
- [ ] 复跑一次断电演习给出对照数字：**255 次请求降到多少**

## 边界

- [ ] **不许改兜底的行为**（交不出动作就由引擎 `Fallback.action` 代打，这条不动）
- [ ] 不碰 prompt、不碰引擎、不碰牌谱格式（若分类结果要进牌谱，先记 `DECISIONS.md` 再动）
- [ ] 打码那一层（票 36）在出口，分类在它之前发生——**别把错误原文的处理顺序搞反了**
