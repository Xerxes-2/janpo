# 38 — 副露要能看出「被鸣的是哪一张、来自谁」

**What to build:** 牌桌上的副露现在只画出三四张牌加一枚种类标签（`吃 [2筒][3筒][4筒]`），
**看不出哪一张是从别人那儿鸣来的，也看不出来自谁**。真牌谱里这两件事是靠**牌的朝向**编码的：
横放那张是被鸣的牌，它在组里的位置说明来自上家 / 对面 / 下家。把这两条信息画出来。

数据早就有：引擎 `Naki` 带 `Taken`（被鸣的那张，暗杠没有）与 `Target`（被鸣的座位，暗杠没有；
加杠记原本碰的来源），字段贴 mjai wire。**prompt 的尾部已经在写了**——
`碰 3m（来自下家，亮出 3m 3m）`。所以现在的局面是**模型看到的比人多**。

**Blocked by:** None — can start immediately.

**Status:** ready-for-human

- [x] 被鸣的那张**一眼可辨**（横放是标准做法，也可另择记号，但要与既有的摸切虚线/牌背斜纹**互不混淆**）
      —— 取**横放**（`transform: rotate(90deg)`，类名 `.tile.taken`）：它动的是朝向，
      与已占的四条（虚线淡色 / 45° 斜纹 / 红字 / 额外间距）一条也不撞
- [x] 来源**一眼可辨**：走位置编码（上家/对面/下家）或显式标注都行，选一种并说清理由。
      措辞照 `CONTEXT.md`（上家/対面/下家的中文用法与 prompt 里的 `words.who` 保持一致）
      —— 取**显式标注**「来自上家」（理由见报告 §2.2）；词照 `CONTEXT.md` 与 `wording.ts` 取**对家**（不是「对面」）
- [x] 三种杠各自正确：**暗杠**无来源（现在已经画成两端背面，别弄坏）；**大明杠**有来源；
      **加杠**的来源是当初碰的那家，且 `Consumed` 的**第一张恒是当初被碰的那张**（引擎注释里写着），
      理想情况下加上去的那张与当初碰来的那张都能看出来
      —— 三种各一条单元用例 + 两张截图（报告 §3）；加杠横放的是当初碰来的那张，后添的那张前面一枚「＋」
- [x] 吃的三张顺序要能看出被鸣的是哪一张（`2筒[3筒]4筒` 与 `[2筒]3筒4筒` 是不同的吃）

## 为什么这算 M1 的活

与票 32（牌背隐形）同类：**信息在数据里、是公开信息、人却看不见**。
项目已经公开可玩，围观者看不出鸣牌来源等于看不懂这一局怎么走的。
这不是好不好看的问题，是**看不看得懂**的问题。
