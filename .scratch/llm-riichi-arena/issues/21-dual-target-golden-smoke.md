# 21 — 双目标黄金用例冒烟

**What to build:** 一份用例，两个目标跑，结果必须逐字节相同。spec 的 Testing Decisions 点名要它：
「同一批黄金用例（输入事件序列 → 期望输出）在 JS 侧跑一遍，防双目标语义漂移，重点是数值与集合语义」。
跑完这一票，「Fable 编出来的引擎和 dotnet 编出来的引擎是同一个引擎」这句话才有闸门守着，
而不是靠 19 号票那一个种子的巧合。

**Blocked by:** 19

**Status:** ready-for-agent

- [ ] 黄金用例以数据形式落盘（dotnet 侧生成/维护），两侧读同一份，用例本身不写死在任一侧代码里
- [ ] 覆盖重点：Rng 的取数序列与牌山头几张（M0 已经钉死的那几行）、整数除法与取整（符与点数最容易漂）、
      集合与 Map 的遍历顺序、字符串与牌记法的往返
- [ ] 至少一场完整对局：同种子在两侧跑完，事件流逐条相同、终局点数与顺位相同
- [ ] JS 侧的跑法进 CI，与 dotnet 侧测试同一个关卡里（`ci.sh` 一条命令全绿）
- [ ] 任一侧漂了就红，且报错能指出漂在哪个用例的哪个字段
