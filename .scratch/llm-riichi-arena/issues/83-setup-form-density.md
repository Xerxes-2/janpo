# 83 — 页面重排：操作控件贴到牌桌，配桌表单让出中心

**What to build:** 主人试玩后报的第⑥⑦两条，其实是同一个毛病：**页面按代码写的顺序排，不是按人用的顺序排。**

- ⑦ 播放 / 单步 / 下一局 / 导出 / 分享 / 倍速这些**开局后一直在用**的控件，眼下在页面顶部，
  离牌桌一千多像素——按一下要把视线甩回去看结果。
- ⑥ 配桌表单**开局前用一次**，却占着视线中心：四席纵向堆着，每席一行按钮 + 一个档位下拉
  **加两个大文本框**（人格、模板），一屏下去只看得到两席半。而这一页要回答的问题很简单：
  **这四个座位分别是谁、什么档位。**

一条分界线治两条：**「操作这一桌」的贴着牌桌，「配这一桌」的收到上面去。**

**Blocked by:** 79（它在翻 `verify-home` 的断言与资产）

**Status:** ready-for-agent

## 调度器已定（主人可否决）

- **控件贴在牌桌正上方**，不做视口吸底：吸底会盖住牌桌下沿——那正是自家手牌那一排。
  牌桌区约 900px 高，控件紧贴其上时「按一下、看结果」在同一屏里，视线移动最短。
  若量出来仍要滚动才看得全，**报告里给数**，别顺手改成吸底。
- **跟着挪的是「作用于这一桌」的那些**：播放 / 暂停 / 单步 / 下一局 / 倍速 / 从头再放 /
  时间轴 / 跳到局号 / 导出牌谱 / 复制分享链接 / 导入牌谱。
  **留在上面的是「配这一桌」的**：对局长度·赤宝牌·食断、种子与重开、四席绑定与档案库。
  视角与危险度算「怎么看这一桌」，**也贴牌桌**（它们改的是牌桌的呈现）。
- 首页（回放）与 `?table=1`（Live）**同一条规则**——两屏共用一套控件装配，别做成两套。

## 要什么行为

- [ ] **四席一眼看全**：座位 → 选手 → 档位 这三样，四行摆在一屏里读得完
- [ ] **人格与模板这两块大文本收起来**（折叠、抽屉、还是弹层由你定），但要满足两条：
      ① 收起时看得出「这一席有没有自定义人格/模板」（有内容要有记号）

      座位绑定是「谁坐哪、给多少信息」——它们是两种东西，现在混在一片

## 边界
