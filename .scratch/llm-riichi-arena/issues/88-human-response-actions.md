# 88 — 真人的响应动作：吃碰杠、立直、荣和、自摸

**What to build:** 票 87 让真人能出牌，但鸣牌一律自动过——那还不算「亲自下场」。
这一票把**引擎给出的合法动作集**整套渲染成按钮（spec 的 story 30：
「这些按钮只在动作合法时出现，所以我不可能犯规」）。

**Blocked by:** 87

**Status:** ready-for-human

## 要什么行为

- [x] 响应阶段：能吃 / 碰 / 大明杠 / 荣和的时候，**按钮才出现**；不能的时候**不在 DOM 里**
- [x] 自己回合：暗杠 / 加杠 / 立直 / 自摸 / 九种九牌（若引擎支持）同理
- [x] **吃有多种组合**（左中右）、碰有赤牌取舍时，要能选**具体哪几张**——
      动作 id 是引擎给的，UI 只是把每个 id 画成一个按钮，**不许 UI 自己算组合**
- [x] **立直是两段**：宣言之后还要选打哪张，且只有能保持听牌的那些牌可点（仍由合法动作集说了算）
- [x] 「过」永远在（响应阶段不点就卡住，那是最难受的死法）
- [x] 与模型席**并发共存**：真人在想的时候别席的答复先收着，引擎收齐才裁决
      （票 74 的形状已经是每席一份，别改它）
- [x] 真人做完动作，牌谱里与 bot/模型的同一种动作**逐字段同形**

## 闸门

- [x] 用固定种子构造出局面，让真人席分别**碰到能碰、能吃、能立直、能荣和**各一次，各点一次，
      断言事件流里真的出现了那一手（**不是断言按钮存在，是断言牌局真的变了**）
- [x] **不合法就不在**：同一局面下断言那些不合法的按钮**不在 DOM 里**（阴性对照）
- [x] 立直两段：宣言后可点的牌集合 = 引擎给的那一集，逐张对拍
- [x] 并发：真人在想时让模型席先答，断言引擎按优先级裁决（头跳/双响的顺序不因谁先答而变）
- [x] 87 立的「结构性不泄露」那条照旧绿（新按钮不许把别家的信息带进 DOM）

## 边界

- [x] 不做时限（票 89）、不做信息辅助（票 89）、不做复盘（票 90）
- [x] **不碰引擎的合法动作集与裁决顺序**：这一票只把已有的 id 画成按钮
- [x] 不碰 `Paifu` 格式、不碰 `web/src/agent/**`
- [x] 不做「悔棋」「撤销」——牌打出去就是打出去了

## 要害

**这一票最容易走偏的地方是「UI 自己算」**：比如吃的三种组合、立直后能打哪些牌、赤牌怎么取舍。
一旦 UI 自己算，规则就有了第二个真源，而它迟早与引擎不一致。
**判据：每一个按钮背后都必须是一个引擎给的动作 id；找不到 id 的按钮不许存在。**
