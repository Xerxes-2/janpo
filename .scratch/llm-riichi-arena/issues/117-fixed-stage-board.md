# 117 — 固定舞台 + 四席绕盘心：牌桌换成标准麻将几何

**What to build:** 主人的判断：**整个 UI 推倒重来，修修补补不行**。四条意见里的第一条与第四条
是同一个病——

> ① 参照市面上麻将游戏的 UI，对人类交互足够友好直观，**布局可以妥协成结构不因为缩放而改变**
> ④ 许多提示都很冗余，造成信息过载

第四条的根源就是第一条：**非标准布局逼得界面用大段文字打补丁解释方位。**
今天 `?table=1` 上有一整段讲「副露从左往右＝从上往下」的说明——那段话是**竖排侧手牌的补丁**，
换成标准几何之后它自证方位，那段话就该消失。

做法（原型已验，见 `.scratch/proto/`）：**固定舞台 1200×750，整体等比缩放，结构永不重排。**
牌桌 656×656 居中，盘心 (328,328)；四席**同一份 DOM** 绕盘心 `rotate(0/90/180/270)`。

**Blocked by:** 116（配桌不收起来，528 px 塞不进 750 px 的舞台）

**Status:** ready-for-human

## 先读这段：原型量出来的数

`node .scratch/proto/shoot.mjs` 可重跑。喂的是**终盘量级**（河 16–19、两家立直、四组副露、127 枚牌）：

| 视口 | scale | 自家牌宽 | 牌越出牌桌 | 一屏 | 文档滚动 |
|---|---|---|---|---|---|
| 1280×800 | 1.067 | 32 px | 0 | ✓ | 无 |
| 1440×900 | 1.200 | 36 px | 0 | ✓ | 无 |
| 390×844 | 0.325 | **9.8 px** | 0 | ✓ | 无 |

对照今天：`?table=1` 牌桌顶 810 px（视口 800）＝ **0 px 可见**；手机 3.69 屏。
（这两组数出自 `node .scratch/polish-budget.mjs` 与 `node .scratch/polish-shots.mjs`，
临时量具、**不接闸门**；票 116 落地后这两组数会变，以你自己 fixed point 上量到的为准。）

**三个几何常数一步都不能错**，原型第一版就是在这儿坏的：

1. `transform-origin` **必须留默认的 50% 50%**，配 `translate(-50%,-50%)`。
   写成 `0 0` 会让 `scale` 把右下角顶出视口——而那时「牌不越出舞台」等三个数**照样全绿**。
2. 席区 `top: 428px` + `transform-origin: 328px -100px` ⇒ 支点正好是盘心 (328,328)。
3. 河 `left: 244px` = 328 − 6×28/2，6 枚一行。

## 调度器已定（主人可否决）

- **借雀魂的几何，不借它的绿绒**：点数在中央盘四边、宝牌在顶角。
  颜色仍是票 80 的四色相（纸 / 墨 / 朱红 / 靛蓝），桌面用深一档的纸色。
  **没动第五个色相**（票 93 用这条纪律否过一次提案）。
- **名字不进中央盘**：中央盘 180×180 只塞得下 5–11 字，`deepseek/deepseek-v4-flash` 放不进去。
  名字挪到席位边上——主人已点头「名字放边上也行」。中央盘只放**风位 + 点数**，
  风位是它与名牌对上的钥匙。名册本体是票 118 的活，这一票先把中央盘立起来。
- **正文换黑体**（主人第一轮意见③），`janpo` 字样留宋体当门脸。
- **删掉 `@media (max-width: 39.99rem)` 那一整块**（票 44 写的竖排布局）：
  仓库里**最窄的闸门视口是 1180 px**（`grep "width: [0-9]" web/scripts/*.mjs` 只有 1180 / 1280），
  那块 CSS **从来没被渲染过一次**，且它与 README「也没有为手机屏幕适配」互相矛盾。
  固定舞台缩放之后，README 那句变成**字面真话**（能看不能读，9.8 px）。
- **手机竖屏不救**：转 90° 只得 15.6 px，仍不算能用。诚实立场写进 README。
