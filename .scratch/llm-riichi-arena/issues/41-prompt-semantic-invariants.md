# 41 — prompt 的语义不变量闸门

**What to build:** 给**渲染出来的自然语言**加一层「说的是不是真话」的闸门。现在的十余道闸门里，
黄金用例逐字段钉的是**决策包**（结构化数据），前缀属性测试钉的是**字节单调**，
**没有一道检查那句中文是否成立**——而它是模型唯一读得到的东西。

票 40 那句「吃 来自对家」（吃只能吃上家，规则上不可能）就是从这个缺口漏过去的：
决策包里是绝对座位号、完全正确，前缀字节也单调，两道闸门都绿。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

## 要做什么

在真实局面上批量渲染 prompt，然后断言一批**语义不变量**。判据是「这句话在麻将规则下是否可能」，
而不是「这句话与上次是否逐字相同」（后者已经有前缀测试管了）。

- [ ] 起一批不变量，至少含：
      **吃恒来自上家**（相对副露方）；**自家副露不出现「来自你」之外的方位歧义**；
      **暗杠不带来源**；河里的牌数与那家的巡目一致；宝牌指示牌数与杠数一致；
      立直成立后那家的打牌全是摸切（宣言牌除外）；手牌张数满足 3n+1/3n+2；
      **可选动作里出现的每一张牌都在「你的手牌」那节里出现过**
- [ ] 样本从**真实对局**批量取（种子扫一批、逐手渲染两档），不要手捏几个局面就算完
- [ ] 每条不变量**先红一次**再修/确认：违反时的报错要点名是哪条不变量、哪一手、哪句话
- [ ] 进 CI（零网络请求，纯渲染 + 断言）
- [ ] 顺带把「历史行只依赖那一条事件本身」这条（票 29b 的前缀前提）也变成可断言的性质，如果做得到

## 边界

- [ ] **不改 prompt 的措辞与结构**（那是 M2 三档对照实验的自由变量）。这一票只加闸门；
      真发现语义错，**报上来另开票**，别顺手改文风
- [ ] 不碰引擎、不碰牌谱格式
- [ ] 不必追求「不变量完备」——**能抓住票 40 那类错**就是合格线，宁可少而准

## 为什么它是 M2 的前置

M2 要做三档 prompt 对照实验。**实验建在没有语义闸门的渲染层上，结论不可靠**：
你分不清「这档更强」和「这档的 prompt 里有句错话」。
