# 111 — 撤票之后：牌桌自己动起来 + 给那条防御分支一个执行者

**What to build:** 票 109 交回来两件小的，都在它刚动过的那一段上。

**Blocked by:** 无（109 已集成）

**Status:** ready-for-human

## 第一件：`SeatBound` 撤完票不把牌桌重新开动

票 109 加了「人拨座位 → 那一席在飞的问话当场作废」，但 `SeatBound` **至今没有 `resume`**：
撤完之后没有任何定时器/效果体去重问那一席，浏览器闸门是靠**手动单步一下**走过去的。
也就是说：**人在自动播放中途拨一下座位，牌桌就停在那儿等他再按一下**。

- [x] 撤票之后那一席**自己被重新问**（模型席）或**自己等人点**（真人席），
      别让「拨一下座位」变成「顺手把牌桌按停了」
- [x] 真人席那一支别破票 87 / 88 / 89 立的规矩：**轮到他就等他**，不许替他打
- [x] **阴性对照**：不在自动播放中拨座位（本来就停着），断言**不会**凭空开动
      ——「撤票要重开动」不等于「拨座位就开始播放」
- [x] 闸门里把票 109 那句「靠单步 1 下走过去」的绕法**去掉**，它该自己走

## 第二件：`VoidCause.Expired` 现在一条用例都到不了（判据 3）

票 108 那道剪枝（`stillCurrent` 判「合法动作集还是不是当下」）在票 109 之后**执行次数归 0**：
同一批 30 颗种子，修前剪枝 30 / 撤票 0 → 修后撤票 30 / **剪枝 0**。
`grep VoidCause.Expired` 全仓库只有 `TableState.fs` 那一处产生点，**没有任何用例到得了它**。

**调度器的裁定：留着那个分支，但给它一个单元级的执行者。**
理由：防御分支本身是对的（将来若有别的绕行路、或 `Fault` 之后那种情形），
而 `Voided` 那笔账带着 `cause`，所以它真在生产里响过一次是看得见的；
**但只要没有一条用例能构造出那个状态，我们就分不清「从不发生」与「发生了被静默吞掉」。**

- [x] 直接在单元层构造那个状态：一份在飞的问话 + 引擎此刻给这一席的合法动作集**已经变了**，
      走 `drain` 那条路，断言它被剪掉、账上留下一笔 `cause = Expired`、**且没有 `DecisionRecord`**
- [ ] 若发现**连单元层都构造不出来**（状态不可达）：那就不是防御分支而是死代码，
      **停下来在报告里写清凭什么不可达**，并给两条选择（删掉 / 换成一句响的断言），由调度器裁
      —— **不适用**：单元层构造出来了（报告 §5.1）。「今天从**页面上**走不到」另写在 §5.2，
      它是保留那条分支的理由，不是删它的理由
- [x] 顺手：`StaleAskTests.fs:213` 那句注释现在描述的是旧世界，改成实况
