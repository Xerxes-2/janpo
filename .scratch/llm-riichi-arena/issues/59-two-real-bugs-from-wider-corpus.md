## 一、打牌前连着两次杠时，明杠欠的那张宝牌翻得太晚（28 局反例）

引擎实现的是「暗杠当场翻、明杠欠到打牌那一刻才翻」——这条本身是**真牌谱教出来的**（票 16）。
但**连着两次杠**时那条「欠到打牌」的算法把第一次欠的也一起推到最后，与天凤不符。

这**正是票 16 的 16-B 当年写下的那句「有反例就改」** —— 现在有 28 局反例了。

- [x] 按 57 号报告里那 28 局逐条对齐（**它们都在扩语料里，`JANPO_PAIFU_DIR` 指过去就能复现**）
- [x] 要动 `GameState` 的杠处理与 `KanTests` 里第 ④ 条的期望值——
      **改期望值前先确认那条期望本身是错的**（判据：先怀疑断言自己，但这次断言与真牌谱对立，
      真牌谱赢；把判断过程写进报告）

## 二、大明杠 → 岭上开花的责任支付，天凤根本不采用（24/24 全错）

引擎里**写死**了「大明杠后岭上开花由放杠者独付」（责任支付 / 包）。
天凤鳳凰卓**不采用这条**，所以那 24 局全错，还连带 22 处终局点数错。

**调度器的裁决（可推翻，理由在下）**：做成 `Ruleset` 上的一个开关，**默认关**（＝天凤口径）。
理由是本项目把**规则集当一等输入**（spec 与 ADR 都这么定），而这条规则在现实中确实有采用的赛制；
写死成「不做」会让将来想支持的人再挖一次。**若你实现时发现开关的代价明显大于收益，
在 `DECISIONS.md` 说清并改成直接去掉——但不许保留现状。**

- [x] 默认口径与天凤一致（那 24 局归零差异，22 处终局点数跟着对上）
- [x] 开关的命名与措辞照 `CONTEXT.md` 的既有体例（`MinkanRinshanSekinin`）；术语表要不要收新词**只报不改**（DECISIONS 59-3）
