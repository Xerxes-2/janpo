# 57 — 把真牌谱对拍扩到更多完整场次

**What to build:** 现在进 CI 的固件是 **18 场半庄 / 177 局**，离线扩样本跑到过 **200 场 / 2110 局**
（票 13 与 16 的记录）。主人的判断是**数据还不够多、不够稳**。这一票把语料扩到更大的量级，
并重新回答一个问题：**哪些进 CI、哪些只在离线跑**。

**Blocked by:** 55, 56（主人的要求：先把 CI 提速做完再扩——否则扩语料会把 CI 拖垮）

**Status:** ready-for-human

## 为什么这道闸门值得扩

它是 **M0 唯一抓到过真 bug 的闸门**，而且两次都是真牌谱教会我们的：
立直宣言牌换听没解振听；明杠的宝牌指示牌翻早了导致岭上开花多算一张宝牌
（**2/2110 局，其中一局把 2700 点算成满贯 8000**）。这类时机细节，属性测试与自造用例都测不出来——
只有真人打的牌谱能。样本从 200 场涨上去，是在买**下一个这种 bug**。

## 要做的

- [x] 用 `scripts/paifu/fetch-corpus.py` 拉更大的语料（`JANPO_PAIFU_DIR` 指过去就能扫）。
      **量级由你按实测定**：先跑一批，看差异密度与耗时，再决定停在哪
- [x] 对拍跑通全量，**逐条核实每一处差异**：是引擎错、牌谱侧噪声，还是规则集口径不同
      （票 13 记过一例上游噪声：双响时 `ura_markers` 重复）。**一处都不许「看起来没事」就放过**
- [x] 抓到真 bug 就**只报不修**（立票交调度器排），除非那处修法一目了然且不动语义边界
- [x] 重新划**进 CI 的那一份**：现在 18 场 / 1.1 MB。CI 里那份的判据是
      「**能在预算内跑完、且覆盖到已知易错的时机**」（杠的宝牌时机、双响、连庄、供托结转、
      各种流局形态）。**别只按场数挑，按覆盖挑**
- [x] 报告里给出一张覆盖表：这批语料里各种罕见形态各出现多少次
      （对照 `Soak.unguarded` 里那三种「谁也到不了」的——**真牌谱里有没有？**
      若有，那三种就从「无闸门」变成「有闸门」，那是这一票的额外收获）
- [x] 网络与体积：拉语料要**礼貌**（限速、别打爆对方），大语料**不进仓库**
      （`data/paifu/` 已在 `.gitignore` 里），进仓库的那一份要说清为什么是这些场

## 边界

- [x] **不改引擎的规则判定**去迁就牌谱。发现不一致先分清是谁错——
      票 13 已有先例：三处差异里两处是我们的 bug、一处是上游噪声
- [x] 不碰 `web/`、不碰 workflow
- [x] CI 时间预算：加进 CI 的那一份**不许让 `./scripts/ci.sh` 的墙钟比票 55/56 之后的基线涨超 15%**。
      涨超了就把量留在离线，并在报告里说明离线那份怎么跑、多久跑一次

## 结果（57 票，见 `run/reports/57-wider-paifu-differential.md`）

- 语料 **12,188 场 / 129,179 局 / 654 MB**（0 跳过），对拍 109,592 次和了、72,488 个清算座位、
  116,991 局终局点数；**118 处差异全部逐条判定**。
- **两笔引擎的账只报不修，请调度器立票**：① 打牌前连着两次杠时明杠宝牌翻得太晚（28 局反例，
  正是票 16 的 16-B 说的「有反例就改」）；② 大明杠 → 岭上开花的责任支付天凤不采用（24/24 全错，
  其中 22 处连带终局点数错）。
- CI 固件 18 场 / 177 局 → **87 场 / 908 局**（按覆盖挑），`ci.sh` 墙钟在噪声内没涨
  （确定性口径：对拍那一类 duration 3.11s → 5.39s，占全量的 2.4%）。
- `Soak.unguarded` 那三种：**四风连打 82 局、流し満貫 17 局 → 都进了 CI 固件、有闸门了**；
  **三家和了语料里有 6 局但 mjai 流复现不出来**（上游把三条荣和宣言删了）→ 仍旧无闸门。
