# 142 — 手机：不救牌桌，只留一句「横过来看」

**What to build:** 竖屏窄屏上，牌桌换成一枚「横过来看」的提示。评审 P2-I 的**最小那一半**。

**Status:** ready-for-agent（主人 2026-08-30 裁：**同意只做最小那一半**）

## 裁下来的边界

评审要的是「竖屏给一个『读』的版式——名册 + 逐手一条」。
那要新造一整页，**与「一页只有一套装配」（票 83）正面相撞**——那条规矩挡住过好几次分岔，不该顺手破。
主人裁：**只做提示那一半**（一条 media query，不新造版式）；
「读」的版式**挂账，不开号**，等哪天真有手机来客的证据再说。

这一票不推翻票 119 那条「9 px 不救」的立场，**是承认它**：
390 px 上四家 34 张牌是数学问题，不是 CSS 问题；转 90° 得 15.6 px，仍不算能用。

## 要什么行为

- [ ] 竖屏且窄时，牌桌那一格换成一句话 + 一枚「横过来看」的入口；**其余版块照旧**
- [ ] 那句话要诚实：说明它为什么不给看（一屏放不下四家 34 张牌），不是「加载失败」那种腔
- [ ] 横过来（或窗口变宽）之后**自动回到牌桌**，不必刷新
- [ ] 闸门视口要真加一档窄的。**今天仓库里最窄的闸门视口是 1180 px**
      （`grep "width: [0-9]" web/scripts/*.mjs`）——∴ 任何只写给窄屏的 CSS
      今天一次都不会被渲染，票 119 正是因为这个删掉了票 44 那一整块。
      没有这一档窄视口，这一票就是又一段没人渲染过的死 CSS
- [ ] README 那句「也没有为手机屏幕适配」跟着核一遍：现在的说法该是「竖屏只给一句提示」
