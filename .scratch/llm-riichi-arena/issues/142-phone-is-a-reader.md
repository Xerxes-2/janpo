# 142 — 手机：不救牌桌，换一种页面

**What to build:** 竖屏给一个「读」的版式——名册 + 逐手一条（谁打了什么 · 它当时说的话），
牌桌只留一枚「横过来看」的入口。评审 P2-I。

**Status:** needs-triage

## 为什么挂着

「9 px 不救」是票 119 已经定过的立场，README 里也写着「没有为手机屏幕适配」。
这一票**不是推翻它，是承认它**：手机上真正能读的那一半是**推理**，不是牌桌。

但它要新造一种页面形态，**与「一页只有一套装配」（票 83）正面相撞**——
那条规矩挡住过好几次分岔，不该顺手破。∴ 要主人裁：
**不裁的后果**是手机来客继续看一桌 9 px 的牌，然后走；
裁了之后多一条要长期维护的版式分支。

我的判断：**先做最小的那一半**——竖屏只留一句「横过来看」的提示，把「读」的版式挂着。
理由是提示那一半不新造版式（一条 media query），而「读」的版式要新造一整页。

## 若裁了要什么行为

- [ ] 竖屏（`orientation: portrait` 且窄）：名册 + 逐手一条（谁打了什么 · 它当时说的话）
- [ ] 牌桌换成一枚「横过来看」的入口，**不许把桌子缩到 9 px 之后再说服自己它能看**
- [ ] 闸门视口要真加一档窄的（今天仓库里最窄的闸门视口是 1180 px，
      ∴ 任何只写给窄屏的 CSS **今天一次都不会被渲染**——票 119 就是因为这个删掉了票 44 那块）

## 边界

- [ ] 不动宽屏那一套装配的任何一处
- [ ] 不动引擎、不动牌谱
