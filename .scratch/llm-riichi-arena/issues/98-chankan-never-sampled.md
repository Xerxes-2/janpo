# 98 — 抢杠那一轮从来没被抽到过：给它摊一条牌山，或证明它抽不到

**What to build:** 票 97 把 `GameStateArbitraries` 的取值域逐条数完之后，
表里躺着一行刺眼的零：**`chankan`（抢杠那一轮）命中数 0，改前改后都是 0.0000%**。
也就是说 `KanProperties` 里跟抢杠有关的那一支**从建起来到今天一次都没执行过**（判据 3）。
97 只描述不编号，留给调度器分配——就是这张票。

**Blocked by:** 无（97 已集成，取值域那张表现在是公开的 `GameStateArbitraries.Traces`）

**Status:** ready-for-human

## 先看清楚它是不是「该抽到而没抽到」

抢杠比立直稀有得多，而且**稀有的原因不一样**：立直是「牌山没摊好所以走不到」，
抢杠是「要有人加杠、同时另一家正好听那张、且不振听有役」。
**所以这一票的第一步不是补轨迹，是判性质**：

- [x] 查 `KanProperties` 里到底有几条断言压在抢杠那一支上，**它们今天由谁守着**
      （`KanTests` 里有没有具名用例？票 97 报告 §6.2 的做法是「随机属性到不了的，用 `[<Fact>]` 锚点守」）
      → **只有一条**（另有 `GameStateProperties` 的一支同样 0 次）；今天守着它的是 `KanTests` 两条具名用例
      与真牌谱对拍（固件里 2 局抢杠），属性本身等于 `fun _ -> true`（报告 §1）
- [x] 判断这一支属于哪一类：
      - **该抽到**：摊一条牌山让它必然发生（照 97 的三条立直轨迹的做法）
      - **抽不到且不必抽**：具名锚点已经守住了 → **把「随机属性到不了这里」写进模块头注释**（判据 4），
        并在报告里说清「那这条属性的随机部分实际在守什么」

## 要什么行为

- [x] 二选一落地（补轨迹 / 写明到不了 + 锚点补齐），**报告里写清选了哪个、凭什么**
      → **摊了两座牌山，但不挂进取值域表，挂在锚点上**：挂进表里只买到一趟 47%，
      而且会当场把七条现成的属性按红（报告 §3 / §4）
- [x] 若补轨迹：用 `dotnet fsi scripts/fsi/arbitrary-coverage.fsx` 量改前改后
      （97 留的探针，3.4 秒，自带「掉了没有」自判）——**加轨迹必须跑它**，否则就是拿别族的占比赌
      → 没加轨迹；探针照跑了，输出与集成头逐行相同
- [x] **任何一族的「一趟至少开口一次」不许掉**（97 立的规矩，探针会自己判）
      → 权重表一字未改，一族没掉
- [x] 若走「写明到不了」：锚点要**真的红过一次**（判据 1），红的原文进报告
      → 红过两次（报告 §5.2）；另外证了一件事：把那条属性自己改坏，它**照样绿**
