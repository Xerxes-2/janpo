# 44 — 牌桌从四家竖排改成真牌桌，并补上「渲染给人」那侧的闸门

**What to build:** 现在四家是**竖排列表**，能看懂但不像牌桌 —— 座位之间的方位关系（谁是上家、
谁在对面）得靠读文字而不是看位置。改成方位正确的牌桌布局：自家在下、下家在右、对家在上、上家在左，
河向中心、副露向外。

同时补上 M1 留下的一处不对称：**「渲染给模型」有黄金用例逐字段钉着（2069 个字段），
「渲染给人」只有截图**。M1 里两次信息缺失（牌背隐形、副露没来源）都是主人肉眼发现的，CI 一次没抓到。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

## 布局

- [ ] 方位正确：自家在下、下家在右、对家在上、上家在左；**方位由观测视角决定**（切座位/上帝视角时跟着转）
- [ ] 河朝中心、副露朝外；**保住票 38 定下的全部记号**：被鸣那张横放、来源文字、加杠的 `＋`、
      暗杠两端牌背、摸切虚线淡色、赤牌红字、刚摸那张的间距——**一个都不许弄坏**
- [ ] 保住票 35 的读者面边界（默认视图无开发向内容）与票 37 的页脚
- [ ] 窄视口不许挤烂（M1 验过 820px，这一票也要验）

## 「渲染给人」的闸门

- [ ] 人能看见的信息每项都要有可断言的 `data-` 标记 + 一道断言，至少覆盖八项：
      **手牌（自家牌面/他家张数）、河（含手切摸切）、副露（含来源与被鸣那张）、点数、
      供托与本场、宝牌指示牌、巡目、立直状态**
- [ ] 每道断言**先红一次**（临时去掉对应渲染），红的原始输出抄进报告
- [ ] 方位也要断言：给定观测座位，断言四家出现在正确的方位槽里
      （这条能抓住「切了视角但布局没转」这类错）

## 边界

- [ ] **DOM 不用 Canvas，第一版无动画**（spec 明写动画预算后置）
- [ ] 合格线是**看得懂一局**，不是雀魂级演出。CSS 上不许过夜
- [ ] 不碰引擎、不碰 `web/src/agent/`、不碰牌谱格式
- [ ] 截图会变：重出 `docs/images/table.png`，并**自己打开图看**（这条在 M1 立过规矩）

## 为什么它是 M2 的前置

M2 要做四家 LLM 同桌 + 思考气泡。**四个气泡挂在竖排列表上没有合适的锚点**，
而布局一改气泡就得重挂。先把布局定下来，气泡才有地方长。
