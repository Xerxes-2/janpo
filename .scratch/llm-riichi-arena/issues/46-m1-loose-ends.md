## 票 48 核出的两条（调度器 2026-08-17 定了方向，照做）

术语表刚裁定「**`Persona` 一局内不变**（否则废掉可缓存前缀）」，但代码里**没人执行这条**：
`loop.ts` 每手重解模板、页面那两格对局中随时可编辑且无提示。而 `Paifu.fs` 的 `Preamble` 设计
**恰恰是为「打到一半换人格」准备的**（按「座位 + 渲染版本」去重，每条决策记录靠自己的
`RenderVersion` 指得回当时那一份）。三处注释（`Agent.fs:69`、`types.ts:180`、`ask.ts:18`）
又说 preamble「整场不变」，比裁定更强，且与 `Paifu.fs` 自己的注释打架。

**方向：把不变量做成真的，边界取「局」。** 人格与模板**在一局之内不许变**，改动**生效于下一局**；
局间更换仍然支持，牌谱照旧按「座位 + 渲染版本」记住每一版（`Paifu` 的形状不用改，它本来就对）。
理由：M2 是对照实验平台，**一局内换人格等于在一局里引入两个自变量**，事后即使牌谱记得住也难归因；
而把边界钉在局上几乎零成本，还让这条不变量**可执行、可测试**。

- [x] 一局进行中，人格与模板的编辑**不生效于本局**：要么锁住那两格，要么接受编辑但明确告知
      「下一局生效」。**别静默地半局换掉**
- [x] 局间更换照旧可用，并**能在牌谱里看到两版 preamble**（加一条测试钉住这件事）
- [x] 把那三处「整场不变」的注释改成与裁定一致的说法（**一局内不变、可在局间更换**），
      并指向 `Paifu.fs` 那段解释，别让四处说法各不相同
- [x] 与本票的 31-D（显示渲染版本）合起来看：**换了渲染要让人当场看得见**，这两条是一件事的两面
