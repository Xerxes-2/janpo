# 112 — 「一秒走了几手」从来没有闸门量过

**What to build:** 票 111 交回来一句：**播放速度没有任何闸门量过**。
牌桌有播放/暂停、有倍速（`Playback`）、票 78 修过「双倍速」那种世代 bug，
但**「按下播放之后，一秒真的走了几手」这件事，全仓库没有一处断言**。

这是个测量空洞，而这个项目的整套纪律是「断言必须真执行」：
判据 3 已经攒了五个案例（记法闸门跑几次 / 立直属性十趟九空转 / 抢杠零次 /
「没有总分」没有执行者 / 票 92 那道剪枝没有闸门）。
**这一条比那五条更素**：它连断言都没有，不是断言没执行。

**Blocked by:** 无

**Status:** ready-for-agent

## 先量，再决定要不要断言（顺序别换）

- [ ] **先把实况量出来**：1× / 2× / 4×（有几档就几档）各自「一秒走了几手」，
      在浏览器里真跑，报中位与 p95，**并说清你是怎么量的**（挂哪个钩子、量点在哪）
- [ ] **与设计值对齐**：代码里那个步进间隔常数是多少？实测与它差多少？
      **差多少是可接受的**由你判并写理由（浏览器定时器本来就不准，
      `setTimeout` 在后台标签页会被节流——**这条要写进报告**，判据 4）
- [ ] 量完再决定断言的形状：**别写一条「大概差不多」的断言**。
      候选形状：某档下 N 手的总耗时落在 [a, b] 区间 / 相邻两手的间隔中位数 /
      倍速之间的**比例**（2× 是 1× 的两倍上下）——**比例那种最稳，绝对值最脆**

## 要害

1. **别把闸门做成「等一会儿看看走了几手」的碰运气**：那种断言在慢机器上会假红，
   而这仓库栽过「假红比真红危险」（判据 16）。挑一个对机器负载不敏感的判据形状。
2. **后台节流那件要么绕开、要么写明**：闸门里的浏览器页面若不在前台，
   `setTimeout` 会被压到 1 秒一次——那会让这条闸门变成噪声源。
   `playwright` 里那一页是不是前台，**你要自己确认并写进报告**。
3. **票 78 那条别破**：世代那道锁（旧世代的 `Ticked` 发不出效果体）现在有执行者，
   你的闸门不许绕过它去直接喂 `Ticked`——**票 111 明确记过这个陷阱**：
   探针自己喂 `Ticked` 时，那个数修前修后一模一样、当不了证据。
4. **拨座位那 600 ms**（票 111 交回来的第 2 条）：量的时候顺手看一眼它值不值一提，
   **别顺手改**（那是它判过的，要推翻得先有数）。

## 闸门

- [ ] 至少一条真断言，**先红一次**：把步进间隔改成 2 倍或 0.5 倍，闸门必须红，原文进报告
- [ ] 阴性对照：**它不许对机器负载敏感**——同一台机器上连跑 10 趟，全绿（把 10 趟的数写进报告）
- [ ] 既有的播放/暂停/单步/世代那几条用例全绿
- [ ] `./scripts/ci.sh` 全绿

## 顺手记着

而那种精度抓不住任何真会发生的 bug），**park 并把数与理由写全**——
