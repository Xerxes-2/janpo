# 85 — 导入半场牌谱时，最后一帧会多出一张假牌

**What to build:** 票 79 真跑时撞出来的机制，产品侧也踩得到：**`Replay` 从一条末尾截断的事件流重建局面时，
会从「推断出来的牌山」替下一家摸一张牌谱里根本没有的牌。**

- 触发路径：**导出半场的牌谱**（页面上任何时刻都能导出）→ **导入它**（票 78）→ 拖到**末帧**。
  那一帧下一家的手里会多出一张凭空造的牌。
- 为什么一直没红：`verify-export` 那道往返闸门比的是**事件流**（导出→回放→再导出，逐条相同），
  不是**末帧的局面**；而票 75 的时间轴用例以前拿的锚点自己也会造同一张假牌，两边一起错、就对上了
  （诊断全文见 `run/reports/79-real-demo-paifu.md` §5，锚点已在票 79 并入时换成事件流加减法）。

**Blocked by:** None

**Status:** ready-for-human

## 要什么行为

- [x] 回放一条**末尾截断**的牌谱时，最后一帧只呈现事件流交代过的牌——**不许出现牌谱里没有的牌**
- [x] 形态由你定，但要在这两条里选一条并说明理由：
      ① 末帧停在「最后一条事件落定」那一刻（不产出那次由引擎自动摸出的帧）；
      ② 把「这一摸是推断的」做成值，UI 上不摆那张牌。
      **别选「把假牌照旧画出来但标个记号」**——它仍然是在给人看一张不存在的牌。
      → **选了①**，理由见报告 §2（摸牌与打牌在引擎里是同一步，拆不开；② 要在四处滤掉同一张牌）
- [x] 完整（未截断）的牌谱回放**一帧都不许变**：首页那份资产、分享链接、导出往返全都压在它上面
      → 首页资产 **470 帧逐帧指纹改前改后完全一致**（报告 §5）

## 闸门

- [x] 新断言：把一份完整牌谱截到某个「下一步该摸牌」的位置，回放它，
      **末帧四家手里的每一张都必须能在事件流里找到出处**（起手或某次自摸）
      → `ReplayTableTests` 那一条（逐切点扫一整局）+ `ReplayTests` 那一条（整场逐条）
- [x] 阳性对照：不截断的同一份牌谱，末帧与今天逐字段相同
- [x] 先红一次（**用截断前的实现**跑那条新断言，把红的原始输出抄进报告）→ 报告 §4
- [x] `verify-export` 的往返、`verify-inbound` 的导入、`verify-home` 的首页三道照旧全绿

## 边界

- [x] 不碰牌山推断本身的算法（它在完整牌谱上是对的）→ `buildWall` 一行未动
- [x] 不碰 `Paifu` 格式与 `Paifu.Version`
- [x] 不碰 Web 层的其它部件（气泡、配桌、布局都有票在排队）→ `src/Janpo.Web/` 一个文件都没改
- [x] 不改 `verify-export` 现有断言的强度

## 顺手记着

这条挂账的价值不止于「导入半场牌谱」这一条路：**它是「第三个锚点自己会造数据」的教科书例子**。
判据 18 说两边对不上时要引入第三个锚点，而票 79 的教训是——**第三个锚点也可能是错的，
要选一个「造不出数据」的**（事件流加减法不需要牌山，因此造不出牌）。
