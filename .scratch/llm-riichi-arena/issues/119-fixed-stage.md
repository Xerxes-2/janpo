# 119 — 固定舞台：缩放不重排，长卷死掉

**What to build:** 主人的意见①后半句——**「布局可以妥协成结构不因为缩放而改变」**。
票 117 起草时把它和牌桌几何写在一起，落地前拆开（主人 2026-08-29 定）：

> 固定舞台要求整页塞进 750 px，而 116 之后 `?table=1` 在 1280×800 是 **1022 px**。
> 先加舞台就得把 1022 压进 750（缩放 0.73、牌 28→20 px）——**净退步**。
> 新几何是 `顶条 44 + 牌桌 656 + 操作条 46 = 746`：**牌桌先变成方块（票 117），舞台才塞得下**。

**Blocked by:** 117

**Status:** ready-for-human

## 做法已经验过了，不必再试

**纯 CSS，不写 JS**：

```css
:root { --u: min(calc(100vw / 1200), calc(100vh / 750)); }   /* 满幅时的 1px */
.stage { width: calc(1200 * var(--u)); height: calc(750 * var(--u)); }
```

长度 ÷ 数值仍是长度，`min()` 取两者小者；每个尺寸写成 `calc(N * var(--u))`。
实测（`.scratch/probe/unit.html` + `web/probe-unit.mjs`，都是临时量具）：

| 视口 | 舞台 | 牌宽（满幅 32） | scale | 文档滚动 |
|---|---|---|---|---|
| 1200×750 | 1200×750 | 32.0 | 1.000 | 无 |
| 1280×800 | 1280×800 | 34.1 | 1.067 | 无 |
| 1440×900 | 1440×900 | 38.4 | 1.200 | 无 |
| 1366×768（16:9） | 1228.8×768 | 32.8 | 1.024 | 无 |
| 390×844 | 390×243.8 | 10.4 | 0.325 | 无 |

四个数与原型的 JS transform 逐个相同，且**比原型更好**：
没有 resize 监听，「缩放只改一个变量」字面为真。

## 调度器已定（主人可否决）

- **删掉 `@media (max-width: 39.99rem)` 那一整块**（票 44 写的竖排布局）：
  仓库里**最窄的闸门视口是 1180 px**（`grep "width: [0-9]" web/scripts/*.mjs` 只有 1180 / 1280），
  那块 CSS **从来没被渲染过一次**，且它与 README「也没有为手机屏幕适配」互相矛盾。
  固定舞台缩放之后，README 那句变成**字面真话**（能看不能读，9.8 px）。
- **`@media (min-width: 40rem)` 那一块跟着核**：固定舞台之后布局不再随宽度变，它多半也空了。
  **别默认删**——先量它此刻还管着什么，管着的搬进基础样式。
- **手机竖屏不救**：390 px 下牌宽 9.8 px，转 90° 只得 15.6 px，仍不算能用。
  诚实立场写进 README（主人已点头，`DECISIONS.md` M5-12 ②）。
